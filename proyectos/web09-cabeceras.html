Cabeceras

Una CSP que no se probó contra el build es una suposición, y una cabecera que no revisa un script se pierde en el próximo cambio.

Al terminar podrás

  • Servir el frontend compilado desde Apache, en el mismo origen que la API, para probar las cabeceras contra lo que se despliega y no contra el servidor de desarrollo.
  • Escribir la CSP del frontend a partir de lo que la aplicación carga de verdad, desplegarla primero en report-only con un endpoint de reportes y después pasarla a bloqueo.
  • Darle a cada respuesta de la API la política "nada" de 78.8 desde un solo lugar, y dejar que los documentos de WEB08 se enmarquen solo en el frontend.
  • Comprobarlo con un script que falla si una respuesta sale sin una cabecera, y con cuatro fallas provocadas: clickjacking, un script inyectado, 'unsafe-inline' y un origen mal escrito en el .env.

La excusa

Después de ocho guías, la API ya manda dos cabeceras de seguridad: Response::json pone X-Content-Type-Options: nosniff y Cache-Control: no-store desde WEB01, y archivos.php pone las suyas desde WEB08. Del frontend no hay nada que revisar, porque nadie lo sirve: el laboratorio corre pnpm dev en localhost:5173, y el frontend/dist que hay en el repositorio es un build viejo que ningún Apache entrega. Las cabeceras de una página son de quien la sirve, así que el primer trabajo es servirla.

  • H1. Cualquiera puede enmarcar la aplicación. Una página de atacante.test carga el sistema de prácticas en un <iframe> semitransparente y pone su propio botón debajo: es el clickjacking de M83. Hoy la cookie de sesión es SameSite=Strict (WEB00), así que el iframe de otro sitio muestra la pantalla de login y no la sesión; eso ayuda, pero es un atributo de una cookie que mañana alguien cambia a Lax por un flujo de login, y no impide enmarcar.
  • H2. Si un XSS se cuela, corre. WEB05 cerró los XSS que encontró, pero no hay una segunda capa para el que no encontró: el navegador ejecuta cualquier <script> que aparezca en la página.
  • H3. La API no dice "nada". Una respuesta JSON abierta directo en el navegador no debería cargar nada ni dejarse enmarcar. nosniff ya impide que se lea como HTML; la CSP de 78.8 lo dice explícito, y desde un solo lugar.

Paso a paso

Paso 1. La API dice "nada", desde un solo lugar

La API tiene treinta y tantos endpoints, y todos empiezan con aplicarCors(...) desde WEB04. Esa es la puerta: una línea ahí, y toda respuesta lleva las cabeceras, también el preflight (que termina antes de llegar a Response) y los errores. Las cabeceras se arman en funciones puras, para probarlas sin servidor:

  1. politicaCsp: escribe una política a partir de sus directivas, en orden.
  2. cabecerasApi: la política de 78.8. La API no sirve HTML: default-src 'none' y frame-ancestors 'none', más nosniff, no-referrer, CORP y no-store.
  3. cabecerasDocumento: lo mismo, salvo quién enmarca: 'self' y los orígenes de ORIGENES_PERMITIDOS, solo los que tienen forma de origen.
  4. enviarCabeceras: las manda. header() reemplaza la cabecera del mismo nombre, así que la última gana.
<?php

declare(strict_types=1);

require_once __DIR__ . '/origen.php';

/** Una política de CSP a partir de sus directivas, en el orden en que se escriben. */
function politicaCsp(array $directivas): string
{
    $partes = [];
    foreach ($directivas as $nombre => $fuentes) {
        $partes[] = trim($nombre . ' ' . implode(' ', (array)$fuentes));
    }
    return implode('; ', $partes);
}

/**
 * Las cabeceras de seguridad de toda respuesta de la API (WEB09).
 * La API no sirve HTML: nada se carga y nada se enmarca.
 */
function cabecerasApi(): array
{
    return [
        'Content-Security-Policy'      => politicaCsp(['default-src' => "'none'", 'frame-ancestors' => "'none'"]),
        'X-Content-Type-Options'       => 'nosniff',
        'Referrer-Policy'              => 'no-referrer',
        'Cross-Origin-Resource-Policy' => 'same-site',
        'Cache-Control'                => 'no-store',
    ];
}

/**
 * Un documento de WEB08 se muestra en un iframe del frontend: lo pueden enmarcar
 * el mismo origen y los orígenes del .env. Solo se escribe lo que tiene forma de origen:
 * un valor con ";" o un "*" en la configuración no llega a la cabecera.
 */
function cabecerasDocumento(?array $origenes = null): array
{
    $validos = array_filter(
        $origenes ?? origenesPermitidos(),
        fn(string $o): bool => preg_match('#^https?://[a-z0-9.-]+(:[0-9]{1,5})?$#', $o) === 1
    );
    $marcos = array_merge(["'self'"], array_values($validos));
    return ['Content-Security-Policy' => politicaCsp(['frame-ancestors' => $marcos])] + cabecerasApi();
}

/** header() reemplaza una cabecera con el mismo nombre: la última que se manda es la que vale. */
function enviarCabeceras(array $cabeceras): void
{
    if (headers_sent()) {
        return;
    }
    foreach ($cabeceras as $nombre => $valor) {
        header("$nombre: $valor");
    }
}

El filtro de cabecerasDocumento parece de más, porque ORIGENES_PERMITIDOS lo escribes tú. Pero el valor termina dentro de una cabecera, y en una CSP un ; empieza una directiva nueva: http://localhost:5173; script-src * en el .env sería una política distinta de la que crees. La falla 4 lo muestra.

Ahora cors.php, con dos líneas nuevas: el require_once y la primera línea de aplicarCors. El archivo entero:

<?php

declare(strict_types=1);

require_once __DIR__ . '/origen.php';
require_once __DIR__ . '/cabeceras.php';

/**
 * Las cabeceras CORS de una respuesta, sin enviarlas (así se prueban sin servidor).
 * $lista existe para la prueba; en el servidor sale del .env.
 */
function cabecerasCors(?string $origen, string $metodo, array $metodos, ?array $lista = null): array
{
    $h = ['Vary' => 'Origin'];
    if ($origen === null || !esOrigenPermitido($origen, $lista)) {
        return $h;
    }
    $h['Access-Control-Allow-Origin'] = $origen;   # ya comparado con la lista: no es texto ajeno
    $h['Access-Control-Allow-Credentials'] = 'true';

    if ($metodo === 'OPTIONS') {
        $h['Access-Control-Allow-Methods'] = implode(', ', $metodos);
        $h['Access-Control-Allow-Headers'] = 'Content-Type, X-CSRF-Token';
        $h['Access-Control-Max-Age'] = '600';
    } else {
        $h['Access-Control-Expose-Headers'] = 'Retry-After';   # el 429 del login (WEB02)
    }
    return $h;
}

/**
 * Primera línea de cada endpoint. Manda las cabeceras de seguridad (WEB09) y las de CORS.
 * El preflight termina aquí: no trae cookie y no llega a requireAuth.
 */
function aplicarCors(array $metodos): void
{
    enviarCabeceras(cabecerasApi());   # WEB09: toda respuesta de la API, también el preflight y los errores

    $metodo = strtoupper((string)($_SERVER['REQUEST_METHOD'] ?? 'GET'));
    $origen = isset($_SERVER['HTTP_ORIGIN']) ? (string)$_SERVER['HTTP_ORIGIN'] : null;

    foreach (cabecerasCors($origen, $metodo, $metodos) as $nombre => $valor) {
        header("$nombre: $valor", $nombre !== 'Vary');   # Vary se suma a otro Vary, no lo pisa
    }
    if ($metodo === 'OPTIONS') {
        http_response_code(204);
        exit;
    }
}

Y en archivos.php, una línea justo antes del foreach de cabecerasArchivo, para que el CV se pueda ver en el iframe del panel:

enviarCabeceras(cabecerasDocumento());   // WEB09: lo enmarca el frontend, no cualquiera

La política del documento no lleva default-src 'none'. El documento es un PDF o una imagen que pasó la firma binaria y sale con nosniff (WEB08): no hay HTML donde correr un script. Y un PDF lo dibuja el visor del navegador dentro del documento, con la política del documento: no conviene depender de cómo trata cada navegador un default-src 'none' ahí. La decisión
Las cabeceras de la API en aplicarCors, que ya es la primera línea de cada endpoint.
Lo que descartas
Ponerlas en Response::json: no cubre el preflight, que termina con exit en aplicarCors, ni la salida de archivos.php. O ponerlas con Header always set en un .htaccess de api/: Apache y PHP escriben en tablas distintas de cabeceras, y archivos.php no podría cambiar frame-ancestors sin terminar con dos políticas, que el navegador aplica las dos.
Qué puede salir mal
Un endpoint nuevo que alguien escribe sin aplicarCors. La matriz solo revisa los que nombra; para ver todos, Get-ChildItem api\endpoints\*.php | Where-Object { -not (Select-String -Path $_ -Pattern 'aplicarCors' -Quiet) } lista los archivos que no la tienen, y el diseño espera ninguno.

Paso 2. El build, servido como en producción

El frontend compilado y la API van en el mismo origen, http://localhost:8080: Apache sirve frontend/dist en la raíz y la carpeta api en /SistemaControlPracticas/api, la misma ruta que usa BASE_API sin VITE_API_BASE. Es lo que hace el proxy de Vite en desarrollo (WEB04), y lo que haría un servidor de producción. Con un solo origen, la CSP dice 'self' y no necesita nombrar otro.

Primero, el origen nuevo en la lista de WEB03: un fetch con POST manda Origin aunque sea del mismo origen, y requireOrigenConfiable lo compara con la lista. En el archivo de secretos:

ORIGENES_PERMITIDOS=http://localhost:5173,http://localhost,http://localhost:8080

Después, el build. VITE_API_BASE no tiene que estar definida, para que las llamadas sean relativas:

pnpm build
Get-ChildItem dist, dist\assets

El diseño espera un dist\index.html nuevo y, en dist\assets, un index-….js y un index-….css con nombres que cambian en cada build. Mira el index.html: los dos archivos se cargan con <script src> y <link>, y no hay ningún script inline. Eso decide la política del paso 3.

La decisión
Probar las cabeceras contra el build servido por Apache, con la API en el mismo origen.
Lo que descartas
Ponerlas en server.headers de vite.config.js: Vite en desarrollo inyecta scripts y estilos inline para el recargado en caliente, y una CSP estricta lo rompe. O usar vite preview, que sí sirve el build: sirve, pero las cabeceras quedarían en la configuración de Vite y no en el servidor que las va a mandar en producción.
Qué puede salir mal
Que el build quede viejo: Apache sirve lo que hay en dist, y un cambio en src no aparece hasta el próximo pnpm build. Para desarrollar sigue usando pnpm dev en 5173, sin CSP.

Paso 3. La CSP, primero en report-only

El frontend es una SPA estática: el index.html no lo genera PHP, así que no hay quién ponga un nonce distinto en cada respuesta. Y no tiene scripts inline, así que tampoco hacen falta hashes. Es el caso del final de 78.4: script-src 'self', sin 'strict-dynamic' (que ignora 'self'), con la condición de que en tu origen nadie pueda subir un .js. Desde WEB08 lo subido no vive en el origen, y archivos.php nunca sirve un tipo de script.

La política va primero en Content-Security-Policy-Report-Only (78.5): el navegador la evalúa, no bloquea nada y manda un reporte por cada cosa que habría bloqueado. Los reportes van a un endpoint de la API. Lo que entra lo escribe cualquiera, así que la lectura es una función pura con topes:

<?php

declare(strict_types=1);

const REPORTES_CSP_MAX_BYTES = 64 * 1024;
const REPORTES_CSP_MAX_POR_ENVIO = 20;

/** Los dos formatos que manda un navegador: report-uri (viejo) y report-to (Reporting API). */
function esTipoDeReporteCsp(string $contentType): bool
{
    $tipo = strtolower(trim(explode(';', $contentType)[0]));
    return in_array($tipo, ['application/csp-report', 'application/reports+json'], true);
}

/**
 * Cada violación, con los mismos cinco campos sea cual sea el formato.
 * El cuerpo lo escribe cualquiera: se lee como datos, se recorta y nunca se confía.
 */
function resumenReportesCsp(string $cuerpo): array
{
    $json = json_decode($cuerpo, true);
    if (!is_array($json)) {
        return [];
    }
    $crudos = isset($json['csp-report']) ? [$json['csp-report']] : $json;   // report-uri trae uno; report-to, una lista

    $corto = fn(mixed $v): string => mb_substr(is_scalar($v) ? (string)$v : '', 0, 200);
    $salida = [];
    foreach (array_slice($crudos, 0, REPORTES_CSP_MAX_POR_ENVIO) as $r) {
        if (!is_array($r)) {
            continue;
        }
        if (isset($r['type'])) {                                            // report-to
            if ($r['type'] !== 'csp-violation' || !is_array($r['body'] ?? null)) {
                continue;
            }
            $b = $r['body'];
            $salida[] = [
                'directiva' => $corto($b['effectiveDirective'] ?? ''),
                'bloqueado' => $corto($b['blockedURL'] ?? ''),
                'pagina'    => $corto($b['documentURL'] ?? ''),
                'archivo'   => $corto($b['sourceFile'] ?? ''),
                'modo'      => $corto($b['disposition'] ?? ''),
            ];
        } else {                                                            // report-uri
            $salida[] = [
                'directiva' => $corto($r['effective-directive'] ?? $r['violated-directive'] ?? ''),
                'bloqueado' => $corto($r['blocked-uri'] ?? ''),
                'pagina'    => $corto($r['document-uri'] ?? ''),
                'archivo'   => $corto($r['source-file'] ?? ''),
                'modo'      => $corto($r['disposition'] ?? ''),
            ];
        }
    }
    return $salida;
}

CabeceraQué corta en esta aplicación
X-Content-Type-Options: nosniffQue el navegador adivine el tipo de un archivo de dist: un .js solo corre si llega como script.
Referrer-Policy: strict-origin-when-cross-originQue un link al sitio web de una institución le cuente la ruta y la consulta de donde venías. Es el valor por defecto de los navegadores actuales Documentado; escribirlo lo fija aunque el valor por defecto cambie.
Permissions-PolicyQue un script inyectado pida la cámara, el micrófono, la ubicación o un pago. La aplicación no usa ninguno.
Cross-Origin-Opener-Policy: same-originQue una ventana de otro sitio abierta desde la aplicación (o que abrió la aplicación) conserve una referencia a ella en window.opener.
X-Frame-Options: DENYLo mismo que frame-ancestors 'none', para navegadores viejos. Con las dos, el navegador moderno usa frame-ancestors Documentado.

No hay <IfModule headers_module> alrededor: si algún día falta el módulo, Apache no arranca con un error que nombra Header, en lugar de arrancar sin ninguna cabecera y sin avisar. httpd.exe -t, reinicia Apache y corre la matriz:

Paso 5. HSTS, solo con https

Strict-Transport-Security le dice al navegador que, durante max-age segundos, a este host solo se entra por https, aunque alguien escriba http:// o un atacante en la red intente bajarlo a http (M01). Un navegador solo la toma si llega por https: por http la ignora, porque un atacante en el medio podría haberla inventado Documentado. Por eso la línea del paso 4 lleva la condición expr=%{HTTPS} == 'on': en tu laboratorio, que es http, no sale, y la matriz lo comprueba ("sin HSTS: esto es http").

Antes de poner HSTS en un servidor de verdad

HSTS no se deshace desde el servidor: un navegador que la recibió con un año de max-age va a negarse a entrar por http durante un año, aunque quites la cabecera. Empieza con max-age=300, súbelo cuando todo funcione por https, y agrega includeSubDomains solo cuando ningún subdominio (un panel interno, una impresora) siga en http. La lista de precarga de los navegadores (preload) es todavía más difícil de deshacer: no la pidas para un dominio de pruebas.

function Cabeceras([string]$Url, [string[]]$Extra = @()) {

        elseif ($l -match '^HTTP/\S+\s+(\d+)') { $h['(estado)'] = $matches[1] }

}

}

Limitaciones

  • No hay nonce, porque no hace falta todavía. Si algún día el HTML lo genera el servidor (una página en PHP, o el renderizado de M84), la política pasa a la estricta de nonce">78.4: un nonce de random_bytes por respuesta y 'strict-dynamic'.
  • La CSP es la segunda capa. Un XSS que solo usa lo que la página ya carga (cambiar un href, abusar de una función de la propia aplicación) no lo frena ninguna política. Escapar la salida (WEB05) sigue siendo el arreglo.
  • El endpoint de reportes está abierto. Cualquiera puede mandarle reportes falsos: el tope de 64 KB y de 20 líneas por envío limita cada request, no cuántas llegan. Fuera del laboratorio necesita un límite por IP, o los reportes van a un servicio aparte.
  • HSTS no se prueba aquí. El laboratorio es http; la condición expr se comprueba solo en que la cabecera no sale.
  • Lo que la guía no cubre. Trusted Types (require-trusted-types-for 'script') y el aislamiento con COEP de 78.7: la aplicación no usa nada que los necesite, y COEP rompería el iframe del CV si algún día se sirviera de otro sitio.
  • Costo. Unos cientos de bytes de cabeceras por respuesta, y una línea de registro por violación.
  • Nada se ejecutó contra tu sistema al escribir esta guía. La prueba pura se corrió sobre copias y la configuración de Apache se revisó con httpd.exe -t sobre un archivo aparte; lo que muestra el navegador y la matriz sale de leer el código, y las tablas son tuyas.
