Archivos y URLs firmadas

Un álbum de fotos compartido entre tres personas. Cada foto o video viaja directo del navegador al almacén con una URL que firmó la api, sin pasar por ella. Vas a escribir tu propio firmador con HMAC y un almacén local que solo obedece URLs firmadas, subir videos de 2 GB en partes que se retoman después de un corte, hacer miniaturas sin que una imagen maliciosa tumbe al worker, y llevar lo mismo a Cloudflare R2 cambiando una variable.

Al terminar podrás

  • Firmar y verificar URLs con HMAC-SHA256: método, ruta, vencimiento, tipo y tamaño dentro de la firma, comparación en tiempo constante y rotación de claves sin cortar las URLs que ya salieron.
  • Subir archivos directo del navegador al almacén, con el preflight de CORS que eso provoca, y confirmar la subida en la api sin creerle al navegador: tamaño con HEAD, tipo y primeros bytes.
  • Subir videos de 2 GB en partes paralelas que se retoman después de un corte, y juntar las partes con la lista que da el almacén, no con la que manda el cliente.
  • Hacer miniaturas en un worker con un lease, reintentos con espera exponencial y una defensa contra bombas de descompresión que lee la cabecera antes de decodificar.
  • Servir lo privado con URLs de vida corta que el navegador sí puede cachear, y descargas con Content-Disposition: attachment detrás de un 302.
  • Cambiar el disco local por Cloudflare R2 con el AWS SDK, y limpiar lo que deja cada falla: subidas abandonadas, multipart sin terminar y objetos huérfanos.

La excusa

Tres amigas comparten un álbum del viaje a Oaxaca. Ana es la dueña, Beto puede subir y Carla solo mira. Suben fotos del teléfono, de 3 a 12 MB, y algún video de varios cientos de megas. Un álbum así se puede programar en una tarde con un POST multipart a la api que guarda el archivo en disco. Y se rompe así:

  • La api se vuelve un caño. Cada byte de cada video entra a la api y sale hacia el disco. Un video de 2 GiB con una subida de 10 Mbps tarda unos 29 minutos, y durante todo ese tiempo hay un hilo de la api ocupado leyendo bytes que no le interesan.
  • Los enlaces se comparten de más. Si la foto vive en una URL fija y pública, cualquiera que la reciba la puede reenviar para siempre. Si la sirve la api, cada miniatura de cada listado vuelve a pasar por ella.
  • La red se corta. A los 1.4 GB de un video de 2, el wifi del hotel se cae. Sin partes, se empieza de cero.
  • El archivo miente. Un .png que es una página HTML con un script, o un PNG de 15 000 por 15 000 píxeles que pesa muy poco y ocuparía 900 MB decodificado en RGB.

La salida estándar, la que usan S3, R2 y Google Cloud Storage, es que la api no toque los bytes. La api decide quién puede subir qué y firma una URL que vale unos minutos para ese objeto, ese método, ese tipo y ese tamaño. El navegador sube directo al almacén. Al terminar, la api revisa lo que llegó antes de creerle. Leer es igual: la api firma una URL corta y el navegador lee directo. Este proyecto construye las dos mitades, la api y un almacén local que solo atiende URLs firmadas, y después cambia el almacén por R2.

En producción real

Todo el proyecto funciona sin cuentas externas: el almacén por defecto es un contenedor con disco local que imita lo que importa de R2 y S3. El paso 12 lo lleva a Cloudflare R2, que tiene un plan gratis de 10 GB al mes, pero pide registrar un método de pago para activarse Documentado. Ese paso es opcional, y si no quieres dar una tarjeta, sáltalo: todo lo demás se aprende igual.

  "part_size": 8388608,

Códigos de respuesta

  • 201La foto quedó pending. Con single, sube a url con exactamente esos headers; con multipart, pide las URLs de las partes.
  • 403FORBIDDEN_ROLE: eres miembro, pero viewer.
  • 404El álbum no existe o no eres miembro: para ti, es lo mismo.
  • 422UNSUPPORTED_TYPE (solo JPEG, PNG y MP4) o FILE_TOO_LARGE, con details.max_bytes.
  • 429TOO_MANY_PENDING: tienes 20 subidas sin confirmar. Trae Retry-After: 60.
  • 503STORAGE_UNAVAILABLE: el almacén no respondió al crear el multipart. Trae Retry-After: 5.

Códigos de respuesta

  • 200Aceptada: uploaded si es una imagen (falta la miniatura) o ready si es un video.
  • 404La foto no existe, o no la estás subiendo tú.
  • 409UPLOAD_MISSING si el objeto no está en el almacén, o PARTS_MISSING con details.missing, la lista de partes que faltan.
  • 422UPLOAD_REJECTED con details.reason: too_large, size_mismatch, content_type_mismatch o content_mismatch. El objeto ya se borró. O BAD_PARTS, si una parte no tiene el tamaño acordado.
GET /v1/photos/{id}/download Diseño de referencia

El enlace "Descargar" de la página apunta aquí. La api revisa que seas miembro del álbum y responde con una redirección a una URL que vale un minuto y le pide al almacén que mande el archivo como adjunto, con el nombre original.

Trade-off

Un almacén propio, no MinIO. MinIO en un contenedor daría la API de S3 completa en local, y el mismo R2ObjectStore serviría para los dos. Pero firmarías con SigV4 sin ver cómo se firma, y lo que este proyecto quiere enseñar es justamente eso: qué entra en una firma, qué verifica el almacén y en qué orden. El servidor de archivos de este proyecto tiene unas 600 líneas y hace solo lo que el álbum usa. Para el camino de producción está el paso 12, con R2 y el SDK oficial.

Una imagen, cinco papeles
El perfil de Spring decide qué es cada proceso. migrate crea las tablas y sale; files es el almacén; api atiende al navegador; worker hace miniaturas; jobs limpia y sale. El almacén no comparte nada con los demás salvo la clave de firma: no tiene base, ni sesión, ni usuarios.
Dos nombres para el almacén
El navegador llega al almacén por localhost:9000; la api y el worker, desde adentro de la red de Compose, por files:9000. Las URLs firmadas que van al navegador usan el nombre público, y la firma cubre solo la ruta y la query, no el host: por eso la api puede usar el nombre interno para sus propios HEAD con la misma firma.
Un rol por proceso
album_api, album_worker y album_jobs, con los permisos justos: el worker no puede crear ni borrar fotos, y la limpieza no puede cambiar ninguna. Lo impone PostgreSQL, como en el paso 1.
Memoria acotada
La api y el worker tienen mem_limit: 512m y la JVM usa hasta el 75 % con MaxRAMPercentage. El worker decodifica imágenes que sube cualquiera; con un límite, una imagen maliciosa mata a un contenedor que se puede reiniciar, no a la máquina. Y el límite es lo que hace visible el experimento de la bomba.
Sin restart
Los experimentos matan procesos a propósito. Con restart: on-failure, Docker los levantaría en un segundo y no verías qué quedó a medias.

Paso 1. Las tablas, los roles y quién ve qué

Tres tablas de negocio y una cola. albums y album_members dicen quién ve qué: la dueña, quien sube (editor) y quien mira (viewer). photos tiene una fila por archivo, pero no los bytes: solo la clave del objeto en el almacén, el tamaño que se declaró, el que llegó de verdad y un estado. thumb_jobs es la cola de miniaturas, en PostgreSQL, como el outbox de A09.

Son las reglas del ciclo de vida del paso 7, escritas donde nadie se las puede saltar: si un día un UPDATE mal escrito intenta dejar una imagen lista sin miniatura, falla la sentencia, no la página.

La api se apoya en cuatro piezas chicas. Users traduce el usuario de la sesión a su id. AlbumAccess responde la única pregunta de permisos que hay: qué rol tiene esta persona en este álbum. Si no es miembro, responde 404 y no 403, porque un 403 confirmaría que el álbum existe; es la defensa contra BOLA que viste en M10. ApiError y ApiExceptionHandler devuelven todos los errores con la misma forma: {"error": {"code": "…", "message": "…", "details": {…}}}, con Retry-After cuando corresponde.

/**
 * Quién puede hacer qué en un álbum. Se pregunta en cada request, con el id del álbum que trae la ruta:
 * el id solo no autoriza nada (BOLA, M10).
 */
@Component
@Profile("api")
public class AlbumAccess {

    /** En orden: cada rol puede lo de los anteriores. */
    public enum Role { VIEWER, EDITOR, OWNER }

    private final JdbcClient jdbc;

    public AlbumAccess(JdbcClient jdbc) {
        this.jdbc = jdbc;
    }

    public Optional<Role> roleOf(UUID albumId, long userId) {
        return jdbc.sql("SELECT role FROM album_members WHERE album_id = :a AND user_id = :u")
                .param("a", albumId)
                .param("u", userId)
                .query(String.class)
                .optional()
                .map(r -> Role.valueOf(r.toUpperCase()));
    }

    /**
     * Quien no es miembro recibe un 404, el mismo que si el álbum no existiera: un 403 le confirmaría que existe.
     * Quien es miembro pero no le alcanza el rol recibe un 403: ya sabe que el álbum existe.
     */
    public Role require(UUID albumId, long userId, Role needed) {
        Role role = roleOf(albumId, userId).orElseThrow(ApiError::notFound);
        if (role.compareTo(needed) < 0) {
            throw new ApiError(HttpStatus.FORBIDDEN, "FORBIDDEN_ROLE",
                    "Tu rol en este álbum (" + role.name().toLowerCase() + ") no alcanza.");
        }
        return role;
    }
}

Paso 2. Las claves de los objetos las arma el servidor

El usuario elige el nombre del archivo, playa.jpg o ../../etc/passwd. Si ese nombre llegara a la clave del objeto, tendrías tres problemas: dos personas que suben IMG_0001.jpg al mismo álbum se pisan, un nombre con ../ intenta salir del directorio, y el nombre, que puede tener datos personales, queda en cada URL y en cada log. Por eso la clave la arma el servidor con dos UUID y nada más, y el nombre va a la base, solo para mostrarlo y para la descarga.

package lab.album.storage;

import java.util.Arrays;
import java.util.UUID;
import java.util.regex.Pattern;

/**
 * Las claves de los objetos las arma el servidor, nunca el usuario: albums/{álbum}/{foto}/original.
 * El nombre del archivo que eligió el usuario va a la base, no a la clave. Así no hay "../", ni nombres que
 * choquen, ni datos personales en una URL. El prefijo por álbum permite listar o borrar un álbum entero.
 */
public final class ObjectKeys {

    public static final String PREFIX = "albums/";

    // Minúsculas, dígitos y . _ - /; empieza con letra o dígito. Los UUID de Java salen en minúsculas.
    private static final Pattern SAFE = Pattern.compile("[a-z0-9][a-z0-9._/-]{0,511}");

    private ObjectKeys() {
    }

    public static String original(UUID albumId, UUID photoId) {
        return PREFIX + albumId + "/" + photoId + "/original";
    }

    public static String thumb(UUID albumId, UUID photoId) {
        return PREFIX + albumId + "/" + photoId + "/thumb.jpg";
    }

    /** La segunda defensa contra el path traversal (la primera es el firewall de Spring Security). */
    public static boolean isValid(String key) {
        return key != null
                && SAFE.matcher(key).matches()
                && !key.endsWith("/")
                && !key.contains("//")
                && Arrays.stream(key.split("/")).noneMatch(s -> s.equals(".") || s.equals(".."));
    }

    /** De albums/{álbum}/{foto}/… saca el id de la foto, o null si la clave no tiene esa forma. */
    public static UUID photoIdOf(String key) {
        String[] parts = key.split("/");
        if (parts.length != 4 || !(parts[0] + "/").equals(PREFIX)) {
            return null;
        }
        try {
            return UUID.fromString(parts[2]);
        } catch (IllegalArgumentException e) {
            return null;
        }
    }
}

Las tres defensas son independientes. La primera es el StrictHttpFirewall de Spring Security, que rechaza con 400 cualquier ruta con .., // o un punto codificado como %2e, antes de que llegue a un controlador. La segunda es ObjectKeys.isValid: solo minúsculas, dígitos y . _ - /, sin segmentos . ni ... La tercera está en el disco (paso 4): la ruta final se normaliza y se comprueba que siga dentro del directorio de datos. Cualquiera de las tres alcanzaría hoy; las tres juntas sobreviven a que mañana alguien cambie una.

La decisión
Claves albums/{álbum}/{foto}/original armadas por el servidor, una lista blanca de caracteres y tres defensas en capas distintas.
Lo que descartas
"Limpiar" el nombre del usuario y usarlo en la clave: cada limpieza deja un caso afuera (Unicode, barras invertidas, nombres reservados de Windows). Y claves direccionadas por contenido, con el hash del archivo, como en M09: deduplican, pero obligan a contar referencias antes de borrar, y en un álbum cada foto tiene un solo dueño.
Qué puede salir mal
Si un día las claves llevan mayúsculas, como un id que no es UUID, isValid las rechaza y el error aparece lejos, como un 400 del almacén. La expresión regular y el formato de la clave cambian juntos.

Paso 3. Firmar una URL con HMAC

Una URL firmada es un permiso que viaja solo: dice qué operación se puede hacer sobre qué objeto y hasta cuándo, y lleva un HMAC que solo puede calcular quien tiene la clave. El almacén no necesita preguntarle nada a la api: recalcula el HMAC con la misma clave y compara. Es la idea de M09 y de SigV4, con un formato propio y más corto.

package lab.album.storage;

import java.net.URLEncoder;
import java.nio.charset.StandardCharsets;
import java.security.GeneralSecurityException;
import java.security.MessageDigest;
import java.time.Clock;
import java.time.Duration;
import java.util.Base64;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.SortedMap;
import java.util.TreeMap;
import java.util.regex.Pattern;
import java.util.stream.Collectors;

import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

/**
 * Firma y verifica las URLs del disco local. La firma es un HMAC-SHA256 de una cadena canónica:
 *
 * <pre>
 * A11-HMAC-SHA256
 * PUT
 * /o/albums/…/original
 * ct=image%2Fjpeg&amp;exp=1760000000&amp;kid=k1&amp;max=1048576
 * </pre>
 *
 * El método va en la firma pero no en la URL: el verificador usa el método de la request que llegó, así que una
 * URL para subir no sirve para leer. Los parámetros van ordenados por nombre para que firmar y verificar armen
 * la misma cadena. Las claves llegan como "k2:secreto,k1:secreto": la primera firma y todas verifican.
 */
public final class UrlSigner {

    public enum Verdict { OK, MISSING, MALFORMED, UNKNOWN_KEY, BAD_SIGNATURE, EXPIRED, TOO_LONG }

    private static final Pattern KID = Pattern.compile("[a-z0-9]{1,16}");

    private final Map<String, byte[]> keys = new LinkedHashMap<>();
    private final String currentKid;
    private final Duration maxTtl;
    private final Clock clock;

    public UrlSigner(String spec, Duration maxTtl, Clock clock) {
        if (spec == null || spec.isBlank()) {
            throw new IllegalStateException("Falta FILES_SIGNING_KEYS (kid:secreto, separados por coma)");
        }
        for (String entry : spec.split(",")) {
            String[] kv = entry.trim().split(":", 2);
            if (kv.length != 2 || !KID.matcher(kv[0]).matches()) {
                throw new IllegalStateException("Cada clave va como kid:secreto, con un kid de letras y dígitos");
            }
            byte[] secret;
            try {
                secret = Base64.getDecoder().decode(kv[1]);
            } catch (IllegalArgumentException e) {
                throw new IllegalStateException("El secreto de " + kv[0] + " no es base64: genera uno con openssl rand -base64 32");
            }
            if (secret.length < 32) {
                throw new IllegalStateException("El secreto de " + kv[0] + " tiene " + secret.length
                        + " bytes; hacen falta 32: openssl rand -base64 32");
            }
            keys.put(kv[0], secret);
        }
        this.currentKid = keys.keySet().iterator().next();
        this.maxTtl = maxTtl;
        this.clock = clock;
    }

    public String currentKid() {
        return currentKid;
    }

    /** Devuelve la query completa (con exp, kid y sig), lista para ir después del "?". */
    public String sign(String method, String path, Map<String, String> params, Duration ttl) {
        if (ttl.compareTo(maxTtl) > 0) {
            throw new IllegalArgumentException("Una URL firmada no puede valer más de " + maxTtl);
        }
        SortedMap<String, String> q = new TreeMap<>(params);
        q.put("exp", Long.toString(clock.instant().plus(ttl).getEpochSecond()));
        q.put("kid", currentKid);
        byte[] mac = hmac(keys.get(currentKid), canonical(method, path, q));
        return encode(q) + "&sig=" + Base64.getUrlEncoder().withoutPadding().encodeToString(mac);
    }

    /**
     * Verifica con los parámetros ya decodificados de la request. El orden importa poco para la seguridad, pero
     * sí para lo que aprendes en los experimentos: primero la firma, así que cambiar exp a mano da BAD_SIGNATURE
     * y no EXPIRED.
     */
    public Verdict verify(String method, String path, Map<String, String> query) {
        String sig = query.get("sig");
        String kid = query.get("kid");
        String exp = query.get("exp");
        if (sig == null || kid == null || exp == null) {
            return Verdict.MISSING;
        }
        byte[] secret = keys.get(kid);
        if (secret == null) {
            return Verdict.UNKNOWN_KEY;
        }
        long expiresAt;
        byte[] given;
        try {
            expiresAt = Long.parseLong(exp);
            given = Base64.getUrlDecoder().decode(sig);
        } catch (IllegalArgumentException e) {
            return Verdict.MALFORMED;
        }
        SortedMap<String, String> q = new TreeMap<>(query);
        q.remove("sig");
        byte[] expected = hmac(secret, canonical(method, path, q));
        // MessageDigest.isEqual compara en tiempo constante: no corta en el primer byte distinto, así que el
        // tiempo de respuesta no le dice a nadie cuántos bytes de su firma inventada acertó.
        if (!MessageDigest.isEqual(expected, given)) {
            return Verdict.BAD_SIGNATURE;
        }
        long now = clock.instant().getEpochSecond();
        if (now > expiresAt) {
            return Verdict.EXPIRED;
        }
        if (expiresAt - now > maxTtl.toSeconds()) {
            return Verdict.TOO_LONG;
        }
        return Verdict.OK;
    }

    static String canonical(String method, String path, SortedMap<String, String> q) {
        return "A11-HMAC-SHA256\n" + method.toUpperCase() + "\n" + path + "\n" + encode(q);
    }

    static String encode(SortedMap<String, String> q) {
        return q.entrySet().stream()
                .map(e -> enc(e.getKey()) + "=" + enc(e.getValue()))
                .collect(Collectors.joining("&"));
    }

    private static String enc(String s) {
        return URLEncoder.encode(s, StandardCharsets.UTF_8);
    }

    private static byte[] hmac(byte[] secret, String data) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(secret, "HmacSHA256"));
            return mac.doFinal(data.getBytes(StandardCharsets.UTF_8));
        } catch (GeneralSecurityException e) {
            throw new IllegalStateException(e);
        }
    }
}

Cuatro detalles hacen que esta firma valga algo:

  • El método va firmado pero no viaja. El verificador usa el método de la request que llegó. Una URL firmada para PUT no sirve para GET: la cadena canónica cambia en la segunda línea y la firma no coincide.
  • Todo lo que restringe va dentro. ct, el Content-Type, y max, el tamaño, son parámetros firmados. Quien cambia max=3481234 por max=999999999 en la URL obtiene BAD_SIGNATURE.
  • La comparación es en tiempo constante. MessageDigest.isEqual no corta en el primer byte distinto. Con un Arrays.equals, que sí corta, un atacante podría medir cuánto tarda cada intento y adivinar la firma byte por byte. Es lo que viste en M36.
  • El vencimiento tiene un techo. Aunque la firma sea válida, una URL que vale más que max-ttl (7 días, el máximo de S3 y R2) se rechaza con TOO_LONG. Si alguien roba la clave por un rato, no puede fabricar URLs eternas.

Las claves llegan en FILES_SIGNING_KEYS como k1:secreto. Con varias, separadas por coma, la primera firma y todas verifican. Así se rota una clave sin romper las URLs que ya salieron:

El orden de las dos primeras fases importa: si un proceso firma con k2 antes de que el almacén la conozca, el almacén responde UNKNOWN_KEY a esas URLs. Por eso k2 se agrega primero al final de la lista, se despliega en todos lados, y recién después se pasa al frente.

La decisión
HMAC-SHA256 sobre una cadena canónica con método, ruta y parámetros ordenados; secretos de 32 bytes como mínimo; un kid en la URL para rotar; y la verificación en un orden fijo.
Lo que descartas
Un token aleatorio guardado en la base, que obligaría al almacén a consultarla en cada lectura. Y firmar la URL entera como texto: ?a=1&b=2 y ?b=2&a=1 son la misma request y darían firmas distintas. Tampoco se firma el host, para que la api pueda usar la misma URL por el nombre interno files:9000.
Qué puede salir mal
Si el reloj del almacén va adelantado respecto del de la api, las URLs vencen antes de lo previsto; con 5 minutos de vida, un desfase de segundos no se nota, pero uno de minutos sí. Y si la clave se filtra, cualquiera firma lo que quiera hasta que la rotes: va en .env, nunca en el repositorio.

Paso 4. Un almacén local que solo obedece firmas

El contenedor files es un almacén de objetos de juguete: guarda bytes en un directorio y atiende las rutas de la tabla de endpoints. No tiene usuarios ni sesión; su única credencial es la firma. Tiene dos clases: DiskObjects, que sabe de archivos, y FilesController, que sabe de HTTP.

package lab.album.files;

import java.io.IOException;

/**
 * Un almacén de objetos de juguete sobre un directorio, con las reglas de S3 que importan aquí:
 * escribir es atómico (nadie ve un objeto a medias), el ETag es un hash del contenido, y una subida multipart
 * guarda partes sueltas hasta que alguien la completa o la aborta.
 *
 * <pre>
 * /data/obj/albums/…/original      los bytes
 * /data/meta/albums/…/original     Content-Type, tamaño y ETag
 * /data/mpu/{uploadId}/info        la clave y el Content-Type de una subida multipart
 * /data/mpu/{uploadId}/00001       cada parte, con su .etag al lado
 * /data/tmp/                       lo que se está escribiendo
 * </pre>
 */
@Component
@Profile("files")
public class DiskObjects {

    /** El mínimo de S3 y de R2 para toda parte que no sea la última. */
    public static final long MIN_PART = 5L * 1024 * 1024;

    private static final Pattern UPLOAD_ID = Pattern.compile("[0-9a-f-]{36}");

    private final Path objects;
    private final Path meta;
    private final Path uploads;
    private final Path tmp;

    public DiskObjects(AlbumProps props) throws IOException {
        Path root = Path.of(props.local().root()).toAbsolutePath().normalize();
        this.objects = Files.createDirectories(root.resolve("obj"));
        this.meta = Files.createDirectories(root.resolve("meta"));
        this.uploads = Files.createDirectories(root.resolve("mpu"));
        this.tmp = Files.createDirectories(root.resolve("tmp"));
    }

    public record Stored(Path file, ObjectInfo info) {
    }

    public ObjectInfo put(String key, String contentType, InputStream in, long maxBytes) throws IOException {
        Path target = inside(objects, key);
        Written w = write(in, maxBytes);
        Files.createDirectories(target.getParent());
        // Primero los metadatos y después los bytes: quien encuentra el objeto ya encuentra su Content-Type.
        writeMeta(key, contentType, w.size(), w.etag());
        Files.move(w.file(), target, StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING);
        return info(key).orElseThrow();
    }

    public Optional<Stored> get(String key) throws IOException {
        Optional<ObjectInfo> i = info(key);
        return i.map(x -> new Stored(inside(objects, key), x));
    }

    public Optional<ObjectInfo> info(String key) throws IOException {
        Path file = inside(objects, key);
        Path m = inside(meta, key);
        if (!Files.isRegularFile(file) || !Files.isRegularFile(m)) {
            return Optional.empty();
        }
        Properties p = new Properties();
        try (var r = Files.newBufferedReader(m, StandardCharsets.UTF_8)) {
            p.load(r);
        }
        return Optional.of(new ObjectInfo(key, Files.size(file), p.getProperty("content-type"),
                p.getProperty("etag"), Files.getLastModifiedTime(file).toInstant()));
    }

    public void delete(String key) throws IOException {
        Files.deleteIfExists(inside(objects, key));
        Files.deleteIfExists(inside(meta, key));
    }

    public List<ObjectInfo> list(String prefix) throws IOException {
        List<ObjectInfo> out = new ArrayList<>();
        try (Stream<Path> files = Files.walk(objects)) {
            for (Path f : (Iterable<Path>) files.filter(Files::isRegularFile)::iterator) {
                String key = objects.relativize(f).toString().replace('\\', '/');
                if (key.startsWith(prefix)) {
                    info(key).ifPresent(out::add);
                }
            }
        }
        return out;
    }

    // ---------- multipart ----------

    public String createUpload(String key, String contentType) throws IOException {
        inside(objects, key);
        String id = UUID.randomUUID().toString();
        Path dir = Files.createDirectories(uploads.resolve(id));
        Properties p = new Properties();
        p.setProperty("key", key);
        p.setProperty("content-type", contentType);
        try (var w = Files.newBufferedWriter(dir.resolve("info"), StandardCharsets.UTF_8)) {
            p.store(w, null);
        }
        return id;
    }

    public PartInfo putPart(String uploadId, String key, int partNumber, InputStream in, long maxBytes)
            throws IOException {
        Path dir = uploadDir(uploadId, key);
        if (partNumber < 1 || partNumber > 10_000) {
            throw new StorageException("INVALID_PART", "El número de parte va de 1 a 10 000");
        }
        Written w = write(in, maxBytes);
        String name = "%05d".formatted(partNumber);
        Files.writeString(dir.resolve(name + ".etag"), w.etag());
        // Subir la misma parte otra vez la reemplaza: así se reintenta una parte que falló.
        Files.move(w.file(), dir.resolve(name), StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING);
        return new PartInfo(partNumber, w.etag(), w.size());
    }

    public List<PartInfo> listParts(String uploadId, String key) throws IOException {
        Path dir = uploadDir(uploadId, key);
        List<PartInfo> parts = new ArrayList<>();
        try (Stream<Path> files = Files.list(dir)) {
            for (Path f : files.filter(f -> f.getFileName().toString().matches("\\d{5}")).sorted().toList()) {
                String etag = Files.readString(f.resolveSibling(f.getFileName() + ".etag"));
                parts.add(new PartInfo(Integer.parseInt(f.getFileName().toString()), etag, Files.size(f)));
            }
        }
        return parts;
    }

    /**
     * Junta las partes que nombra el cliente, en orden. Las reglas de R2: números en orden creciente, los ETag
     * tienen que coincidir, todas las partes salvo la última iguales y de al menos 5 MiB. El ETag final, como en
     * S3, no es el hash del archivo: es el hash de los hashes de las partes, con "-N" al final.
     */
    public ObjectInfo complete(String uploadId, String key, List<PartInfo> parts) throws IOException {
        Path dir = uploadDir(uploadId, key);
        if (parts.isEmpty()) {
            throw new StorageException("INVALID_PART", "Sin partes");
        }
        List<Path> files = new ArrayList<>();
        long size0 = -1;
        int previous = 0;
        MessageDigest ofEtags = sha256();
        for (int i = 0; i < parts.size(); i++) {
            PartInfo p = parts.get(i);
            if (p.partNumber() <= previous) {
                throw new StorageException("INVALID_PART", "Las partes van en orden creciente y sin repetir");
            }
            previous = p.partNumber();
            Path f = dir.resolve("%05d".formatted(p.partNumber()));
            if (!Files.isRegularFile(f)) {
                throw new StorageException("INVALID_PART", "No llegó la parte " + p.partNumber());
            }
            String etag = Files.readString(f.resolveSibling(f.getFileName() + ".etag"));
            if (!etag.equals(p.etag())) {
                throw new StorageException("INVALID_PART", "El ETag de la parte " + p.partNumber() + " no coincide");
            }
            long size = Files.size(f);
            boolean last = i == parts.size() - 1;
            if (!last && (size < MIN_PART || (size0 >= 0 && size != size0))) {
                throw new StorageException("INVALID_PART",
                        "Todas las partes salvo la última tienen que medir lo mismo, y al menos 5 MiB");
            }
            size0 = size0 < 0 ? size : size0;
            ofEtags.update(HexFormat.of().parseHex(etag.replace("\"", "")));
            files.add(f);
        }
        Properties info = uploadInfo(dir);
        Path joined = Files.createTempFile(tmp, "mpu-", ".part");
        try (OutputStream out = Files.newOutputStream(joined)) {
            for (Path f : files) {
                Files.copy(f, out);
            }
        }
        String etag = "\"" + HexFormat.of().formatHex(ofEtags.digest()) + "-" + parts.size() + "\"";
        Path target = inside(objects, key);
        Files.createDirectories(target.getParent());
        writeMeta(key, info.getProperty("content-type"), Files.size(joined), etag);
        Files.move(joined, target, StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING);
        deleteTree(dir);
        return info(key).orElseThrow();
    }

    public void abort(String uploadId, String key) throws IOException {
        deleteTree(uploadDir(uploadId, key));
    }

    /**
     * Lo que hace R2 por su cuenta: descartar las subidas multipart que nadie completó ni abortó en 7 días,
     * y lo que quedó en tmp/ de escrituras cortadas. Devuelve cuántas subidas descartó.
     */
    public int expire(Duration uploadsMaxAge, Duration tmpMaxAge) throws IOException {
        Instant now = Instant.now();
        int n = 0;
        try (Stream<Path> dirs = Files.list(uploads)) {
            for (Path d : dirs.toList()) {
                if (Files.getLastModifiedTime(d).toInstant().isBefore(now.minus(uploadsMaxAge))) {
                    deleteTree(d);
                    n++;
                }
            }
        }
        try (Stream<Path> files = Files.list(tmp)) {
            for (Path f : files.toList()) {
                if (Files.getLastModifiedTime(f).toInstant().isBefore(now.minus(tmpMaxAge))) {
                    Files.deleteIfExists(f);
                }
            }
        }
        return n;
    }

    // ---------- piezas comunes ----------

    private record Written(Path file, long size, String etag) {
    }

    /** Copia a un archivo temporal contando bytes y calculando el SHA-256. Pasado maxBytes, corta: 413. */
    private Written write(InputStream in, long maxBytes) throws IOException {
        Path file = Files.createTempFile(tmp, "put-", ".part");
        MessageDigest sha = sha256();
        long total = 0;
        try (OutputStream out = Files.newOutputStream(file)) {
            byte[] buf = new byte[64 * 1024];
            int n;
            while ((n = in.read(buf)) > 0) {
                total += n;
                if (total > maxBytes) {
                    throw new StorageException("TOO_LARGE", "El cuerpo pasa de " + maxBytes + " bytes");
                }
                sha.update(buf, 0, n);
                out.write(buf, 0, n);
            }
        } catch (IOException | RuntimeException e) {
            Files.deleteIfExists(file);
            throw e;
        }
        return new Written(file, total, "\"" + HexFormat.of().formatHex(sha.digest()) + "\"");
    }

    private void writeMeta(String key, String contentType, long size, String etag) throws IOException {
        Path m = inside(meta, key);
        Files.createDirectories(m.getParent());
        Properties p = new Properties();
        p.setProperty("content-type", contentType);
        p.setProperty("size", Long.toString(size));
        p.setProperty("etag", etag);
        Path t = Files.createTempFile(tmp, "meta-", ".tmp");
        try (var w = Files.newBufferedWriter(t, StandardCharsets.UTF_8)) {
            p.store(w, null);
        }
        Files.move(t, m, StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING);
    }

    private Path uploadDir(String uploadId, String key) throws IOException {
        if (uploadId == null || !UPLOAD_ID.matcher(uploadId).matches()) {
            throw new StorageException("NO_SUCH_UPLOAD", "uploadId inválido");
        }
        Path dir = uploads.resolve(uploadId);
        if (!Files.isRegularFile(dir.resolve("info")) || !key.equals(uploadInfo(dir).getProperty("key"))) {
            throw new StorageException("NO_SUCH_UPLOAD", "No existe la subida " + uploadId + " para " + key);
        }
        return dir;
    }

    private static Properties uploadInfo(Path dir) throws IOException {
        Properties p = new Properties();
        try (var r = Files.newBufferedReader(dir.resolve("info"), StandardCharsets.UTF_8)) {
            p.load(r);
        }
        return p;
    }

    /** Resuelve la clave dentro de base y comprueba que no se escapa: la tercera defensa contra "../". */
    private static Path inside(Path base, String key) {
        if (!ObjectKeys.isValid(key)) {
            throw new StorageException("BAD_KEY", "Clave inválida");
        }
        Path p = base.resolve(key).normalize();
        if (!p.startsWith(base)) {
            throw new StorageException("BAD_KEY", "Clave inválida");
        }
        return p;
    }

    private static void deleteTree(Path dir) throws IOException {
        try (Stream<Path> s = Files.walk(dir)) {
            for (Path p : s.sorted(Comparator.reverseOrder()).toList()) {
                Files.deleteIfExists(p);
            }
        } catch (NoSuchFileException e) {
            // Ya no estaba: abortar dos veces no es un error.
        }
    }

    private static MessageDigest sha256() {
        try {
            return MessageDigest.getInstance("SHA-256");
        } catch (NoSuchAlgorithmException e) {
            throw new UncheckedIOException(new IOException(e));
        }
    }
}

Y resolve es la tercera defensa del paso 2.

package lab.album.files;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.context.annotation.Profile;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;

/**
 * El servidor de objetos local: un S3 de juguete. No tiene usuarios ni sesión; la única credencial es la firma
 * de la URL. Rutas:
 *
 * <pre>
 * GET    /o/{clave}                      leer (acepta un Range)       HEAD igual, sin cuerpo
 * PUT    /o/{clave}?ct=…&amp;max=…           subir en un solo PUT
 * POST   /o/{clave}?uploads=1&amp;ct=…       empezar una subida multipart
 * PUT    /o/{clave}?upload=…&amp;part=N      subir una parte
 * GET    /o/{clave}?upload=…              listar las partes que llegaron
 * POST   /o/{clave}?upload=…              completar (cuerpo: las partes en JSON)
 * DELETE /o/{clave}?upload=…              abortar                     DELETE /o/{clave}  borrar
 * GET    /list?prefix=…                   listar objetos
 * </pre>
 */
@RestController
@Profile("files")
public class FilesController {

    private static final Logger log = LoggerFactory.getLogger(FilesController.class);
    /** Sin max firmado, el tope de un PUT simple en S3 y en R2. */
    private static final long MAX_SINGLE_PUT = 5L * 1024 * 1024 * 1024;
    private static final Pattern RANGE = Pattern.compile("bytes=(\\d+)-(\\d*)");

    private final DiskObjects disk;
    private final UrlSigner signer;
    private final JsonMapper json;

    public FilesController(DiskObjects disk, UrlSigner signer, JsonMapper json) {
        this.disk = disk;
        this.signer = signer;
        this.json = json;
    }

    /** Un error con su status y su código. Viaja como JSON y también en X-Error-Code, para LocalObjectStore. */
    static final class Fail extends RuntimeException {
        final int status;
        final String code;

        Fail(int status, String code, String message) {
            super(message);
            this.status = status;
            this.code = code;
        }
    }

    @RequestMapping(path = "/o/**", method = {RequestMethod.GET, RequestMethod.HEAD, RequestMethod.PUT,
            RequestMethod.POST, RequestMethod.DELETE})
    public void object(HttpServletRequest req, HttpServletResponse res) throws IOException {
        handle(res, () -> {
            String path = req.getRequestURI();
            // Las claves no llevan nada que codificar. Un % en la ruta solo puede ser alguien probando
            // %2e%2e: el firewall de Spring Security ya rechaza la mayoría; esto cierra el resto.
            if (path.indexOf('%') >= 0) {
                throw new Fail(400, "BAD_KEY", "La ruta no puede llevar caracteres codificados");
            }
            String key = path.substring("/o/".length());
            if (!ObjectKeys.isValid(key)) {
                throw new Fail(400, "BAD_KEY", "Clave inválida");
            }
            Map<String, String> q = query(req.getQueryString());
            String method = req.getMethod();
            checkSignature(method, path, q);
            switch (method) {
                case "GET", "HEAD" -> {
                    if (q.containsKey("upload")) {
                        writeJson(res, 200, disk.listParts(q.get("upload"), key));
                    } else {
                        serve(req, res, key, q, method.equals("HEAD"));
                    }
                }
                case "PUT" -> put(req, res, key, q);
                case "POST" -> post(req, res, key, q);
                case "DELETE" -> {
                    if (q.containsKey("upload")) {
                        disk.abort(q.get("upload"), key);
                    } else {
                        disk.delete(key);
                    }
                    res.setStatus(204);
                }
                default -> throw new Fail(405, "METHOD_NOT_ALLOWED", method);
            }
        });
    }

    @GetMapping("/list")
    public void list(HttpServletRequest req, HttpServletResponse res) throws IOException {
        handle(res, () -> {
            Map<String, String> q = query(req.getQueryString());
            checkSignature("GET", "/list", q);
            writeJson(res, 200, disk.list(q.getOrDefault("prefix", "")));
        });
    }

    private void serve(HttpServletRequest req, HttpServletResponse res, String key, Map<String, String> q,
                       boolean headOnly) throws IOException {
        DiskObjects.Stored stored = disk.get(key)
                .orElseThrow(() -> new Fail(404, "NOT_FOUND", "No existe " + key));
        ObjectInfo info = stored.info();
        long size = info.size();
        long first = 0;
        long last = size - 1;
        String range = req.getHeader("Range");
        if (range != null) {
            // Un solo rango, "bytes=a-b" o "bytes=a-": lo que usan la api y el reproductor de video.
            Matcher m = RANGE.matcher(range);
            if (!m.matches() || Long.parseLong(m.group(1)) >= size) {
                res.setHeader("Content-Range", "bytes */" + size);
                throw new Fail(416, "BAD_RANGE", "Rango inválido: " + range);
            }
            first = Long.parseLong(m.group(1));
            last = m.group(2).isEmpty() ? size - 1 : Math.min(Long.parseLong(m.group(2)), size - 1);
            res.setStatus(206);
            res.setHeader("Content-Range", "bytes " + first + "-" + last + "/" + size);
        } else {
            res.setStatus(200);
        }
        long length = last - first + 1;
        res.setContentType(info.contentType());
        res.setContentLengthLong(length);
        res.setHeader("ETag", info.etag());
        res.setHeader("Last-Modified",
                DateTimeFormatter.RFC_1123_DATE_TIME.format(info.lastModified().atZone(ZoneOffset.UTC)));
        res.setHeader("Accept-Ranges", "bytes");
        // Lo que sirve este origen son datos, nunca una página: el navegador no adivina el tipo (nosniff), y si
        // alguien logra que se abra como documento, corre sin scripts ni acceso a nada (sandbox).
        res.setHeader("X-Content-Type-Options", "nosniff");
        res.setHeader("Content-Security-Policy", "sandbox; default-src 'none'");
        // rcd y rcc vienen firmados por la api: el usuario no puede inventarlos.
        res.setHeader("Cache-Control", q.getOrDefault("rcc", "private, no-cache"));
        if (q.containsKey("rcd")) {
            res.setHeader("Content-Disposition", q.get("rcd"));
        }
        if (headOnly) {
            return;
        }
        try (InputStream in = Files.newInputStream(stored.file()); OutputStream out = res.getOutputStream()) {
            in.skipNBytes(first);
            byte[] buf = new byte[64 * 1024];
            long left = length;
            while (left > 0) {
                int n = in.read(buf, 0, (int) Math.min(buf.length, left));
                if (n < 0) {
                    break;
                }
                out.write(buf, 0, n);
                left -= n;
            }
        }
    }

    private void put(HttpServletRequest req, HttpServletResponse res, String key, Map<String, String> q)
            throws IOException {
        long max = q.containsKey("max") ? Long.parseLong(q.get("max")) : MAX_SINGLE_PUT;
        // Si el navegador avisa el tamaño (Content-Length) y pasa del tope, se rechaza antes de leer un byte.
        // Si no avisa, DiskObjects cuenta mientras escribe y corta al pasarse.
        if (req.getContentLengthLong() > max) {
            throw new Fail(413, "TOO_LARGE", "El cuerpo pasa de " + max + " bytes");
        }
        if (q.containsKey("upload")) {
            PartInfo p = disk.putPart(q.get("upload"), key, Integer.parseInt(q.get("part")), req.getInputStream(), max);
            res.setHeader("ETag", p.etag());
            res.setStatus(200);
            return;
        }
        String signed = q.get("ct");
        if (signed == null) {
            throw new Fail(400, "BAD_REQUEST", "Un PUT simple lleva ct firmado");
        }
        // Como R2: el Content-Type que llega tiene que ser el que se firmó. Si no, quien tiene una URL para
        // subir una foto podría subir un text/html y servirlo desde este origen.
        if (!signed.equalsIgnoreCase(req.getContentType())) {
            throw new Fail(403, "CONTENT_TYPE_MISMATCH",
                    "La URL se firmó para " + signed + " y llegó " + req.getContentType());
        }
        ObjectInfo info = disk.put(key, signed, req.getInputStream(), max);
        log.info("PUT {} {} bytes", key, info.size());
        res.setHeader("ETag", info.etag());
        res.setStatus(200);
    }

    private void post(HttpServletRequest req, HttpServletResponse res, String key, Map<String, String> q)
            throws IOException {
        if (q.containsKey("uploads")) {
            String ct = q.get("ct");
            if (ct == null) {
                throw new Fail(400, "BAD_REQUEST", "Falta ct");
            }
            writeJson(res, 200, Map.of("upload_id", disk.createUpload(key, ct)));
        } else if (q.containsKey("upload")) {
            List<PartInfo> parts = json.readValue(req.getInputStream(), new TypeReference<List<PartInfo>>() { });
            ObjectInfo info = disk.complete(q.get("upload"), key, parts);
            log.info("Multipart completo {} {} bytes en {} partes", key, info.size(), parts.size());
            writeJson(res, 200, Map.of("etag", info.etag(), "size", info.size()));
        } else {
            throw new Fail(400, "BAD_REQUEST", "Un POST lleva ?uploads o ?upload");
        }
    }

    private void checkSignature(String method, String path, Map<String, String> q) {
        UrlSigner.Verdict v = signer.verify(method, path, q);
        if (v != UrlSigner.Verdict.OK) {
            String why = switch (v) {
                case MISSING -> "Faltan exp, kid o sig";
                case MALFORMED -> "exp o sig no tienen el formato esperado";
                case UNKNOWN_KEY -> "No conozco la clave " + q.get("kid");
                case BAD_SIGNATURE -> "La firma no corresponde a este método, ruta y parámetros";
                case EXPIRED -> "La URL venció";
                case TOO_LONG -> "La URL vale más que el máximo permitido";
                default -> v.name();
            };
            throw new Fail(403, v.name(), why);
        }
    }

    /** Decodifica la query a mano: un parámetro repetido es un 400, no "gana el primero" ni "gana el último". */
    static Map<String, String> query(String raw) {
        Map<String, String> q = new HashMap<>();
        if (raw == null || raw.isEmpty()) {
            return q;
        }
        for (String kv : raw.split("&")) {
            int i = kv.indexOf('=');
            String k = URLDecoder.decode(i < 0 ? kv : kv.substring(0, i), StandardCharsets.UTF_8);
            String v = i < 0 ? "" : URLDecoder.decode(kv.substring(i + 1), StandardCharsets.UTF_8);
            if (q.put(k, v) != null) {
                throw new Fail(400, "BAD_REQUEST", "Parámetro repetido: " + k);
            }
        }
        return q;
    }

    private interface Action {
        void run() throws IOException;
    }

    private void handle(HttpServletResponse res, Action action) throws IOException {
        try {
            action.run();
        } catch (Fail f) {
            error(res, f.status, f.code, f.getMessage());
        } catch (StorageException e) {
            int status = switch (e.code()) {
                case "NOT_FOUND", "NO_SUCH_UPLOAD" -> 404;
                case "TOO_LARGE" -> 413;
                case "INVALID_PART", "BAD_KEY" -> 400;
                default -> 500;
            };
            error(res, status, e.code(), e.getMessage());
        } catch (NumberFormatException e) {
            error(res, 400, "BAD_REQUEST", "Un número inválido en la query");
        }
    }

    private void error(HttpServletResponse res, int status, String code, String message) throws IOException {
        if (res.isCommitted()) {
            log.warn("{} después de empezar a responder: {}", code, message);
            return;
        }
        res.resetBuffer();
        res.setHeader("X-Error-Code", code);
        writeJson(res, status, Map.of("error", Map.of("code", code, "message", message)));
    }

    private void writeJson(HttpServletResponse res, int status, Object body) throws IOException {
        res.setStatus(status);
        res.setContentType("application/json");
        json.writeValue(res.getOutputStream(), body);
    }
}

Cada request sigue el mismo camino: rechazar la ruta si trae algo codificado con %, validar la forma de la clave, decodificar la query a mano (un parámetro repetido es un 400, para que nadie juegue con cuál gana), verificar la firma con el método de la request y recién ahí tocar el disco. Las respuestas de error llevan el código en X-Error-Code, para que los experimentos lo vean con curl -i. Al servir un objeto, el almacén agrega X-Content-Type-Options: nosniff: el navegador usa el Content-Type que se guardó y no intenta adivinar si unos bytes "parecen" HTML.

El navegador sube desde localhost:8080 a localhost:9000, otro origen. Un PUT con Content-Type: image/jpeg no es una "request simple" para CORS, así que antes de mandarlo el navegador pregunta con un OPTIONS, el preflight:

package lab.album.files;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Profile;
import org.springframework.core.annotation.Order;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.web.cors.CorsConfiguration;
import org.springframework.web.cors.CorsConfigurationSource;
import org.springframework.web.cors.UrlBasedCorsConfigurationSource;

import lab.album.AlbumProps;

/**
 * La seguridad del servidor de archivos: nada de login ni de sesión (la firma es la credencial), pero sí el
 * firewall de Spring Security, que rechaza rutas con "..", "//" o barras codificadas antes de llegar al
 * controlador. Y CORS: el navegador sube desde localhost:8080 a localhost:9000, otro origen.
 */
@Configuration
@Profile("files")
public class FilesSecurityConfig {

    // Primero esta cadena: en las pruebas conviven files y api en el mismo proceso.
    @Bean
    @Order(1)
    SecurityFilterChain filesChain(HttpSecurity http) throws Exception {
        http.securityMatcher("/o/**", "/list")
                .authorizeHttpRequests(a -> a.anyRequest().permitAll())
                // Sin cookies no hay CSRF: una página ajena que dispara un PUT necesitaría una URL firmada.
                .csrf(c -> c.disable())
                .cors(Customizer.withDefaults())
                .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                // Spring Security agrega "Cache-Control: no-cache, no-store" a todo. Aquí el Cache-Control lo
                // decide la api (va firmado en rcc): las miniaturas se cachean en el navegador.
                .headers(h -> h.cacheControl(c -> c.disable()));
        return http.build();
    }

    /**
     * Solo la página del álbum puede subir desde un navegador. CORS no protege el almacén (curl lo ignora):
     * le dice al navegador qué páginas pueden leer las respuestas. La protección es la firma.
     */
    @Bean
    CorsConfigurationSource corsConfigurationSource(AlbumProps props) {
        CorsConfiguration c = new CorsConfiguration();
        c.setAllowedOrigins(props.local().allowedOrigins());
        c.addAllowedMethod("GET");
        c.addAllowedMethod("HEAD");
        c.addAllowedMethod("PUT");
        c.addAllowedHeader("Content-Type");
        c.addExposedHeader("ETag");
        // El navegador guarda la respuesta al preflight una hora: un OPTIONS por hora, no uno por parte.
        c.setMaxAge(3600L);
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/o/**", c);
        return source;
    }
}

CORS no protege al almacén: curl lo ignora por completo. Lo que hace CORS es decirle al navegador qué páginas pueden leer las respuestas de otro origen. La protección es la firma. Lo que sí aporta aquí es que una página ajena, aunque consiga una URL firmada, no puede subir desde el navegador de una víctima y leer el resultado. addExposedHeader("ETag") deja que JavaScript lea el ETag de cada parte. El álbum no lo necesita, porque en el paso 8 la api le pide la lista de partes al almacén, pero un cliente que completa por su cuenta, como los SDK de S3 en el navegador, sí: sin exponerlo, el header llega y JavaScript lo ve como null.

package lab.album.files;

import java.io.IOException;

import org.springframework.stereotype.Component;

/** Una vez por hora, la limpieza que en R2 hace la regla de ciclo de vida del bucket. */
@Component
@Profile("files")
public class FilesHousekeeping {

    private static final Logger log = LoggerFactory.getLogger(FilesHousekeeping.class);

    private final DiskObjects disk;

    public FilesHousekeeping(DiskObjects disk) {
        this.disk = disk;
    }

    @Scheduled(fixedDelay = 3_600_000, initialDelay = 60_000)
    void expire() throws IOException {
        int n = disk.expire(Duration.ofDays(7), Duration.ofDays(1));
        if (n > 0) {
            log.info("Descarté {} subidas multipart abandonadas", n);
        }
    }
}

FilesHousekeeping hace lo que R2 hace solo con una regla de ciclo de vida: descarta las subidas multipart que nadie completó ni abortó en 7 días, y los temporales que dejó una escritura cortada. Prueba el almacén con una URL inventada:

curl -i -X PUT --data-binary 'hola' 'http://localhost:9000/o/albums/x/y/original?ct=text%2Fplain&exp=9999999999&kid=k1&sig=AAAA'

Tiene que responder 403 con X-Error-Code: BAD_SIGNATURE. Sin una firma de verdad, el almacén no hace nada.

La decisión
Un servidor de archivos propio, en la misma imagen con el perfil files, que verifica la firma antes de cualquier otra cosa, escribe de forma atómica, corta al pasar de max y manda nosniff.
Lo que descartas
Servir los archivos desde la api con un FileSystemResource: volverías al caño de la excusa. Y un Nginx con secure_link, que verifica un MD5 de la URL: sirve para leer, pero no sabe de multipart ni limita el tamaño de un PUT.
Qué puede salir mal
Con un cuerpo grande que pasa de max, el 413 sale antes de que el navegador termine de mandar, y Tomcat puede cerrar la conexión en lugar de leer el resto: el navegador ve un error de red, no el 413. Por eso la página revisa el tamaño antes de pedir la URL, y la api lo vuelve a revisar al confirmar.

Paso 5. Una interfaz, dos almacenes

La api y el worker no saben si hablan con el disco local o con R2. Hablan con ObjectStore, que tiene dos clases de métodos: los presign*, que no hacen red y solo firman una URL para el navegador, y los demás, que sí le hablan al almacén.

/**
 * Lo que la api y el worker le piden al almacén. Dos implementaciones: el disco local (LocalObjectStore, que
 * habla con el contenedor files) y Cloudflare R2 (R2ObjectStore, con el AWS SDK). Los métodos presign* no hacen

public interface ObjectStore {

    /** "local" o "r2": para los logs y para la CSP de la página. */
    String name();

    /** El origen que la página tiene que permitir en su CSP (img-src y connect-src). */
    String browserOrigin();

    /**
     * Una URL para subir un objeto con un PUT. El Content-Type queda firmado: el navegador tiene que mandar ese.
     * maxBytes solo lo impone el disco local; R2 no puede limitar el tamaño de un PUT firmado, y por eso
     * la api revisa el tamaño real al confirmar.
     */
    URI presignPut(String key, String contentType, long maxBytes, Duration ttl);

    /** Una URL para leer. contentDisposition y cacheControl, si no son null, son los headers de la respuesta. */
    URI presignGet(String key, Duration ttl, String contentDisposition, String cacheControl);

    /** Empieza una subida multipart y devuelve su uploadId. */
    String createMultipart(String key, String contentType);

    URI presignPart(String key, String uploadId, int partNumber, long maxBytes, Duration ttl);

    /** Las partes que ya llegaron, en orden. NO_SUCH_UPLOAD si la subida ya terminó o se abortó. */
    List<PartInfo> listParts(String key, String uploadId);

    /** Junta las partes en un objeto. INVALID_PART si falta una, un ETag no coincide o el tamaño no sirve. */
    void completeMultipart(String key, String uploadId, List<PartInfo> parts);

    /** Descarta las partes. No falla si la subida ya no existe. */

    /** Los bytes de first a last, inclusive: para mirar la firma del formato sin bajar el archivo. */
    byte[] readRange(String key, long first, long last);

    /** El objeto entero en memoria, con un tope: TOO_LARGE si pasa de maxBytes. */
    byte[] readAll(String key, long maxBytes);

    void put(String key, InputStream data, long length, String contentType, String cacheControl);

    /** No falla si el objeto no existe. */
    void delete(String key);

    /** Los objetos con ese prefijo. */
    List<ObjectInfo> list(String prefix);

/**
 * El almacén local, visto desde la api y el worker: un cliente HTTP del contenedor files. No toca el disco:
 * cada operación es una request con una URL firmada por este mismo proceso, igual que las del navegador.
 * Las URLs para el navegador usan publicUrl (localhost:9000); las propias, internalUrl (files:9000).
 */
public class LocalObjectStore implements ObjectStore {

    // Lo que dura una URL que el propio servidor usa enseguida.
    private static final Duration SELF = Duration.ofMinutes(1);
    private static final Duration TIMEOUT = Duration.ofSeconds(30);

    private final UrlSigner signer;
    private final String publicUrl;
    private final String internalUrl;
    private final JsonMapper json;
    private final HttpClient http = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(2)).build();

    public LocalObjectStore(UrlSigner signer, String publicUrl, String internalUrl, JsonMapper json) {
        this.signer = signer;
        this.publicUrl = publicUrl;
        this.internalUrl = internalUrl;
        this.json = json;
    }

    @Override
    public String name() {
        return "local";
    }

    @Override
    public String browserOrigin() {
        return publicUrl;
    }

    @Override
    public URI presignPut(String key, String contentType, long maxBytes, Duration ttl) {
        return url(publicUrl, "PUT", key, Map.of("ct", contentType, "max", Long.toString(maxBytes)), ttl);
    }

    @Override
    public URI presignGet(String key, Duration ttl, String contentDisposition, String cacheControl) {
        Map<String, String> p = new HashMap<>();
        if (contentDisposition != null) {
            p.put("rcd", contentDisposition);
        }
        if (cacheControl != null) {
            p.put("rcc", cacheControl);
        }
        return url(publicUrl, "GET", key, p, ttl);
    }

    @Override
    public String createMultipart(String key, String contentType) {
        var r = send("POST", key, Map.of("uploads", "1", "ct", contentType), HttpRequest.BodyPublishers.noBody());
        return json.readTree(r.body()).get("upload_id").asString();
    }

    @Override
    public URI presignPart(String key, String uploadId, int partNumber, long maxBytes, Duration ttl) {
        return url(publicUrl, "PUT", key,
                Map.of("upload", uploadId, "part", Integer.toString(partNumber), "max", Long.toString(maxBytes)), ttl);
    }

    @Override
    public List<PartInfo> listParts(String key, String uploadId) {
        var r = send("GET", key, Map.of("upload", uploadId), HttpRequest.BodyPublishers.noBody());
        return json.readValue(r.body(), new TypeReference<List<PartInfo>>() { });
    }

    @Override
    public void completeMultipart(String key, String uploadId, List<PartInfo> parts) {
        send("POST", key, Map.of("upload", uploadId),
                HttpRequest.BodyPublishers.ofByteArray(json.writeValueAsBytes(parts)));
    }

    @Override
    public void abortMultipart(String key, String uploadId) {
        try {
            send("DELETE", key, Map.of("upload", uploadId), HttpRequest.BodyPublishers.noBody());
        } catch (StorageException e) {
            if (!e.is("NO_SUCH_UPLOAD")) {
                throw e;
            }
        }
    }

    @Override
    public Optional<ObjectInfo> head(String key) {
        HttpResponse<byte[]> r;
        try {
            r = send("HEAD", key, Map.of(), HttpRequest.BodyPublishers.noBody());
        } catch (StorageException e) {
            if (e.is("NOT_FOUND")) {
                return Optional.empty();
            }
            throw e;
        }
        var h = r.headers();
        return Optional.of(new ObjectInfo(key,
                h.firstValueAsLong("Content-Length").orElse(-1),
                h.firstValue("Content-Type").orElse(null),
                h.firstValue("ETag").orElse(null),
                h.firstValue("Last-Modified")
                        .map(v -> ZonedDateTime.parse(v, DateTimeFormatter.RFC_1123_DATE_TIME).toInstant())
                        .orElse(null)));
    }

    @Override
    public byte[] readRange(String key, long first, long last) {
        URI u = url(internalUrl, "GET", key, Map.of(), SELF);
        return exchange(HttpRequest.newBuilder(u).timeout(TIMEOUT).header("Range", "bytes=" + first + "-" + last)
                .GET().build()).body();
    }

    @Override
    public byte[] readAll(String key, long maxBytes) {
        Optional<ObjectInfo> info = head(key);
        if (info.isEmpty()) {
            throw new StorageException("NOT_FOUND", "No existe " + key);
        }
        if (info.get().size() > maxBytes) {
            throw new StorageException("TOO_LARGE", key + " pesa " + info.get().size() + " bytes");
        }
        byte[] body = send("GET", key, Map.of(), HttpRequest.BodyPublishers.noBody()).body();
        // Entre el HEAD y el GET alguien pudo reemplazar el objeto: se vuelve a revisar con lo que llegó.
        if (body.length > maxBytes) {
            throw new StorageException("TOO_LARGE", key + " pesa " + body.length + " bytes");
        }
        return body;
    }

    @Override
    public void put(String key, InputStream data, long length, String contentType, String cacheControl) {
        URI u = url(internalUrl, "PUT", key, Map.of("ct", contentType), SELF);
        HttpRequest.Builder b = HttpRequest.newBuilder(u).timeout(Duration.ofMinutes(5))
                .header("Content-Type", contentType)
                .PUT(HttpRequest.BodyPublishers.fromPublisher(HttpRequest.BodyPublishers.ofInputStream(() -> data), length));
        exchange(b.build());
    }

    @Override
    public void delete(String key) {
        try {
            send("DELETE", key, Map.of(), HttpRequest.BodyPublishers.noBody());
        } catch (StorageException e) {
            if (!e.is("NOT_FOUND")) {
                throw e;
            }
        }
    }

    @Override
    public List<ObjectInfo> list(String prefix) {
        String query = signer.sign("GET", "/list", Map.of("prefix", prefix), SELF);
        HttpRequest req = HttpRequest.newBuilder(URI.create(internalUrl + "/list?" + query)).timeout(TIMEOUT).GET().build();
        return json.readValue(exchange(req).body(), new TypeReference<List<ObjectInfo>>() { });
    }

    private URI url(String base, String method, String key, Map<String, String> params, Duration ttl) {
        if (!ObjectKeys.isValid(key)) {
            throw new IllegalArgumentException("Clave inválida: " + key);
        }
        String path = "/o/" + key;
        return URI.create(base + path + "?" + signer.sign(method, path, params, ttl));
    }

    private HttpResponse<byte[]> send(String method, String key, Map<String, String> params,
                                      HttpRequest.BodyPublisher body) {
        URI u = url(internalUrl, method, key, params, SELF);
        return exchange(HttpRequest.newBuilder(u).timeout(TIMEOUT).method(method, body).build());
    }

    private HttpResponse<byte[]> exchange(HttpRequest req) {
        HttpResponse<byte[]> r;
        try {
            r = http.send(req, HttpResponse.BodyHandlers.ofByteArray());
        } catch (IOException e) {
            throw new StorageException("UNAVAILABLE", "El almacén local no responde: " + e.getMessage(), e);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new StorageException("UNAVAILABLE", "Interrumpido", e);
        }
        if (r.statusCode() < 300) {
            return r;
        }
        String code = switch (r.statusCode()) {
            case 404 -> r.headers().firstValue("X-Error-Code").orElse("NOT_FOUND");
            case 400, 413 -> r.headers().firstValue("X-Error-Code").orElse("BAD_REQUEST");
            case 403 -> "FORBIDDEN";
            default -> "UNAVAILABLE";
        };
        throw new StorageException(code, req.method() + " " + req.uri().getPath() + " respondió " + r.statusCode());
    }
}

StorageException lleva un código (NOT_FOUND, NO_SUCH_UPLOAD, INVALID_PART, TOO_LARGE, UNAVAILABLE…) que las dos implementaciones usan igual: el resto del código pregunta e.is("NO_SUCH_UPLOAD") y no le importa si vino de un 404 del disco o de una NoSuchUploadException del SDK.

La decisión
Una interfaz con lo que el álbum usa, ni un método más, y la elección del almacén por configuración.
Lo que descartas
Usar el S3Client del SDK en todos lados y apuntarlo a MinIO en local: es lo más común en producción, y lo que harías si ya tuvieras S3. Aquí la interfaz propia es lo que permite que el almacén local firme con tu HMAC, y deja claro qué operaciones necesita el álbum.
Qué puede salir mal
Las dos implementaciones se pueden separar sin que nadie lo note: una devuelve las partes en orden y la otra no, o una lanza NOT_FOUND donde la otra devuelve vacío. Las pruebas corren contra el almacén local; contra R2, el paso 12 tiene su propia comprobación a mano.

Las comprobaciones van de la más barata a la más cara: el rol, el tipo, el tamaño y cuántas subidas pendientes tiene la persona. Esa última es la que evita que alguien pida diez mil URLs y deje diez mil filas pending. Con 16 MiB o menos, alcanza con un solo PUT; con más, la subida va en partes de 8 MiB (paso 8). En el multipart, el orden de las dos escrituras está pensado: primero se crea la subida en el almacén y después la fila, porque una subida sin fila la descarta el almacén solo, y una fila sin subida apuntaría a nada.

El max firmado en la URL es exactamente el tamaño declarado. El almacén local corta al pasarse; R2 no puede, porque no acepta un límite de tamaño en un PUT firmado. Por eso la api nunca cree el tamaño hasta confirmar.

package lab.album.photo;

import java.util.Arrays;
import java.util.Optional;

/**
 * Los tres tipos que acepta el álbum y cómo se reconoce cada uno por sus primeros bytes (su "firma" o magic
 * number). El Content-Type lo declara el navegador y la extensión la elige el usuario: ninguno de los dos
 * prueba nada. Los primeros bytes sí dicen qué formato es; que el archivo entero sea válido lo dice el
 * decodificador, en el worker.
 */
public final class MediaTypes {

    public enum Kind { IMAGE, VIDEO }

    private static final byte[] JPEG = {(byte) 0xFF, (byte) 0xD8, (byte) 0xFF};
    private static final byte[] PNG = {(byte) 0x89, 'P', 'N', 'G', '\r', '\n', 0x1A, '\n'};
    /** En un MP4 los bytes 4 a 7 dicen "ftyp" (los 0 a 3 son el tamaño de esa primera caja). */
    private static final byte[] FTYP = {'f', 't', 'y', 'p'};

    /** Cuántos bytes hay que leer para reconocer cualquiera de los tres. */
    public static final int HEAD_BYTES = 16;

    private MediaTypes() {
    }

    public static Optional<Kind> kindOf(String contentType) {
        return switch (contentType == null ? "" : contentType) {
            case "image/jpeg", "image/png" -> Optional.of(Kind.IMAGE);
            case "video/mp4" -> Optional.of(Kind.VIDEO);
            default -> Optional.empty();
        };
    }

    public static boolean matches(String contentType, byte[] head) {
        return switch (contentType) {
            case "image/jpeg" -> startsWith(head, 0, JPEG);
            case "image/png" -> startsWith(head, 0, PNG);
            case "video/mp4" -> startsWith(head, 4, FTYP);
            default -> false;
        };
    }

    private static boolean startsWith(byte[] data, int offset, byte[] prefix) {
        return data.length >= offset + prefix.length
                && Arrays.equals(data, offset, offset + prefix.length, prefix, 0, prefix.length);
    }
}

    static final HttpStatus UNPROCESSABLE = HttpStatus.valueOf(422);
    private static final int MAX_PART_URLS = 100;

    public record UploadRequest(@NotBlank @Size(max = 1000) String filename,
                                @NotBlank @JsonProperty("content_type") String contentType,
                                @Positive long size) {
    }

    /** La respuesta a "quiero subir": una URL (single) o el plan de partes (multipart). */
    @JsonInclude(JsonInclude.Include.NON_NULL)
    public record Ticket(@JsonProperty("photo_id") UUID photoId, String strategy, String method, URI url,
                         Map<String, String> headers, @JsonProperty("part_size") Long partSize,
                         @JsonProperty("part_count") Integer partCount,
                         @JsonProperty("expires_at") Instant expiresAt) {
    }

    public record PartUrl(@JsonProperty("part_number") int partNumber, URI url) {
    }

    public record PartUrls(List<PartUrl> parts, @JsonProperty("expires_at") Instant expiresAt) {
    }

    private final JdbcClient jdbc;
    private final TransactionTemplate tx;
    private final ObjectStore store;
    private final AlbumAccess access;
    private final PhotoUrls urls;
    private final AlbumProps props;
    private final Clock clock;

    public UploadService(JdbcClient jdbc, TransactionTemplate tx, ObjectStore store, AlbumAccess access,
                         PhotoUrls urls, AlbumProps props, Clock clock) {
        this.jdbc = jdbc;
        this.tx = tx;
        this.store = store;
        this.access = access;
        this.urls = urls;
        this.props = props;
        this.clock = clock;
    }

    // ---------- 1. Pedir la subida ----------

    public Ticket begin(UUID albumId, long userId, UploadRequest req) {
        access.require(albumId, userId, AlbumAccess.Role.EDITOR);
        MediaTypes.Kind kind = MediaTypes.kindOf(req.contentType()).orElseThrow(() -> new ApiError(UNPROCESSABLE,
                "UNSUPPORTED_TYPE", "Solo se aceptan image/jpeg, image/png y video/mp4."));
        long max = (kind == MediaTypes.Kind.IMAGE ? props.maxImageBytes() : props.maxVideoBytes()).toBytes();
        if (req.size() > max) {
            throw new ApiError(UNPROCESSABLE, "FILE_TOO_LARGE", "El archivo pasa del máximo.",
                    Map.of("max_bytes", max), null);
        }
        long pending = jdbc.sql("SELECT count(*) FROM photos WHERE uploader_id = :u AND status = 'pending'")
                .param("u", userId)
                .query(Long.class)
                .single();
        if (pending >= props.maxPendingPerUser()) {
            throw new ApiError(HttpStatus.TOO_MANY_REQUESTS, "TOO_MANY_PENDING",
                    "Tienes demasiadas subidas sin terminar. Termina o borra alguna.",
                    Map.of("pending", pending), 60);
        }
        // El id lo genera la base (UUIDv7: ordenado por tiempo, el índice crece por un extremo).
        UUID photoId = jdbc.sql("SELECT uuidv7()").query(UUID.class).single();
        String key = ObjectKeys.original(albumId, photoId);
        String name = cleanName(req.filename());
        Instant expires = clock.instant().plus(props.uploadTtl());

        if (req.size() <= props.singlePutMax().toBytes()) {
            insert(photoId, albumId, userId, kind, name, req, key, null, null, null);
            URI url = store.presignPut(key, req.contentType(), req.size(), props.uploadTtl());
            log.info("Subida simple {} ({} bytes) por {}", photoId, req.size(), store.name());
            return new Ticket(photoId, "single", "PUT", url, Map.of("Content-Type", req.contentType()),
                    null, null, expires);
        }

        long partSize = props.partSize().toBytes();
        int partCount = (int) ((req.size() + partSize - 1) / partSize);
        // Primero el almacén y después la fila. Si la api muere entre los dos, queda una subida sin fila que
        // nadie completará: la regla de ciclo de vida del bucket (o la limpieza, en local) la descarta.
        // Al revés quedaría una fila que apunta a una subida que no existe.
        String uploadId = store.createMultipart(key, req.contentType());
        try {
            insert(photoId, albumId, userId, kind, name, req, key, uploadId, partSize, partCount);
        } catch (RuntimeException e) {
            store.abortMultipart(key, uploadId);
            throw e;
        }
        log.info("Subida multipart {} ({} bytes, {} partes de {})", photoId, req.size(), partCount, partSize);
        return new Ticket(photoId, "multipart", "PUT", null, null, partSize, partCount, expires);
    }

    private void insert(UUID id, UUID albumId, long userId, MediaTypes.Kind kind, String name, UploadRequest req,
                        String key, String uploadId, Long partSize, Integer partCount) {
        jdbc.sql("""
                        INSERT INTO photos (id, album_id, uploader_id, kind, original_name, content_type,
                                            declared_size, object_key, upload_id, part_size, part_count)
                        VALUES (:id, :a, :u, :k, :n, :ct, :s, :key, :up, :ps, :pc)""")
                .param("id", id)
                .param("a", albumId)
                .param("u", userId)
                .param("k", kind.name().toLowerCase())
                .param("n", name)
                .param("ct", req.contentType())
                .param("s", req.size())
                .param("key", key)
                .param("up", uploadId)
                .param("ps", partSize)
                .param("pc", partCount)
                .update();
    }

    /**
     * El nombre solo se muestra y va en la descarga (Content-Disposition). Sin caracteres de control (un salto de
     * línea partiría el header), sin comillas ni barras, y con un largo acotado.
     */
    static String cleanName(String raw) {
        String s = raw.replaceAll("[\\p{Cntrl}\"\\\\/]", "_").strip();
        if (s.length() > 200) {
            s = s.substring(s.length() - 200);
        }
        return s.isEmpty() ? "archivo" : s;
    }

    // ---------- 2. Las URLs de las partes ----------

    public PartUrls partUrls(UUID photoId, long userId, List<Integer> numbers) {
        PhotoRow p = pendingMultipartOf(photoId, userId);
        if (numbers.isEmpty() || numbers.size() > MAX_PART_URLS) {
            throw new ApiError(HttpStatus.BAD_REQUEST, "BAD_PART_NUMBERS", "Pide entre 1 y 100 partes por llamada.");
        }
        List<PartUrl> out = new ArrayList<>();
        for (int n : numbers) {
            if (n < 1 || n > p.partCount()) {
                throw new ApiError(HttpStatus.BAD_REQUEST, "BAD_PART_NUMBERS",
                        "Las partes van de 1 a " + p.partCount() + ".");
            }
            out.add(new PartUrl(n, store.presignPart(p.objectKey(), p.uploadId(), n, p.partSize(),
                    props.uploadTtl())));
        }
        return new PartUrls(out, clock.instant().plus(props.uploadTtl()));
    }

    /** Lo que ya llegó: para retomar una subida cortada sin volver a mandar esas partes. */
    public List<PartInfo> uploadedParts(UUID photoId, long userId) {
        PhotoRow p = pendingMultipartOf(photoId, userId);
        try {
            return store.listParts(p.objectKey(), p.uploadId());
        } catch (StorageException e) {
            if (e.is("NO_SUCH_UPLOAD")) {
                throw new ApiError(HttpStatus.CONFLICT, "UPLOAD_MISSING", "La subida ya no existe en el almacén.");
            }
            throw e;
        }
    }

    private PhotoRow pendingMultipartOf(UUID photoId, long userId) {
        PhotoRow p = ownUpload(photoId, userId);
        if (!p.status().equals("pending") || !p.multipart()) {
            throw new ApiError(HttpStatus.CONFLICT, "NOT_PENDING", "Esta subida ya terminó o no es multipart.");
        }
        return p;
    }

    /** Las subidas a medias son de quien las empezó. A los demás, aunque vean el álbum, un 404. */
    private PhotoRow ownUpload(UUID photoId, long userId) {
        PhotoRow p = Photos.find(jdbc, photoId).orElseThrow(ApiError::notFound);
        if (p.uploaderId() != userId) {
            throw ApiError.notFound();
        }
        return p;
    }

    // ---------- 3. Confirmar ----------

    /**
     * Idempotente: confirmar dos veces da lo mismo. La segunda vez la foto ya no está pending y se devuelve
     * como está. Y si la primera se cortó después de completar el multipart, la segunda encuentra la subida
     * cerrada (NO_SUCH_UPLOAD) pero el objeto entero, y sigue desde ahí.
     */
    public PhotoView complete(UUID photoId, long userId) {
        PhotoRow p = ownUpload(photoId, userId);
        if (!p.status().equals("pending")) {
            return PhotoView.of(p, urls);
        }
        if (p.multipart()) {
            completeParts(p);
        }
        ObjectInfo obj = store.head(p.objectKey()).orElseThrow(() -> new ApiError(HttpStatus.CONFLICT,
                "UPLOAD_MISSING", "El archivo todavía no está en el almacén. Súbelo y vuelve a confirmar."));

        String reason = check(p, obj);
        if (reason != null) {
            reject(p, reason);
            throw new ApiError(UNPROCESSABLE, "UPLOAD_REJECTED", "El archivo no es lo que se declaró.",
                    Map.of("reason", reason), null);
        }
        boolean image = p.image();
        int changed = tx.execute(s -> {
            int n = jdbc.sql("""
                            UPDATE photos
                            SET status = :st, size_bytes = :size, upload_id = NULL, part_size = NULL,
                                part_count = NULL, uploaded_at = now(),
                                ready_at = CASE WHEN :st = 'ready' THEN now() END
                            WHERE id = :id AND status = 'pending'""")
                    .param("st", image ? "uploaded" : "ready")
                    .param("size", obj.size())
                    .param("id", p.id())
                    .update();
            if (n == 1 && image) {
                // En la misma transacción: no hay foto confirmada sin su trabajo de miniatura.
                jdbc.sql("INSERT INTO thumb_jobs (photo_id) VALUES (:id) ON CONFLICT DO NOTHING")
                        .param("id", p.id())
                        .update();
            }
            return n;
        });
        if (changed == 0) {
            log.info("Otra request confirmó {} primero", p.id());
        }
        return PhotoView.of(Photos.find(jdbc, p.id()).orElseThrow(), urls);
    }

    /**
     * Las partes las lista el almacén, no el navegador: si faltan o sobran, no se completa. Todas miden
     * part_size salvo la última, y la suma es el tamaño declarado.
     */
    private void completeParts(PhotoRow p) {
        List<PartInfo> parts;
        try {
            parts = store.listParts(p.objectKey(), p.uploadId());
        } catch (StorageException e) {
            if (e.is("NO_SUCH_UPLOAD") && store.head(p.objectKey()).isPresent()) {
                return;
            }
            if (e.is("NO_SUCH_UPLOAD")) {
                throw new ApiError(HttpStatus.CONFLICT, "UPLOAD_MISSING", "La subida ya no existe en el almacén.");
            }
            throw e;
        }
        long total = 0;
        List<Integer> missing = new ArrayList<>();
        int expected = 1;
        for (PartInfo part : parts) {
            while (expected < part.partNumber()) {
                missing.add(expected++);
            }
            boolean last = part.partNumber() == p.partCount();
            if (part.partNumber() > p.partCount() || (!last && part.size() != p.partSize())) {
                throw new ApiError(UNPROCESSABLE, "BAD_PARTS", "La parte " + part.partNumber()
                        + " no tiene el tamaño acordado.", Map.of("part_number", part.partNumber()), null);
            }
            total += part.size();
            expected++;
        }
        while (expected <= p.partCount()) {
            missing.add(expected++);
        }
        if (!missing.isEmpty()) {
            throw new ApiError(HttpStatus.CONFLICT, "PARTS_MISSING", "Faltan partes por subir.",
                    Map.of("missing", missing.size() > 20 ? missing.subList(0, 20) : missing), null);
        }
        if (total != p.declaredSize()) {
            throw new ApiError(UNPROCESSABLE, "BAD_PARTS", "Las partes no suman el tamaño declarado.",
                    Map.of("declared", p.declaredSize(), "uploaded", total), null);
        }
        store.completeMultipart(p.objectKey(), p.uploadId(), parts);
    }

    /** null si el objeto es lo que se declaró; si no, el motivo. */
    private String check(PhotoRow p, ObjectInfo obj) {
        long max = (p.image() ? props.maxImageBytes() : props.maxVideoBytes()).toBytes();
        if (obj.size() > max) {
            return "too_large";
        }
        if (obj.size() != p.declaredSize()) {
            return "size_mismatch";
        }
        if (obj.contentType() == null || !obj.contentType().equalsIgnoreCase(p.contentType())) {
            return "content_type_mismatch";
        }
        byte[] head = store.readRange(p.objectKey(), 0, MediaTypes.HEAD_BYTES - 1);
        if (!MediaTypes.matches(p.contentType(), head)) {
            return "content_mismatch";
        }
        return null;
    }

    private void reject(PhotoRow p, String reason) {
        // Primero se borra el objeto: si la api muere aquí, la fila sigue pending y la limpieza la encuentra.
        store.delete(p.objectKey());
        jdbc.sql("UPDATE photos SET status = 'rejected', reason = :r WHERE id = :id AND status = 'pending'")
                .param("r", reason)
                .param("id", p.id())
                .update();
        log.warn("Subida {} rechazada: {}", p.id(), reason);
    }

    // ---------- Borrar ----------

    /**
     * Primero la fila y después los objetos: si se cae entre los dos, queda un objeto sin fila (un huérfano que
     * la limpieza borra), nunca una fila que apunta a nada.
     */
    public void delete(UUID photoId, long userId) {
        PhotoRow p = Photos.find(jdbc, photoId).orElseThrow(ApiError::notFound);
        AlbumAccess.Role role = access.require(p.albumId(), userId, AlbumAccess.Role.VIEWER);
        boolean mine = p.uploaderId() == userId && role != AlbumAccess.Role.VIEWER;
        if (!mine && role != AlbumAccess.Role.OWNER) {
            throw new ApiError(HttpStatus.FORBIDDEN, "FORBIDDEN_ROLE", "Solo quien la subió o la dueña la borran.");
        }
        jdbc.sql("DELETE FROM photos WHERE id = :id").param("id", p.id()).update();
        urls.forget(p.objectKey());
        if (p.multipart()) {
            store.abortMultipart(p.objectKey(), p.uploadId());
        }
        store.delete(p.objectKey());
        if (p.thumbKey() != null) {
            urls.forget(p.thumbKey());
            store.delete(p.thumbKey());
        }
    }
}

 * Solo existe con ALBUM_PROXY_UPLOAD=true.

@RestController

    private final ObjectStore store;
    private final Users users;
    private final AlbumProps props;

    public ProxyUploadController(UploadService uploads, ObjectStore store, Users users, AlbumProps props) {
        this.uploads = uploads;
        this.store = store;
        this.users = users;
        this.props = props;
    }

    @PutMapping("/v1/albums/{albumId}/via-api")
    @ResponseStatus(HttpStatus.CREATED)
    PhotoView upload(@AuthenticationPrincipal UserDetails user, @PathVariable UUID albumId,
                     @RequestParam String filename, HttpServletRequest req) throws IOException {
        long size = req.getContentLengthLong();
        if (size <= 0) {
            throw new ApiError(HttpStatus.LENGTH_REQUIRED, "LENGTH_REQUIRED", "Falta Content-Length.");
        }
        if (size > props.singlePutMax().toBytes()) {
            throw new ApiError(HttpStatus.valueOf(422), "TOO_LARGE_FOR_PROXY",
                    "Por la api solo se suben archivos que caben en un PUT simple.");
        }
        long userId = users.idOf(user);
        // El mismo pedido que hace el navegador, para reservar la fila con las mismas reglas.
        UploadService.Ticket t = uploads.begin(albumId, userId,
                new UploadService.UploadRequest(filename, req.getContentType(), size));
        String key = ObjectKeys.original(albumId, t.photoId());
        // Se reenvía en streaming: la api no junta el archivo en memoria, pero sí lo lee y lo vuelve a mandar.
        store.put(key, req.getInputStream(), size, req.getContentType(), null);
        return uploads.complete(t.photoId(), userId);
    }

        PhotoRow p = ownUpload(photoId, userId);
        if (!p.status().equals("pending")) {
            return PhotoView.of(p, urls);
        }
        if (p.multipart()) {
            completeParts(p);
        }
        ObjectInfo obj = store.head(p.objectKey()).orElseThrow(() -> new ApiError(HttpStatus.CONFLICT,
                "UPLOAD_MISSING", "El archivo todavía no está en el almacén. Súbelo y vuelve a confirmar."));

        String reason = check(p, obj);
        if (reason != null) {
            reject(p, reason);
            throw new ApiError(UNPROCESSABLE, "UPLOAD_REJECTED", "El archivo no es lo que se declaró.",
                    Map.of("reason", reason), null);
        }
        boolean image = p.image();
        int changed = tx.execute(s -> {
            int n = jdbc.sql("""
                            UPDATE photos
                            SET status = :st, size_bytes = :size, upload_id = NULL, part_size = NULL,
                                part_count = NULL, uploaded_at = now(),
                                ready_at = CASE WHEN :st = 'ready' THEN now() END
                            WHERE id = :id AND status = 'pending'""")
                    .param("st", image ? "uploaded" : "ready")
                    .param("size", obj.size())
                    .param("id", p.id())
                    .update();
            if (n == 1 && image) {
                // En la misma transacción: no hay foto confirmada sin su trabajo de miniatura.
                jdbc.sql("INSERT INTO thumb_jobs (photo_id) VALUES (:id) ON CONFLICT DO NOTHING")
                        .param("id", p.id())
                        .update();
            }
            return n;
        });
        if (changed == 0) {
            log.info("Otra request confirmó {} primero", p.id());
        }
        return PhotoView.of(Photos.find(jdbc, p.id()).orElseThrow(), urls);
    }
    /** null si el objeto es lo que se declaró; si no, el motivo. */
    private String check(PhotoRow p, ObjectInfo obj) {
        long max = (p.image() ? props.maxImageBytes() : props.maxVideoBytes()).toBytes();
        if (obj.size() > max) {
            return "too_large";
        }
        if (obj.size() != p.declaredSize()) {
            return "size_mismatch";
        }
        if (obj.contentType() == null || !obj.contentType().equalsIgnoreCase(p.contentType())) {
            return "content_type_mismatch";
        }
        byte[] head = store.readRange(p.objectKey(), 0, MediaTypes.HEAD_BYTES - 1);
        if (!MediaTypes.matches(p.contentType(), head)) {
            return "content_mismatch";
        }
        return null;
    }

    private void reject(PhotoRow p, String reason) {
        // Primero se borra el objeto: si la api muere aquí, la fila sigue pending y la limpieza la encuentra.
        store.delete(p.objectKey());
        jdbc.sql("UPDATE photos SET status = 'rejected', reason = :r WHERE id = :id AND status = 'pending'")
                .param("r", reason)
                .param("id", p.id())
                .update();
        log.warn("Subida {} rechazada: {}", p.id(), reason);
    }

Cuatro preguntas, de la más barata a la más cara. Un HEAD responde las tres primeras: ¿pasa del máximo?, ¿mide lo que se declaró?, ¿tiene el Content-Type que se firmó? La cuarta lee 16 bytes con un Range y mira la firma del formato: FF D8 FF para un JPEG, 89 50 4E 47 para un PNG, ftyp en los bytes 4 a 7 para un MP4. Si algo no cuadra, el objeto se borra primero y la fila pasa a rejected después: si la api muere entre las dos, queda una fila pending que la limpieza encuentra.

Confirmar es idempotente, como el POST con Idempotency-Key de A15, pero sin clave: el estado de la fila hace de clave. Si la foto ya no está pending, se devuelve como está. Si dos requests confirman a la vez, las dos hacen las comprobaciones, pero el UPDATE … WHERE status = 'pending' solo lo gana una, y el trabajo de miniatura se inserta en la misma transacción, con ON CONFLICT DO NOTHING: nunca hay dos.

Qué pasa si falla

Los 16 bytes prueban el formato, no que el archivo entero sea válido. Un JPEG con una cabecera correcta y basura después pasa la confirmación; lo atrapa el decodificador en el worker (paso 9) y la foto termina en rejected con not_decodable. Las dos revisiones se complementan: la primera es barata y frena lo obvio en la request, la segunda es cara y va en segundo plano.

La decisión
La verdad la tiene el almacén: tamaño, tipo y primeros bytes se leen de ahí al confirmar. Rechazar borra el objeto. Confirmar dos veces da lo mismo.
Lo que descartas
Un evento del almacén que avise "llegó un objeto", como las notificaciones de S3 o de R2 hacia una cola (M09): quita la llamada a complete, pero agrega una cola y deja a la página sin saber cuándo terminó. Es lo que harías si muchos clientes suben sin una página tuya de por medio.
Qué puede salir mal
Entre el HEAD y la lectura de los 16 bytes, quien tiene la URL de subida, que vale 5 minutos, podría reemplazar el objeto. La URL de subida no se puede revocar, así que lo que el worker decodifica es lo que haya en ese momento. Por eso el worker no confía en nada de lo anterior: readAll vuelve a medir lo que bajó y el decodificador tiene sus propios límites.

Paso 8. Videos de 2 GB en partes que se retoman

Un archivo de más de 16 MiB va en partes de 8 MiB, como en M09. Cada parte es un PUT con su propia URL firmada, las partes viajan en paralelo, y si una falla se reintenta solo esa. Al final, la api le pide al almacén que las junte.

    private PhotoRow pendingMultipartOf(UUID photoId, long userId) {
        PhotoRow p = ownUpload(photoId, userId);
        if (!p.status().equals("pending") || !p.multipart()) {
            throw new ApiError(HttpStatus.CONFLICT, "NOT_PENDING", "Esta subida ya terminó o no es multipart.");
        }
        return p;
    }

    /** Las subidas a medias son de quien las empezó. A los demás, aunque vean el álbum, un 404. */
    private PhotoRow ownUpload(UUID photoId, long userId) {
        PhotoRow p = Photos.find(jdbc, photoId).orElseThrow(ApiError::notFound);
        if (p.uploaderId() != userId) {
            throw ApiError.notFound();
        }
        return p;
    }
    /**
     * Las partes las lista el almacén, no el navegador: si faltan o sobran, no se completa. Todas miden
     * part_size salvo la última, y la suma es el tamaño declarado.
     */
    private void completeParts(PhotoRow p) {
        List<PartInfo> parts;
        try {
            parts = store.listParts(p.objectKey(), p.uploadId());
        } catch (StorageException e) {
            if (e.is("NO_SUCH_UPLOAD") && store.head(p.objectKey()).isPresent()) {
                return;
            }
            if (e.is("NO_SUCH_UPLOAD")) {
                throw new ApiError(HttpStatus.CONFLICT, "UPLOAD_MISSING", "La subida ya no existe en el almacén.");
            }
            throw e;
        }
        long total = 0;
        List<Integer> missing = new ArrayList<>();
        int expected = 1;
        for (PartInfo part : parts) {
            while (expected < part.partNumber()) {
                missing.add(expected++);
            }
            boolean last = part.partNumber() == p.partCount();
            if (part.partNumber() > p.partCount() || (!last && part.size() != p.partSize())) {
                throw new ApiError(UNPROCESSABLE, "BAD_PARTS", "La parte " + part.partNumber()
                        + " no tiene el tamaño acordado.", Map.of("part_number", part.partNumber()), null);
            }
            total += part.size();
            expected++;
        }
        while (expected <= p.partCount()) {
            missing.add(expected++);
        }
        if (!missing.isEmpty()) {
            throw new ApiError(HttpStatus.CONFLICT, "PARTS_MISSING", "Faltan partes por subir.",
                    Map.of("missing", missing.size() > 20 ? missing.subList(0, 20) : missing), null);
        }
        if (total != p.declaredSize()) {
            throw new ApiError(UNPROCESSABLE, "BAD_PARTS", "Las partes no suman el tamaño declarado.",
                    Map.of("declared", p.declaredSize(), "uploaded", total), null);
        }
        store.completeMultipart(p.objectKey(), p.uploadId(), parts);
    }

La regla importante es quién dice qué partes hay. El navegador podría mandar la lista con sus ETag, que es lo que hace S3 con CompleteMultipartUpload, pero entonces la api estaría juntando lo que el cliente dice que subió. Aquí la lista la da el almacén: completeParts pide las partes que llegaron y comprueba tres cosas. Que no falte ninguna (si faltan, 409 PARTS_MISSING con sus números, para que la página suba solo esas), que todas menos la última midan exactamente part_size, y que la suma sea el tamaño declarado.

Las reglas del almacén son las de R2: cada parte menos la última mide al menos 5 MiB y todas miden lo mismo, y hay como máximo 10 000 partes Documentado. Con partes de 8 MiB, el máximo de 2 GiB de un video son 2 048 ÷ 8 = 256 partes; muy lejos del tope. El ETag del objeto final no es el hash del archivo: es el hash de los hashes de las partes con -N al final, como en S3. Si algún día comparas ETags para saber si dos archivos son iguales, uno subido entero y otro en partes no van a coincidir.

Retomar es la razón de ser de las partes. Si el wifi del hotel se cae a los 1.4 GB, la subida sigue existiendo en el almacén con las partes que llegaron. La página guarda en localStorage una huella del archivo (álbum, nombre, tamaño y fecha de modificación) con el id de la subida; cuando eliges el mismo archivo otra vez, pregunta GET /v1/photos/{id}/parts y sube solo las que faltan. Esa misma idea, con un archivo .subida-<nombre> en lugar de localStorage, la usa scripts/grande.sh.

La decisión
Partes de 8 MiB con URLs firmadas por lotes de 20, tres partes en paralelo, cuatro intentos por parte con espera exponencial y una URL nueva desde el segundo intento. Al confirmar, la lista de partes la da el almacén.
Lo que descartas
Partes de 5 MiB, el mínimo: más requests para el mismo archivo. Partes de 100 MiB: reintentar una parte cortada cuesta subir de nuevo 100 MiB. Y firmar todas las URLs al empezar: un video lento usaría URLs de hace media hora, ya vencidas.
Qué puede salir mal
Una parte que se sube dos veces, porque el primer intento sí llegó pero la respuesta se perdió, no es un problema: subir la misma parte otra vez la reemplaza. Lo que sí es un problema es una subida que nadie termina, que ocupa espacio para siempre. Por eso existe la regla de ciclo de vida que la descarta a los 7 días, en R2 y en el almacén local.

Paso 9. Miniaturas en segundo plano, sin morir por una bomba

Una foto de 12 MB no sirve para una grilla: la página necesita miniaturas de 400 px. Hacerlas en la request de complete la haría lenta y metería un decodificador de imágenes ajenas en el proceso que atiende a todos. Las hace el worker, otro proceso con su propio rol y su propio límite de memoria, a partir de la cola thumb_jobs que llenó el paso 7.

package lab.album.thumb;

import java.awt.Color;
import java.awt.Graphics2D;
import java.awt.RenderingHints;
import java.awt.image.BufferedImage;
import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.util.Iterator;

import javax.imageio.IIOImage;
import javax.imageio.ImageIO;
import javax.imageio.ImageReadParam;
import javax.imageio.ImageReader;
import javax.imageio.ImageWriteParam;
import javax.imageio.ImageWriter;
import javax.imageio.stream.ImageInputStream;
import javax.imageio.stream.ImageOutputStream;

/**
 * Hace la miniatura de una imagen que subió otra persona: datos que no controlas. Tres precauciones:
 * 1. Lee la cabecera (ancho y alto) antes de decodificar. Una "bomba" de 15 000 × 15 000 píxeles pesa unos KB
 *    comprimida y cientos de MB en memoria: se rechaza por sus píxeles sin tocar el resto del archivo.
 * 2. Decodifica con submuestreo: para una miniatura de 400 px no hace falta cada píxel del original.
 * 3. Todo error del decodificador es un archivo malo, no un error del worker: se rechaza y no se reintenta.
 * No aplica la orientación EXIF (ignoreMetadata): una foto vertical de un teléfono puede salir acostada.
 */
public class Thumbnailer {

    public record Thumb(byte[] jpeg, int width, int height) {
    }

    /** El archivo no sirve. reason: too_many_pixels o not_decodable. */
    public static class Rejected extends Exception {

        private final String reason;

        public Rejected(String reason, String detail) {
            super(reason + ": " + detail);
            this.reason = reason;
        }

        public String reason() {
            return reason;
        }
    }

    private final long maxPixels;
    private final int box;

    public Thumbnailer(long maxPixels, int box) {
        this.maxPixels = maxPixels;
        this.box = box;
        // Sin archivos temporales en disco: los datos ya están en memoria.
        ImageIO.setUseCache(false);
    }

    public Thumb make(byte[] data) throws Rejected {
        try (ImageInputStream in = ImageIO.createImageInputStream(new ByteArrayInputStream(data))) {
            Iterator<ImageReader> readers = ImageIO.getImageReaders(in);
            if (!readers.hasNext()) {
                throw new Rejected("not_decodable", "ningún lector reconoce el formato");
            }
            ImageReader reader = readers.next();
            try {
                reader.setInput(in, true, true);
                // getWidth y getHeight leen solo la cabecera.
                int w = reader.getWidth(0);
                int h = reader.getHeight(0);
                if (w <= 0 || h <= 0 || (long) w * h > maxPixels) {
                    throw new Rejected("too_many_pixels", w + "x" + h);
                }
                ImageReadParam param = reader.getDefaultReadParam();
                // Lee uno de cada "step" píxeles en cada eje. Queda al menos el doble de la miniatura,
                // para que el escalado final tenga de dónde promediar.
                int step = Math.max(1, Math.max(w, h) / (2 * box));
                param.setSourceSubsampling(step, step, 0, 0);
                BufferedImage src = reader.read(0, param);
                return new Thumb(encode(scale(src, w, h)), w, h);
            } finally {
                reader.dispose();
            }
        } catch (IOException | RuntimeException e) {
            // Un PNG truncado, un JPEG con tablas inválidas, un índice fuera de rango dentro del decodificador.
            throw new Rejected("not_decodable", e.getClass().getSimpleName());
        }
    }

    /** Cabe en un cuadrado de box × box, sin deformar y sin agrandar las imágenes chicas. */
    private BufferedImage scale(BufferedImage src, int w, int h) {
        double ratio = Math.min(1.0, (double) box / Math.max(w, h));
        int tw = Math.max(1, (int) Math.round(w * ratio));
        int th = Math.max(1, (int) Math.round(h * ratio));
        // RGB sin canal alfa: JPEG no tiene transparencia, así que un PNG transparente queda sobre blanco.
        BufferedImage out = new BufferedImage(tw, th, BufferedImage.TYPE_INT_RGB);
        Graphics2D g = out.createGraphics();
        try {
            g.setColor(Color.WHITE);
            g.fillRect(0, 0, tw, th);
            g.setRenderingHint(RenderingHints.KEY_INTERPOLATION, RenderingHints.VALUE_INTERPOLATION_BILINEAR);
            g.drawImage(src, 0, 0, tw, th, null);
        } finally {
            g.dispose();
        }
        return out;
    }

    private static byte[] encode(BufferedImage img) throws IOException {
        ImageWriter writer = ImageIO.getImageWritersByFormatName("jpeg").next();
        ByteArrayOutputStream bytes = new ByteArrayOutputStream();
        try (ImageOutputStream out = ImageIO.createImageOutputStream(bytes)) {
            writer.setOutput(out);
            ImageWriteParam p = writer.getDefaultWriteParam();
            p.setCompressionMode(ImageWriteParam.MODE_EXPLICIT);
            p.setCompressionQuality(0.82f);
            writer.write(null, new IIOImage(img, null, null), p);
        } finally {
            writer.dispose();
        }
        return bytes.toByteArray();
    }
}

Las cuentas de la figura salen de 4 bytes por píxel, lo que ocupa una BufferedImage de tipo TYPE_INT_RGB: 15 000 × 15 000 × 4 = 900 000 000 bytes. Un PNG de ese tamaño, si es de un solo color, se comprime a muy poco: es una bomba de descompresión. La defensa es leer el ancho y el alto de la cabecera, que ImageReader.getWidth obtiene sin decodificar los píxeles, y rechazar si pasan de max-pixels (40 millones). La segunda defensa es el submuestreo: para una miniatura de 400 px, con leer uno de cada step píxeles alcanza. Una foto de 8 000 × 5 000 se lee con step 10 y queda en 800 × 500 × 4 = 1.6 MB.

package lab.album.thumb;

import java.io.ByteArrayInputStream;
import java.util.Optional;
import java.util.UUID;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.context.annotation.Profile;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import org.springframework.transaction.support.TransactionTemplate;

import lab.album.AlbumProps;
import lab.album.CrashPoints;
import lab.album.photo.PhotoRow;
import lab.album.photo.Photos;
import lab.album.storage.ObjectKeys;
import lab.album.storage.ObjectStore;
import lab.album.storage.StorageException;

/**
 * Las miniaturas, en segundo plano. Toma trabajos de thumb_jobs con un lease de 60 s (si muere a la mitad, el
 * trabajo vuelve solo cuando vence) y procesa de a uno. La clave de la miniatura es siempre la misma para cada
 * foto, así que repetir un trabajo reescribe el mismo objeto: no hay miniaturas duplicadas.
 */
@Component
@Profile("worker")
public class ThumbnailWorker {

    private static final Logger log = LoggerFactory.getLogger(ThumbnailWorker.class);
    private static final int MAX_ATTEMPTS = 5;

    record Job(UUID photoId, int attempts) {
    }

    private final JdbcClient jdbc;
    private final TransactionTemplate tx;
    private final ObjectStore store;
    private final Thumbnailer thumbnailer;
    private final AlbumProps props;

    public ThumbnailWorker(JdbcClient jdbc, TransactionTemplate tx, ObjectStore store,
                           AlbumProps props) {
        this.jdbc = jdbc;
        this.tx = tx;
        this.store = store;
        this.props = props;
        this.thumbnailer = new Thumbnailer(props.maxPixels(), props.thumbSize());
    }

    @Scheduled(fixedDelay = 1000)
    void tick() {
        if (props.background()) {
            drain(4);
        }
    }

    /** Procesa hasta max trabajos y devuelve cuántos tomó. Las pruebas lo llaman directo. */
    public int drain(int max) {
        int taken = 0;
        while (taken < max) {
            Optional<Job> job = lease();
            if (job.isEmpty()) {
                break;
            }
            taken++;
            process(job.get());
        }
        return taken;
    }

    /**
     * Toma un trabajo y lo marca hasta dentro de 60 s. SKIP LOCKED: dos workers nunca toman el mismo, y ninguno
     * espera al otro. attempts sube al tomarlo, no al fallar: un trabajo que mata al worker igual se cuenta.
     */
    private Optional<Job> lease() {
        return jdbc.sql("""
                        UPDATE thumb_jobs
                        SET locked_until = now() + interval '60 seconds', attempts = attempts + 1
                        WHERE photo_id = (
                            SELECT photo_id FROM thumb_jobs
                            WHERE run_after <= now() AND (locked_until IS NULL OR locked_until < now())
                            ORDER BY run_after
                            LIMIT 1
                            FOR UPDATE SKIP LOCKED)
                        RETURNING photo_id, attempts""")
                .query(Job.class)
                .optional();
    }

    private void process(Job job) {
        Optional<PhotoRow> found = Photos.find(jdbc, job.photoId());
        if (found.isEmpty() || !found.get().status().equals("uploaded")) {
            // La borraron, o ya la procesó otro: el trabajo sobra.
            deleteJob(job.photoId());
            return;
        }
        PhotoRow p = found.get();
        if (job.attempts() > MAX_ATTEMPTS) {
            // Mató al worker MAX_ATTEMPTS veces (nunca llegó al catch): se da por perdida.
            fail(p, "too_many_attempts");
            return;
        }
        try {
            byte[] original = store.readAll(p.objectKey(), props.maxImageBytes().toBytes());
            Thumbnailer.Thumb t = thumbnailer.make(original);
            String thumbKey = ObjectKeys.thumb(p.albumId(), p.id());
            store.put(thumbKey, new ByteArrayInputStream(t.jpeg()), t.jpeg().length, "image/jpeg", null);
            CrashPoints.haltIfAsked("tras-miniatura");
            tx.executeWithoutResult(s -> {
                jdbc.sql("""
                                UPDATE photos
                                SET status = 'ready', thumb_key = :k, width = :w, height = :h, ready_at = now()
                                WHERE id = :id AND status = 'uploaded'""")
                        .param("k", thumbKey)
                        .param("w", t.width())
                        .param("h", t.height())
                        .param("id", p.id())
                        .update();
                deleteJob(p.id());
            });
            log.info("Miniatura de {}: {}x{}, {} bytes", p.id(), t.width(), t.height(), t.jpeg().length);
        } catch (Thumbnailer.Rejected e) {
            // El archivo es malo: reintentar daría lo mismo. Se rechaza y se borra el original.
            tx.executeWithoutResult(s -> {
                jdbc.sql("UPDATE photos SET status = 'rejected', reason = :r WHERE id = :id AND status = 'uploaded'")
                        .param("r", e.reason())
                        .param("id", p.id())
                        .update();
                deleteJob(p.id());
            });
            store.delete(p.objectKey());
            log.warn("Foto {} rechazada: {}", p.id(), e.getMessage());
        } catch (StorageException e) {
            // El almacén falló: puede ser pasajero. Se reintenta con espera exponencial (2, 4, 8… s, hasta 300).
            if (job.attempts() >= MAX_ATTEMPTS) {
                fail(p, "storage_error");
                return;
            }
            jdbc.sql("""
                            UPDATE thumb_jobs
                            SET run_after = now() + least(power(2, attempts), 300) * interval '1 second',
                                locked_until = NULL, last_error = :err
                            WHERE photo_id = :id""")
                    .param("err", e.code() + ": " + e.getMessage())
                    .param("id", p.id())
                    .update();
            log.warn("Miniatura de {} falló (intento {}): {}", p.id(), job.attempts(), e.code());
        }
    }

    private void fail(PhotoRow p, String reason) {
        tx.executeWithoutResult(s -> {
            jdbc.sql("UPDATE photos SET status = 'failed', reason = :r WHERE id = :id AND status = 'uploaded'")
                    .param("r", reason)
                    .param("id", p.id())
                    .update();
            deleteJob(p.id());
        });
        log.error("Foto {} quedó en failed: {}", p.id(), reason);
    }

    private void deleteJob(UUID photoId) {
        jdbc.sql("DELETE FROM thumb_jobs WHERE photo_id = :id").param("id", photoId).update();
    }
}

El worker toma trabajos como el relay de A09: un UPDATE … WHERE photo_id = (SELECT … FOR UPDATE SKIP LOCKED) que marca el trabajo con un lease de 60 s. Si el worker muere a la mitad, nadie libera el trabajo, pero el lease vence y otro worker lo toma. attempts sube al tomarlo, no al fallar: un archivo que mata al worker cada vez que lo intenta igual se cuenta, y al sexto intento la foto pasa a failed con too_many_attempts sin volver a tocar el archivo.

La miniatura tiene una clave fija por foto (…/thumb.jpg), así que repetir un trabajo reescribe el mismo objeto. Si el worker muere después de subir la miniatura y antes de marcar la foto, el siguiente intento la vuelve a hacer y la sobreescribe: no quedan miniaturas duplicadas. Ese es el punto donde el experimento de caídas detiene el proceso, con CrashPoints.haltIfAsked("tras-miniatura").

En producción real

javax.imageio no aplica la orientación EXIF: una foto vertical de un teléfono, que guarda los píxeles acostados y una etiqueta que dice "gírala", puede salir acostada en la miniatura. Las librerías de imágenes de producción (libvips, ImageMagick, Thumbnailator con un lector de metadatos) la aplican. Y en producción el decodificador corre aislado: en otro proceso, con límites de memoria y de tiempo, y a veces dentro de un sandbox, porque los decodificadores de imágenes tienen un largo historial de vulnerabilidades.

La decisión
Un worker aparte, con lease, reintentos para las fallas pasajeras y rechazo sin reintento para los archivos malos; el tamaño en píxeles se revisa en la cabecera antes de decodificar, y se decodifica con submuestreo.
Lo que descartas
Generar la miniatura en el navegador antes de subir: ahorra trabajo al servidor, pero cualquiera puede subir una "miniatura" que no se parece al original. Y una cola externa como Redis Streams: la tabla thumb_jobs se escribe en la misma transacción que la foto, así que nunca hay foto sin trabajo.
Qué puede salir mal
Un formato que el decodificador lee entero aunque pidas submuestreo, o una imagen de pocos píxeles pero con miles de capas o fotogramas: el control de píxeles no lo ve. Por eso el límite de memoria del contenedor es la última defensa, y el contador de intentos impide que un archivo mate al worker para siempre.

Paso 10. Ver y descargar con URLs de vida corta

Leer es la otra mitad de la idea: la api no sirve los bytes, entrega URLs firmadas para leerlos. Pero hay dos maneras de leer, con necesidades opuestas.

package lab.album.photo;

import java.net.URI;
import java.time.Clock;
import java.time.Duration;
import java.time.Instant;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

import org.springframework.context.annotation.Profile;
import org.springframework.stereotype.Component;

import lab.album.AlbumProps;
import lab.album.storage.ObjectStore;

/**
 * Las URLs para ver miniaturas y videos. Una URL nueva en cada listado sería una URL distinta cada vez, y el
 * navegador no reusaría nada de su caché: bajaría las mismas miniaturas en cada recarga. Por eso la api guarda
 * la URL de cada clave y la reutiliza mientras le quede al menos un tercio de vida (5 de 15 minutos).
 * El objeto se sirve con "Cache-Control: private, max-age=900", firmado dentro de la URL.
 */
@Component
@Profile("api")
public class PhotoUrls {

    public record Signed(URI url, Instant expiresAt) {
    }

    /** Un tope de memoria tosco: pasado este número de claves, la caché se vacía entera. */
    private static final int MAX_ENTRIES = 50_000;

    private final ObjectStore store;
    private final Duration ttl;
    private final Clock clock;
    private final Map<String, Signed> cache = new ConcurrentHashMap<>();

    public PhotoUrls(ObjectStore store, AlbumProps props, Clock clock) {
        this.store = store;
        this.ttl = props.readTtl();
        this.clock = clock;
    }

    public Signed view(String key) {
        Instant now = clock.instant();
        Signed s = cache.get(key);
        if (s != null && Duration.between(now, s.expiresAt()).compareTo(ttl.dividedBy(3)) > 0) {
            return s;
        }
        if (cache.size() > MAX_ENTRIES) {
            cache.clear();
        }
        Signed fresh = new Signed(store.presignGet(key, ttl, null, "private, max-age=" + ttl.toSeconds()),
                now.plus(ttl));
        cache.put(key, fresh);
        return fresh;
    }

    /** Al borrar una foto: que nadie siga recibiendo su URL desde la caché. */
    public void forget(String key) {
        cache.remove(key);
    }
}

Las miniaturas tienen un problema que las descargas no: se cargan en cada listado. Si la api firmara una URL nueva en cada request, el exp cambiaría y con él la URL, y para el navegador una URL distinta es otro recurso: bajaría las mismas miniaturas cada vez. PhotoUrls guarda la URL de cada clave y la reutiliza mientras le quede más de un tercio de vida (5 de 15 minutos). Durante 10 minutos todos los listados devuelven la misma URL, y el navegador la sirve desde su caché. Como la URL es la misma para cualquier persona que puede ver el álbum, la prueba UploadFlowTest comprueba que ana y beto reciben la misma.

package lab.album.photo;

import java.net.URI;

import org.springframework.context.annotation.Profile;

import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.security.core.annotation.AuthenticationPrincipal;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RestController;

import lab.album.AlbumProps;
import lab.album.album.AlbumAccess;
import lab.album.album.Users;
import lab.album.storage.ObjectStore;
import lab.album.web.ApiError;

@RestController
@Profile("api")
public class PhotoController {

    private final JdbcClient jdbc;
    private final Users users;
    private final AlbumAccess access;
    private final PhotoUrls urls;
    private final ObjectStore store;
    private final UploadService uploads;
    private final AlbumProps props;

    public PhotoController(JdbcClient jdbc, Users users, AlbumAccess access, PhotoUrls urls, ObjectStore store,
                           UploadService uploads, AlbumProps props) {
        this.jdbc = jdbc;
        this.users = users;
        this.access = access;
        this.urls = urls;
        this.store = store;
        this.uploads = uploads;
        this.props = props;
    }

    /**
     * Las fotos de un álbum con sus URLs firmadas. El listado no se cachea (no-cache: siempre se pregunta);
     * lo que se cachea son las miniaturas, porque sus URLs se repiten de un listado al siguiente (PhotoUrls).
     */
    @GetMapping("/v1/albums/{albumId}/photos")
    ResponseEntity<List<PhotoView>> list(@AuthenticationPrincipal UserDetails user, @PathVariable UUID albumId) {
        access.require(albumId, users.idOf(user), AlbumAccess.Role.VIEWER);
        List<PhotoView> photos = Photos.inAlbum(jdbc, albumId, 200).stream()
                .map(p -> PhotoView.of(p, urls))
                .toList();
        return ResponseEntity.ok().cacheControl(CacheControl.noCache().cachePrivate()).body(photos);
    }

    @GetMapping("/v1/photos/{id}")
    PhotoView get(@AuthenticationPrincipal UserDetails user, @PathVariable UUID id) {
        return PhotoView.of(visible(id, users.idOf(user)), urls);
    }

    /**
     * La descarga: un 302 a una URL que vale un minuto y le pide al almacén "Content-Disposition: attachment"
     * con el nombre original. El navegador guarda el archivo en lugar de mostrarlo.
     */
    @GetMapping("/v1/photos/{id}/download")
    ResponseEntity<Void> download(@AuthenticationPrincipal UserDetails user, @PathVariable UUID id) {
        PhotoRow p = visible(id, users.idOf(user));
        if (!p.status().equals("ready")) {
            throw new ApiError(HttpStatus.CONFLICT, "NOT_READY", "La foto todavía no está lista.");
        }
        String disposition = ContentDisposition.attachment()
                .filename(p.originalName(), StandardCharsets.UTF_8)
                .build()
                .toString();
        URI url = store.presignGet(p.objectKey(), props.downloadTtl(), disposition, "private, no-store");
        return ResponseEntity.status(HttpStatus.FOUND)
                .location(url)
                .cacheControl(CacheControl.noStore())
                .build();
    }

    @DeleteMapping("/v1/photos/{id}")
    ResponseEntity<Void> delete(@AuthenticationPrincipal UserDetails user, @PathVariable UUID id) {
        uploads.delete(id, users.idOf(user));
        return ResponseEntity.noContent().build();
    }

    /** Una foto se ve si soy miembro de su álbum. Las pendientes, solo quien las sube. */
    private PhotoRow visible(UUID id, long userId) {
        PhotoRow p = Photos.find(jdbc, id).orElseThrow(ApiError::notFound);
        access.require(p.albumId(), userId, AlbumAccess.Role.VIEWER);
        if (p.status().equals("pending") && p.uploaderId() != userId) {
            throw ApiError.notFound();
        }
        return p;
    }
}

La descarga va por la api a propósito. El enlace "Descargar" de la página es /v1/photos/{id}/download, que se puede compartir y marcar como favorito sin que deje de funcionar: cada vez que se abre, la api revisa que seas miembro del álbum y firma una URL nueva. Los dos parámetros de respuesta, rcd y rcc en el almacén local, response-content-disposition y response-cache-control en R2, van firmados: nadie puede cambiar attachment por inline para que el navegador muestre un archivo que se pidió descargar.

Trade-off

Una URL de 15 minutos que se filtra sirve 15 minutos, aunque se borre a la persona del álbum: la firma no se puede revocar. Si eso no alcanza, las alternativas de M09 son una CDN que valida una cookie firmada o un token en cada request, o servir a través de un proxy que consulta permisos. Las dos cuestan una consulta por lectura. Para un álbum entre amigas, 15 minutos es un riesgo aceptable; para historias clínicas, no.

La decisión
Ver con URLs de 15 minutos reutilizadas mientras les quede un tercio de vida, servidas con private, max-age=900; descargar con un 302 a una URL de 60 s con attachment.
Lo que descartas
Un almacén público con claves imposibles de adivinar: una URL filtrada sirve para siempre. Y firmar URLs de un día para que el navegador cachee más: es más tiempo con una URL robada.
Qué puede salir mal
La caché de PhotoUrls vive en la memoria de cada réplica: con tres réplicas de la api, cada una tiene sus propias URLs y el navegador puede recibir tres URLs distintas para la misma miniatura. Funciona igual, solo cachea peor. La solución, si importa, es redondear exp hacia arriba a un múltiplo de 5 minutos: todas las réplicas firman la misma URL sin hablar entre ellas.

// Los bytes nunca pasan por la api. Los nombres de archivo se muestran con textContent, nunca con innerHTML.
const Album = (() => {
  const $ = (s) => document.querySelector(s);
  const PARALELAS = 3;   // partes subiendo a la vez
  const LOTE = 20;       // URLs de partes por pedido a la api
  const INTENTOS = 4;    // por parte
  let yo = null;
  let album = null;
  let rol = null;

  async function me() {
    if (!yo) {
      const r = await fetch('/v1/me', { headers: { Accept: 'application/json' } });
      yo = await r.json();
    }
    return yo;
  }

  // Las llamadas a la api (mismo origen, con la cookie de sesión y el token CSRF).
  async function api(method, path, body) {
    const m = await me();
    const headers = { Accept: 'application/json' };
    if (body !== undefined) headers['Content-Type'] = 'application/json';
    if (method !== 'GET') headers[m.csrf_header] = m.csrf_token;
    const r = await fetch(path, { method, headers, body: body === undefined ? undefined : JSON.stringify(body) });
    const data = r.status === 204 ? null : await r.json().catch(() => null);
    if (!r.ok) {
      throw Object.assign(new Error(data?.error?.message || 'HTTP ' + r.status),
        { status: r.status, code: data?.error?.code, details: data?.error?.details });
    }
    return data;
  }

  // El PUT al almacén va con XMLHttpRequest y no con fetch: fetch no informa el progreso de una subida.
  // Es otro origen: el navegador manda antes un OPTIONS (preflight) y el almacén responde con CORS.
  function putArchivo(url, blob, contentType, onProgress) {
    return new Promise((resolve, reject) => {
      const xhr = new XMLHttpRequest();
      xhr.open('PUT', url);
      if (contentType) xhr.setRequestHeader('Content-Type', contentType);
      xhr.upload.onprogress = (e) => onProgress?.(e.loaded);
      xhr.onload = () => (xhr.status >= 200 && xhr.status < 300)
        ? resolve()
        : reject(Object.assign(new Error('El almacén respondió ' + xhr.status), { status: xhr.status }));
      // Sin CORS, un error del almacén también llega aquí: el navegador no deja leer la respuesta.
      xhr.onerror = () => reject(Object.assign(new Error('Error de red o de CORS'), { status: 0 }));
      xhr.send(blob);
    });
  }

  const pausa = (ms) => new Promise((r) => setTimeout(r, ms));

  // Para retomar: el mismo archivo (nombre, tamaño y fecha) en el mismo álbum es la misma subida.
  // localStorage puede no existir (modo privado estricto): entonces no se retoma, se empieza de nuevo.
  const huella = (f) => 'subida:' + album + '|' + f.name + '|' + f.size + '|' + f.lastModified;
  function recordar(f, plan) { try { localStorage.setItem(huella(f), JSON.stringify(plan)); } catch { /* sin localStorage */ } }
  function olvidar(f) { try { localStorage.removeItem(huella(f)); } catch { /* sin localStorage */ } }
  function recordada(f) {
    try { return JSON.parse(localStorage.getItem(huella(f))); } catch { return null; }
  }

  function filaDeCola(nombre) {
    const li = document.createElement('li');
    const n = document.createElement('span');
    const estado = document.createElement('span');
    const barra = document.createElement('progress');
    n.textContent = nombre;
    estado.setAttribute('role', 'status');
    barra.max = 1;
    barra.value = 0;
    li.append(n, estado, barra);
    $('#cola').prepend(li);
    return { estado, barra };
  }

  function mensaje(e) {
    switch (e.code) {
      case 'UNSUPPORTED_TYPE': return 'Tipo no permitido (JPEG, PNG o MP4).';
      case 'FILE_TOO_LARGE': return 'Pasa del máximo (' + Math.round(e.details.max_bytes / 1048576) + ' MiB).';
      case 'TOO_MANY_PENDING': return 'Demasiadas subidas sin terminar.';
      case 'FORBIDDEN_ROLE': return 'Tu rol en este álbum no permite subir.';
      case 'UPLOAD_REJECTED': return 'Rechazado: ' + e.details.reason;
      case 'STORAGE_UNAVAILABLE': return 'El almacén no responde; vuelve a intentar.';
      default: return e.status === 0 ? 'Se cortó la red. Elige el mismo archivo para retomar.' : e.message;
    }
  }

  async function subir(f) {
    const fila = filaDeCola(f.name);
    const avance = (bytes) => { fila.barra.value = bytes / f.size; };
    try {
      let plan = recordada(f);
      let hechas = new Set();
      if (plan) {
        try {
          const partes = await api('GET', '/v1/photos/' + plan.id + '/parts');
          hechas = new Set(partes.map((p) => p.part_number));
          fila.estado.textContent = 'Retomando: ' + hechas.size + ' de ' + plan.part_count + ' partes ya estaban.';
        } catch {
          olvidar(f);      // La subida ya no existe (terminó, se borró o venció): se empieza de nuevo.
          plan = null;
        }
      }
      let foto;
      if (!plan) {
        fila.estado.textContent = 'Pidiendo permiso…';
        const t = await api('POST', '/v1/albums/' + album + '/uploads',
          { filename: f.name, content_type: f.type, size: f.size });
        if (t.strategy === 'single') {
          fila.estado.textContent = 'Subiendo…';
          await putArchivo(t.url, f, t.headers['Content-Type'], avance);
          foto = await api('POST', '/v1/photos/' + t.photo_id + '/complete');
        } else {
          plan = { id: t.photo_id, part_size: t.part_size, part_count: t.part_count };
          recordar(f, plan);
        }
      }
      if (plan) {
        fila.estado.textContent = 'Subiendo en ' + plan.part_count + ' partes…';
        await subirPartes(f, plan, hechas, avance);
        foto = await api('POST', '/v1/photos/' + plan.id + '/complete');
        olvidar(f);
      }
      fila.barra.value = 1;
      await esperarLista(foto, fila);
      cargarFotos();
    } catch (e) {
      fila.estado.textContent = mensaje(e);
    }
  }

  async function subirPartes(f, plan, hechas, avance) {
    const tamaño = (n) => Math.min(plan.part_size, f.size - (n - 1) * plan.part_size);
    const pendientes = [];
    for (let n = 1; n <= plan.part_count; n++) if (!hechas.has(n)) pendientes.push(n);
    const yaSubido = [...hechas].reduce((s, n) => s + tamaño(n), 0);
    const enVuelo = new Map();
    const informar = () => avance(yaSubido + [...enVuelo.values()].reduce((a, b) => a + b, 0));
    const urls = new Map();

    // Las URLs se piden por lotes, justo antes de usarlas: una URL de hace una hora pudo haber vencido.
    async function urlDe(n, renovar) {
      if (renovar || !urls.has(n)) {
        const lote = pendientes.filter((p) => p >= n).slice(0, LOTE);
        const r = await api('POST', '/v1/photos/' + plan.id + '/parts', { part_numbers: lote });
        r.parts.forEach((p) => urls.set(p.part_number, p.url));
      }
      return urls.get(n);
    }

    async function una(n) {
      const desde = (n - 1) * plan.part_size;
      const trozo = f.slice(desde, desde + tamaño(n));
      for (let intento = 1; ; intento++) {
        try {
          // A partir del segundo intento, URL nueva: el fallo pudo ser un 403 por vencimiento.
          await putArchivo(await urlDe(n, intento > 1), trozo, null, (b) => { enVuelo.set(n, b); informar(); });
          enVuelo.set(n, trozo.size);
          informar();
          return;
        } catch (e) {
          enVuelo.set(n, 0);
          if (intento >= INTENTOS) throw e;
          await pausa(500 * 2 ** intento + Math.random() * 250);
        }
      }
    }

    const cola = [...pendientes];
    const trabajador = async () => { while (cola.length) await una(cola.shift()); };
    await Promise.all(Array.from({ length: Math.min(PARALELAS, cola.length) }, trabajador));
  }

  // La miniatura se hace en segundo plano: se pregunta cada segundo, hasta 30 veces.
  async function esperarLista(foto, fila) {
    for (let i = 0; foto.status === 'uploaded' && i < 30; i++) {
      fila.estado.textContent = 'Haciendo la miniatura…';
      await pausa(1000);
      foto = await api('GET', '/v1/photos/' + foto.id);
    }
    fila.estado.textContent = foto.status === 'ready' ? 'Lista.'
      : foto.status === 'uploaded' ? 'Sigue en proceso; aparecerá sola.'
      : 'No se pudo procesar: ' + foto.reason;
  }

  let reintentoUrls = false;
  async function cargarFotos() {
    const fotos = await api('GET', '/v1/albums/' + album + '/photos');
    const ul = $('#fotos');
    ul.replaceChildren();
    $('#vacio').hidden = fotos.length > 0;
    reintentoUrls = false;
    for (const f of fotos) {
      const li = document.createElement('li');
      if (f.thumb_url) {
        const img = document.createElement('img');
        img.alt = f.original_name;
        img.loading = 'lazy';
        img.src = f.thumb_url;
        // Si la URL venció (la página quedó abierta mucho tiempo), se pide el listado otra vez, una sola vez.
        img.onerror = () => { if (!reintentoUrls) { reintentoUrls = true; cargarFotos(); } };
        li.append(img);
      } else if (f.media_url) {
        const v = document.createElement('video');
        v.controls = true;
        v.preload = 'none';
        v.src = f.media_url;
        li.append(v);
      }
      const pie = document.createElement('div');
      pie.className = 'pie';
      const nombre = document.createElement('span');
      nombre.className = 'nombre';
      nombre.textContent = f.original_name;
      pie.append(nombre);
      if (f.download_path) {
        const a = document.createElement('a');
        a.href = f.download_path;
        a.textContent = 'Descargar';
        pie.append(a);
      } else {
        const s = document.createElement('span');
        s.textContent = f.status === 'failed' ? 'Falló: ' + f.reason : 'Procesando…';
        pie.append(s);
      }
      if (rol !== 'viewer') {
        const b = document.createElement('button');
        b.type = 'button';
        b.textContent = 'Borrar';
        b.onclick = async () => {
          try { await api('DELETE', '/v1/photos/' + f.id); cargarFotos(); } catch (e) { b.textContent = mensaje(e); }
        };
        pie.append(b);
      }
      li.append(pie);
      ul.append(li);
    }
  }

  async function iniciar() {
    const m = await me();
    $('#who').textContent = 'Sesión: ' + m.username + ' · almacén: ' + m.storage;
    const albums = await api('GET', '/v1/albums');
    const sel = $('#album');
    for (const a of albums) {
      const o = document.createElement('option');
      o.value = a.id;
      o.textContent = a.title + ' (' + a.role + ')';
      sel.append(o);
    }
    const elegir = () => {
      const a = albums.find((x) => x.id === sel.value);
      album = a.id;
      rol = a.role;
      $('#archivos').disabled = rol === 'viewer';
      cargarFotos();
    };
    sel.onchange = elegir;
    if (albums.length) elegir();
    $('#archivos').onchange = (e) => {
      for (const f of e.target.files) subir(f);
      e.target.value = '';
    };
  }

  return { iniciar };
})();

Tres detalles que vienen de los pasos anteriores:

  • XHR, no fetch, para subir. fetch no informa el progreso de una subida; XMLHttpRequest sí, con upload.onprogress. Un error de red y una respuesta que CORS no deja leer llegan al mismo lugar, onerror con status 0: la página no puede distinguir "se cortó el wifi" de "el almacén no tiene CORS".
  • Nombres con textContent. El nombre del archivo lo eligió una persona, y puede ser <img src=x onerror=…>.jpg. La página nunca lo mete con innerHTML; y aunque lo hiciera, la CSP del paso 1 no deja correr scripts en línea.
  • Una URL vencida se renueva una vez. Si dejas la página abierta más de 15 minutos, las URLs de las miniaturas vencen. El onerror de la primera imagen que falla pide el listado otra vez; si vuelve a fallar, no insiste.
La decisión
Una página sin dependencias que sube con XHR, tres partes a la vez, retoma con una huella en localStorage y muestra todo lo ajeno con textContent.
Lo que descartas
Una librería de subidas como Uppy, que hace todo esto y más (y es lo que usarías en un producto). Escrita a mano, cada línea es una decisión de los pasos anteriores que puedes ver.
Qué puede salir mal
En una pestaña privada estricta, localStorage puede no existir; la página lo usa dentro de try/catch y, sin él, no retoma: empieza de nuevo. La subida vieja queda pending hasta que la limpieza la borre.

/**
 * Cloudflare R2 con el cliente S3 del AWS SDK: la misma API de S3, con el endpoint de tu cuenta y la región "auto".
 * Las URLs prefirmadas salen de S3Presigner, que firma con SigV4 sin hacer red.
 */
public class R2ObjectStore implements ObjectStore {

    private final S3Client s3;
    private final S3Presigner presigner;
    private final String bucket;
    private final String endpoint;

    public R2ObjectStore(String accountId, String bucket, String accessKeyId, String secretAccessKey) {
        this.bucket = bucket;
        this.endpoint = "https://" + accountId + ".r2.cloudflarestorage.com";
        var credentials = StaticCredentialsProvider.create(AwsBasicCredentials.create(accessKeyId, secretAccessKey));
        // Path-style (endpoint/bucket/clave) en lugar de bucket.endpoint/clave: un solo origen para la CSP y el CORS.
        this.s3 = S3Client.builder()
                .endpointOverride(URI.create(endpoint))
                .region(Region.of("auto"))
                .credentialsProvider(credentials)
                .serviceConfiguration(S3Configuration.builder()
                        .pathStyleAccessEnabled(true)
                        // R2 rechaza con 403 el envío por partes con firma (aws-chunked) que el SDK usa en putObject.
                        .chunkedEncodingEnabled(false)
                        .build())
                // Los SDK recientes agregan checksums CRC por defecto. Solo cuando la operación los exige:
                // menos headers que R2 pueda no aceptar.
                .requestChecksumCalculation(RequestChecksumCalculation.WHEN_REQUIRED)
                .responseChecksumValidation(ResponseChecksumValidation.WHEN_REQUIRED)
                .overrideConfiguration(c -> c
                        .apiCallAttemptTimeout(Duration.ofSeconds(30))
                        .apiCallTimeout(Duration.ofMinutes(2)))
                .build();
        this.presigner = S3Presigner.builder()
                .endpointOverride(URI.create(endpoint))
                .region(Region.of("auto"))
                .credentialsProvider(credentials)
                .serviceConfiguration(S3Configuration.builder().pathStyleAccessEnabled(true).build())
                .build();
    }

    @Override
    public String name() {
        return "r2";
    }

    @Override
    public String browserOrigin() {
        return endpoint;
    }

    @Override
    public URI presignPut(String key, String contentType, long maxBytes, Duration ttl) {
        // maxBytes no se puede imponer: R2 no acepta las políticas de POST (content-length-range) de S3.
        var put = PutObjectRequest.builder().bucket(bucket).key(key).contentType(contentType).build();
        return uri(presigner.presignPutObject(PutObjectPresignRequest.builder()
                .signatureDuration(ttl).putObjectRequest(put).build()).url());
    }

    @Override
    public URI presignGet(String key, Duration ttl, String contentDisposition, String cacheControl) {
        var get = GetObjectRequest.builder().bucket(bucket).key(key)
                .responseContentDisposition(contentDisposition)
                .responseCacheControl(cacheControl)
                .build();
        return uri(presigner.presignGetObject(GetObjectPresignRequest.builder()
                .signatureDuration(ttl).getObjectRequest(get).build()).url());
    }

    @Override
    public String createMultipart(String key, String contentType) {
        return call(() -> s3.createMultipartUpload(b -> b.bucket(bucket).key(key).contentType(contentType)).uploadId());
    }

    @Override
    public URI presignPart(String key, String uploadId, int partNumber, long maxBytes, Duration ttl) {
        var part = UploadPartRequest.builder().bucket(bucket).key(key).uploadId(uploadId).partNumber(partNumber).build();
        return uri(presigner.presignUploadPart(UploadPartPresignRequest.builder()
                .signatureDuration(ttl).uploadPartRequest(part).build()).url());
    }

    @Override
    public List<PartInfo> listParts(String key, String uploadId) {
        return call(() -> s3.listPartsPaginator(b -> b.bucket(bucket).key(key).uploadId(uploadId)).parts().stream()
                .map(p -> new PartInfo(p.partNumber(), p.eTag(), p.size()))
                .toList());
    }

    @Override
    public void completeMultipart(String key, String uploadId, List<PartInfo> parts) {
        List<CompletedPart> done = parts.stream()
                .map(p -> CompletedPart.builder().partNumber(p.partNumber()).eTag(p.etag()).build())
                .toList();
        call(() -> s3.completeMultipartUpload(b -> b.bucket(bucket).key(key).uploadId(uploadId)
                .multipartUpload(m -> m.parts(done))));
    }

    @Override
    public void abortMultipart(String key, String uploadId) {
        try {
            call(() -> s3.abortMultipartUpload(b -> b.bucket(bucket).key(key).uploadId(uploadId)));
        } catch (StorageException e) {
            if (!e.is("NO_SUCH_UPLOAD")) {
                throw e;
            }
        }
    }

    @Override
    public Optional<ObjectInfo> head(String key) {
        try {
            HeadObjectResponse h = call(() -> s3.headObject(b -> b.bucket(bucket).key(key)));
            return Optional.of(new ObjectInfo(key, h.contentLength(), h.contentType(), h.eTag(), h.lastModified()));
        } catch (StorageException e) {
            if (e.is("NOT_FOUND")) {
                return Optional.empty();
            }
            throw e;
        }
    }

    @Override
    public byte[] readRange(String key, long first, long last) {
        return call(() -> s3.getObjectAsBytes(b -> b.bucket(bucket).key(key).range("bytes=" + first + "-" + last))
                .asByteArray());
    }

    @Override
    public byte[] readAll(String key, long maxBytes) {
        return call(() -> {
            try (ResponseInputStream<GetObjectResponse> in = s3.getObject(b -> b.bucket(bucket).key(key))) {
                if (in.response().contentLength() > maxBytes) {
                    throw new StorageException("TOO_LARGE", key + " pesa " + in.response().contentLength() + " bytes");
                }
                return in.readNBytes((int) Math.min(maxBytes, Integer.MAX_VALUE - 8));
            } catch (IOException e) {
                throw new StorageException("UNAVAILABLE", "Se cortó la lectura de " + key, e);
            }
        });
    }

    @Override
    public void put(String key, InputStream data, long length, String contentType, String cacheControl) {
        call(() -> s3.putObject(b -> b.bucket(bucket).key(key).contentType(contentType).cacheControl(cacheControl),
                RequestBody.fromInputStream(data, length)));
    }

    @Override
    public void delete(String key) {
        call(() -> s3.deleteObject(b -> b.bucket(bucket).key(key)));
    }

    @Override
    public List<ObjectInfo> list(String prefix) {
        return call(() -> s3.listObjectsV2Paginator(b -> b.bucket(bucket).prefix(prefix)).contents().stream()
                .map(o -> new ObjectInfo(o.key(), o.size(), null, o.eTag(), o.lastModified()))
                .toList());
    }

    /** Traduce las excepciones del SDK a los códigos de StorageException, los mismos del disco local. */
    private static <T> T call(java.util.function.Supplier<T> op) {
        try {
            return op.get();
        } catch (NoSuchKeyException e) {
            throw new StorageException("NOT_FOUND", e.getMessage(), e);
        } catch (NoSuchUploadException e) {
            throw new StorageException("NO_SUCH_UPLOAD", e.getMessage(), e);
        } catch (S3Exception e) {
            String code = e.awsErrorDetails() == null ? "" : e.awsErrorDetails().errorCode();
            if (e.statusCode() == 404) {
                throw new StorageException("NoSuchUpload".equals(code) ? "NO_SUCH_UPLOAD" : "NOT_FOUND", e.getMessage(), e);
            }
            if ("InvalidPart".equals(code) || "InvalidPartOrder".equals(code) || "EntityTooSmall".equals(code)) {
                throw new StorageException("INVALID_PART", e.getMessage(), e);
            }
            throw new StorageException(e.statusCode() >= 500 ? "UNAVAILABLE" : "FORBIDDEN", e.getMessage(), e);
        } catch (SdkClientException e) {
            throw new StorageException("UNAVAILABLE", "R2 no responde: " + e.getMessage(), e);
        }
    }

    private static URI uri(java.net.URL url) {
        try {
            return url.toURI();
        } catch (URISyntaxException e) {
            throw new IllegalStateException(e);
        }
    }
}

Cuatro ajustes del cliente tienen su razón. pathStyleAccessEnabled(true) arma las URLs como https://<cuenta>.r2.cloudflarestorage.com/a11-album/clave en lugar de https://a11-album.<cuenta>…/clave: un solo origen para la CSP y el CORS. chunkedEncodingEnabled(false) evita el envío por partes firmadas que el SDK usa en putObject. Los checksums WHEN_REQUIRED evitan headers que el SDK agrega por defecto desde 2025 y que no todos los almacenes compatibles con S3 aceptan. Y el Content-Type va en el PutObjectRequest que se firma: SigV4 lo incluye en los headers firmados, así que el navegador tiene que mandar exactamente ese, como con ct en el almacén local.

Hay dos diferencias con el almacén local. R2 no puede limitar el tamaño de un PUT firmado (no acepta las políticas de POST de S3 con content-length-range), así que quien tiene una URL para 3 MB puede subir 3 GB; lo frena la confirmación del paso 7, que lo rechaza con size_mismatch y lo borra. Y las URLs firmadas solo funcionan con el endpoint de S3 de R2, no con un dominio propio conectado al bucket Documentado.

La decisión
R2 con el SDK oficial de AWS y SigV4, path-style, un token limitado a un bucket con lectura y escritura de objetos, y las claves solo en .env.
Lo que descartas
Un token de cuenta con permiso de administrador: si se filtra, pierdes todos los buckets, no uno. Y S3, que funciona igual con el mismo código cambiando el endpoint y la región, pero cobra la salida de datos, que en un álbum de fotos es casi todo el tráfico.
Qué puede salir mal
Con el CORS mal puesto, curl sube sin problema y el navegador no: el preflight falla y la página ve un error de red. Si el reloj de tu máquina se desfasa varios minutos, R2 rechaza las firmas con un 403 aunque la clave sea buena. Y si te olvidas el bucket con archivos, al pasar de 10 GB empieza a costar.

Paso 13. Lo que deja cada falla, y quién lo limpia

Cada "primero esto y después aquello" de los pasos anteriores se eligió para que, si algo se cae en el medio, quede un tipo de basura conocido. Este paso la barre.

package lab.album.jobs;

import java.time.Clock;

import org.springframework.context.annotation.Profile;

import lab.album.photo.PhotoRow;
import lab.album.storage.ObjectInfo;
import lab.album.storage.ObjectKeys;
import lab.album.storage.ObjectStore;

/**
 * La limpieza. Cada regla de "primero esto y después aquello" del resto del código deja, si algo se cae en el
 * medio, un tipo de basura conocido. Este proceso barre los tres:
 * 1. subidas pendientes de más de 24 h (la URL venció hace mucho: nadie las va a terminar);
 * 2. fotos rechazadas de más de 7 días (se guardan un tiempo para que el usuario vea el motivo);
 * 3. objetos sin fila de más de 24 h (huérfanos de un borrado o un rechazo que se cortó a la mitad).
 * Corre a mano o desde un cron: docker compose run --rm jobs
 */
@Component
@Profile("jobs")
@Order(10)
public class Janitor implements CommandLineRunner {

    private static final Logger log = LoggerFactory.getLogger(Janitor.class);
    static final Duration PENDING_MAX_AGE = Duration.ofHours(24);
    static final Duration REJECTED_MAX_AGE = Duration.ofDays(7);
    /** Un objeto recién escrito puede no tener fila todavía por un instante: se le da un día de gracia. */
    static final Duration ORPHAN_GRACE = Duration.ofHours(24);
    private static final int BATCH = 1000;

    public record Report(int pending, int rejected, int orphans) {
    }

    private final JdbcClient jdbc;
    private final ObjectStore store;
    private final Clock clock;

    public Janitor(JdbcClient jdbc, ObjectStore store, Clock clock) {
        this.jdbc = jdbc;
        this.store = store;
        this.clock = clock;
    }

    @Override
    public void run(String... args) {
        Report r = sweep();
        log.info("Limpieza: {} pendientes, {} rechazadas, {} huérfanos", r.pending(), r.rejected(), r.orphans());
    }

    public Report sweep() {
        return new Report(sweepPending(), sweepRejected(), sweepOrphans());
    }

    /** Primero la fila y después el almacén, como al borrar: si se corta, queda un huérfano que barre el paso 3. */
    private int sweepPending() {
        int n = 0;
        for (PhotoRow p : old("pending", PENDING_MAX_AGE)) {
            int deleted = jdbc.sql("DELETE FROM photos WHERE id = :id AND status = 'pending'")
                    .param("id", p.id())
                    .update();
            if (deleted == 0) {
                continue; // Alguien la confirmó justo ahora.
            }
            if (p.multipart()) {
                store.abortMultipart(p.objectKey(), p.uploadId());
            }
            store.delete(p.objectKey());
            n++;
        }
        return n;
    }

    private int sweepRejected() {
        int n = 0;
        for (PhotoRow p : old("rejected", REJECTED_MAX_AGE)) {
            jdbc.sql("DELETE FROM photos WHERE id = :id AND status = 'rejected'").param("id", p.id()).update();
            // El rechazo ya borró el objeto; borrarlo otra vez no falla y cubre un rechazo que se cortó.
            store.delete(p.objectKey());
            n++;
        }
        return n;
    }

    private int sweepOrphans() {
        Instant cutoff = clock.instant().minus(ORPHAN_GRACE);
        List<ObjectInfo> candidates = new ArrayList<>();
        for (ObjectInfo o : store.list(ObjectKeys.PREFIX)) {
            if (o.lastModified() != null && o.lastModified().isBefore(cutoff)) {
                candidates.add(o);
            }
        }
        int n = 0;
        for (int i = 0; i < candidates.size(); i += BATCH) {
            List<ObjectInfo> batch = candidates.subList(i, Math.min(i + BATCH, candidates.size()));
            List<UUID> ids = batch.stream().map(o -> ObjectKeys.photoIdOf(o.key())).filter(id -> id != null).toList();
            Set<UUID> alive = new HashSet<>(ids.isEmpty() ? List.of() : jdbc
                    .sql("SELECT id FROM photos WHERE id IN (:ids)")
                    .param("ids", ids)
                    .query(UUID.class)
                    .list());
            for (ObjectInfo o : batch) {
                UUID id = ObjectKeys.photoIdOf(o.key());
                if (id == null) {
                    log.warn("Objeto con una clave que no reconozco, no lo toco: {}", o.key());
                } else if (!alive.contains(id)) {
                    store.delete(o.key());
                    n++;
                }
            }
        }
        return n;
    }

    private List<PhotoRow> old(String status, Duration age) {
        return jdbc.sql("SELECT " + PhotoRow.COLUMNS
                        + " FROM photos WHERE status = :s AND created_at < :cutoff ORDER BY created_at LIMIT :n")
                .param("s", status)
                .param("cutoff", OffsetDateTime.ofInstant(clock.instant().minus(age), ZoneOffset.UTC))
                .param("n", BATCH)
                .query(PhotoRow.class)
                .list();
    }
}
    // ---------- Borrar ----------

    /**
     * Primero la fila y después los objetos: si se cae entre los dos, queda un objeto sin fila (un huérfano que
     * la limpieza borra), nunca una fila que apunta a nada.
     */
    public void delete(UUID photoId, long userId) {
        PhotoRow p = Photos.find(jdbc, photoId).orElseThrow(ApiError::notFound);
        AlbumAccess.Role role = access.require(p.albumId(), userId, AlbumAccess.Role.VIEWER);
        boolean mine = p.uploaderId() == userId && role != AlbumAccess.Role.VIEWER;
        if (!mine && role != AlbumAccess.Role.OWNER) {
            throw new ApiError(HttpStatus.FORBIDDEN, "FORBIDDEN_ROLE", "Solo quien la subió o la dueña la borran.");
        }
        jdbc.sql("DELETE FROM photos WHERE id = :id").param("id", p.id()).update();
        urls.forget(p.objectKey());
        if (p.multipart()) {
            store.abortMultipart(p.objectKey(), p.uploadId());
        }
        store.delete(p.objectKey());
        if (p.thumbKey() != null) {
            urls.forget(p.thumbKey());
            store.delete(p.thumbKey());
        }
    }
}

La regla de orden es la misma en todo el proyecto: nunca una fila que apunta a nada. Al borrar, primero la fila y después los objetos: si la api muere en el medio, queda un objeto sin fila, que no se ve en ningún listado y que la limpieza encuentra. Al revés, quedaría una foto en el álbum con una miniatura rota. Al rechazar es al revés porque la fila no desaparece, cambia de estado: primero se borra el objeto, y si la api muere ahí, la fila sigue pending y la limpieza la encuentra.

Los huérfanos tienen un margen de 24 h por una carrera: entre que la api crea la fila pending y que llega el objeto, hay un rato en que el objeto existe y la fila también, pero un listado del almacén y una consulta a la base hechos en momentos distintos podrían no verlos juntos. Con 24 h de margen, cualquier objeto así ya tiene su fila o ya no la va a tener. Y una clave que no tiene la forma albums/…/…/… no se toca: no la creó el álbum, y borrar lo que no reconoces es como se pierden datos.

Tiene que terminar con Limpieza: 0 pendientes, 0 rechazadas, 0 huérfanos y Terminado si no hay nada viejo. El experimento de la limpieza, más abajo, deja basura a propósito para verla desaparecer.

La decisión
Un proceso que corre y termina, a mano o desde un cron, con tres barridos por edad y lotes de 1 000, y la regla de ciclo de vida del almacén para los multipart.
Lo que descartas
Transacciones que abarquen la base y el almacén: no existen, porque el almacén no participa en las transacciones de PostgreSQL. Y un evento de borrado del almacén hacia la api: más piezas para cubrir los mismos casos.
Qué puede salir mal
Listar un bucket entero cuesta: en R2, un listado es una operación de clase A, y cada página trae hasta 1 000 claves. Con millones de objetos, barrer huérfanos una vez por hora sale caro; ahí conviene listar por prefijo de álbum, o guardar un registro de borrados pendientes en la base.

# Funciones comunes de los scripts. Se carga con: . "$(dirname "$0")/lib.sh"
# Necesitan curl y sed; nada más. El JSON de la api viene compacto ("clave":"valor"), así que sed alcanza.
API=${API:-http://localhost:8080}
ALBUM=${ALBUM:-01990000-0000-7000-8000-000000000001}   # "Viaje a Oaxaca"

# Abre una sesión como $1 (la contraseña es el mismo nombre) y deja el token CSRF en TOKEN.
login() {
  U=$1
  JAR=$(mktemp)
  TOKEN=$(curl -s -u "$U:$U" -c "$JAR" -b "$JAR" "$API/v1/me" | campo csrf_token)
  if [ -z "$TOKEN" ]; then echo "No pude entrar como $U: ¿está arriba la api?" >&2; exit 1; fi
}

# api <método> <ruta> [body]: llama a la api con la sesión y deja el status en STATUS y la respuesta en BODY.
# No imprime nada: dentro de $(...) STATUS se perdería con la subshell.
api() {
  local args=(-s -w '\n%{http_code}' -u "$U:$U" -c "$JAR" -b "$JAR" -X "$1" "$API$2"
              -H "X-CSRF-TOKEN: $TOKEN" -H 'Accept: application/json')
  if [ -n "${3:-}" ]; then args+=(-H 'Content-Type: application/json' -d "$3"); fi
  local out
  out=$(curl "${args[@]}")
  STATUS=${out##*$'\n'}
  BODY=${out%$'\n'*}
}

# campo <nombre>: lee JSON de stdin y saca el primer valor de ese campo (texto o número).
campo() {
  sed -nE "s/.*\"$1\":\"?([^\",}]*)\"?.*/\1/p" | head -n 1
}

# El Content-Type según la extensión, el mismo que el navegador pondría en file.type.
tipo() {
  case "${1##*.}" in
    jpg|jpeg|JPG|JPEG) echo image/jpeg ;;
    png|PNG) echo image/png ;;
    mp4|MP4) echo video/mp4 ;;
    *) echo application/octet-stream ;;
  esac
}

# Bytes de un archivo, sin depender de stat (que cambia entre Linux, macOS y Git Bash).
bytes() {
  wc -c < "$1" | tr -d ' '
}

# Pregunta por la foto cada segundo, hasta 30 veces, mientras siga en uploaded (la miniatura se hace aparte).
# Deja la última respuesta en BODY.
esperar() {
  local s
  for _ in $(seq 1 30); do
    api GET "/v1/photos/$1"
    s=$(echo "$BODY" | campo status)
    [ "$s" != uploaded ] && break
    sleep 1
  done
}

# Sube un video en partes, como el navegador, y permite cortarlo a la mitad y retomarlo.
# Uso: scripts/grande.sh video.mp4 [usuario]
#      PARAR_EN=2 scripts/grande.sh video.mp4    (sube hasta la parte 2 y "se cae")
#      RETOMAR=1  scripts/grande.sh video.mp4    (pregunta qué partes llegaron y sube el resto)
# El id de la subida queda en .subida-<nombre> mientras no termina: es la huella que el navegador guarda en localStorage.
set -euo pipefail
. "$(dirname "$0")/lib.sh"

F=${1:?Uso: grande.sh <archivo> [usuario]}
login "${2:-ana}"
CT=$(tipo "$F")
SIZE=$(bytes "$F")
NAME=$(basename "$F")
STATE=".subida-$NAME"
TMP=$(mktemp -d)
trap 'rm -rf "$TMP"' EXIT

HECHAS=" "
if [ "${RETOMAR:-0}" = 1 ] && [ -f "$STATE" ]; then
  . "$STATE"   # ID, PART_SIZE, PART_COUNT
  api GET "/v1/photos/$ID/parts"
  [ "$STATUS" = 200 ] || { echo "La subida ya no existe ($STATUS): $BODY"; rm -f "$STATE"; exit 1; }

else

  echo "Pido la subida: $STATUS $BODY"
  [ "$STATUS" = 201 ] || exit 1

  PART_SIZE=$(echo "$BODY" | campo part_size)

fi

FALTAN=""
for n in $(seq 1 "$PART_COUNT"); do
  case "$HECHAS" in *" $n "*) ;; *) FALTAN="$FALTAN $n" ;; esac
done

for n in $FALTAN; do

    exit 0
  fi
done

api POST "/v1/photos/$ID/complete"
echo "Confirmo: $STATUS $BODY"
if [ "$STATUS" = 200 ]; then rm -f "$STATE"; fi

La decisión
Scripts que hacen lo mismo que la página, paso por paso, imprimiendo el status y la respuesta de cada uno, con variables para mentir sobre el tipo y el tamaño, cortar una subida y retomarla.
Lo que descartas
Probar todo desde la página: las mentiras sobre el tipo o el tamaño no se pueden hacer desde un <input type="file">, que pone el tamaño real. Y un cliente en Java: curl muestra cada header que va y viene.
Qué puede salir mal
Los scripts leen el JSON con sed, que funciona porque la api responde JSON compacto, sin espacios. Si cambias Jackson para que indente, dejan de encontrar los campos. Con jq no pasaría, pero sería una dependencia más.

/** El firmante solo, sin Spring ni red: un reloj fijo y claves de prueba. */
class UrlSignerTest {

    // 32 bytes en base64: "a" repetida y "b" repetida. Solo para las pruebas.
    static final String K1 = "k1:YWFhYWFhYWFhYWFhYWFhYWFhYWFhYWFhYWFhYWFhYWE=";
    static final String K2 = "k2:YmJiYmJiYmJiYmJiYmJiYmJiYmJiYmJiYmJiYmJiYmI=";
    static final String PATH = "/o/albums/a/b/original";
    static final Instant T0 = Instant.parse("2026-10-12T10:00:00Z");

    static UrlSigner signer(String keys, Instant now) {
        return new UrlSigner(keys, Duration.ofDays(7), Clock.fixed(now, ZoneOffset.UTC));
    }

    /** De "a=1&b=2" a un mapa decodificado, como lo recibe el servidor. */
    static Map<String, String> parse(String query) {
        Map<String, String> q = new HashMap<>();
        for (String kv : query.split("&")) {
            String[] p = kv.split("=", 2);
            q.put(URLDecoder.decode(p[0], StandardCharsets.UTF_8), URLDecoder.decode(p[1], StandardCharsets.UTF_8));
        }
        return q;
    }

    Map<String, String> signedPut() {
        return parse(signer(K1, T0).sign("PUT", PATH, Map.of("ct", "image/png", "max", "1000"), Duration.ofMinutes(5)));
    }

    @Test
    void laUrlFirmadaVerificaConElMismoMetodoYRuta() {
        assertThat(signer(K1, T0).verify("PUT", PATH, signedPut())).isEqualTo(Verdict.OK);
    }

    @Test
    void unaUrlParaSubirNoSirveParaLeer() {
        assertThat(signer(K1, T0).verify("GET", PATH, signedPut())).isEqualTo(Verdict.BAD_SIGNATURE);
    }

    @Test
    void otraRutaConLaMismaFirmaNoSirve() {
        assertThat(signer(K1, T0).verify("PUT", "/o/albums/a/c/original", signedPut()))
                .isEqualTo(Verdict.BAD_SIGNATURE);
    }

    @Test
    void cambiarElVencimientoAManoRompeLaFirma() {
        Map<String, String> q = signedPut();
        q.put("exp", Long.toString(Long.parseLong(q.get("exp")) + 3600));
        assertThat(signer(K1, T0).verify("PUT", PATH, q)).isEqualTo(Verdict.BAD_SIGNATURE);
    }

    @Test
    void cambiarElContentTypeOElMaximoRompeLaFirma() {
        Map<String, String> ct = signedPut();
        ct.put("ct", "text/html");
        Map<String, String> max = signedPut();
        max.put("max", "999999999");
        assertThat(signer(K1, T0).verify("PUT", PATH, ct)).isEqualTo(Verdict.BAD_SIGNATURE);
        assertThat(signer(K1, T0).verify("PUT", PATH, max)).isEqualTo(Verdict.BAD_SIGNATURE);
    }

    @Test
    void agregarUnParametroRompeLaFirma() {
        Map<String, String> q = signedPut();
        q.put("rcd", "attachment");
        assertThat(signer(K1, T0).verify("PUT", PATH, q)).isEqualTo(Verdict.BAD_SIGNATURE);
    }

    @Test
    void pasadoElVencimientoDaExpired() {
        UrlSigner later = signer(K1, T0.plus(Duration.ofMinutes(5)).plusSeconds(1));
        assertThat(later.verify("PUT", PATH, signedPut())).isEqualTo(Verdict.EXPIRED);
    }

    @Test
    void justoEnElVencimientoTodaviaVale() {
        UrlSigner atExp = signer(K1, T0.plus(Duration.ofMinutes(5)));
        assertThat(atExp.verify("PUT", PATH, signedPut())).isEqualTo(Verdict.OK);
    }

    @Test
    void sinFirmaOConUnaClaveDesconocida() {
        Map<String, String> noSig = signedPut();
        noSig.remove("sig");
        Map<String, String> otherKid = signedPut();
        otherKid.put("kid", "k9");
        assertThat(signer(K1, T0).verify("PUT", PATH, noSig)).isEqualTo(Verdict.MISSING);
        assertThat(signer(K1, T0).verify("PUT", PATH, otherKid)).isEqualTo(Verdict.UNKNOWN_KEY);
    }

    @Test
    void trasRotarLaClaveNuevaFirmaYLaViejaSigueVerificando() {
        Map<String, String> old = signedPut();
        UrlSigner rotated = signer(K2 + "," + K1, T0);
        Map<String, String> fresh = parse(rotated.sign("PUT", PATH, Map.of(), Duration.ofMinutes(5)));

        assertThat(rotated.currentKid()).isEqualTo("k2");
        assertThat(fresh.get("kid")).isEqualTo("k2");
        assertThat(rotated.verify("PUT", PATH, old)).isEqualTo(Verdict.OK);
        // Cuando se retira k1, sus URLs dejan de servir aunque no hayan vencido.
        assertThat(signer(K2, T0).verify("PUT", PATH, old)).isEqualTo(Verdict.UNKNOWN_KEY);
    }

    @Test
    void unaUrlQueValeMasQueElMaximoSeRechaza() {
        UrlSigner generous = new UrlSigner(K1, Duration.ofDays(30), Clock.fixed(T0, ZoneOffset.UTC));
        Map<String, String> q = parse(generous.sign("GET", PATH, Map.of(), Duration.ofDays(20)));
        assertThat(signer(K1, T0).verify("GET", PATH, q)).isEqualTo(Verdict.TOO_LONG);
        assertThatThrownBy(() -> signer(K1, T0).sign("GET", PATH, Map.of(), Duration.ofDays(8)))
                .isInstanceOf(IllegalArgumentException.class);
    }

    @Test
    void unSecretoCortoNoArranca() {
        assertThatThrownBy(() -> signer("k1:cmVlbXBsYXphbWU=", T0))
                .isInstanceOf(IllegalStateException.class)
                .hasMessageContaining("32");
    }

    @Test
    void losParametrosVanOrdenadosEnLaCadenaCanonica() {
        String a = UrlSigner.canonical("PUT", PATH, new java.util.TreeMap<>(Map.of("max", "1", "ct", "image/png")));
        assertThat(a).isEqualTo("A11-HMAC-SHA256\nPUT\n" + PATH + "\nct=image%2Fpng&max=1");
    }

/**
 * Los permisos los impone la base, no el código. Cada prueba asume un rol con SET LOCAL ROLE (dura lo que
 * la transacción) e intenta algo que ese proceso no debería poder hacer: 42501 es insufficient_privilege.
 */
class GrantsTest extends IntegrationTest {

    @Autowired
    TransactionTemplate tx;

    private void as(String role, String sql) {
        tx.executeWithoutResult(s -> {
            jdbc.sql("SET LOCAL ROLE " + role).update();
            if (sql.startsWith("SELECT")) {
                jdbc.sql(sql).query().listOfRows();
            } else {
                jdbc.sql(sql).update();
            }
        });
    }

    private void denied(String role, String sql) {
        assertThatThrownBy(() -> as(role, sql))
                .satisfies(e -> assertThat(sqlState(e)).isEqualTo("42501"));
    }

    private static String sqlState(Throwable e) {
        for (Throwable t = e; t != null; t = t.getCause()) {
            if (t instanceof SQLException s) {
                return s.getSQLState();
            }
        }
        return null;
    }

    @Test
    void laApiNoTocaLaColaMasQueParaInsertar() {
        as("album_api", "SELECT count(*) FROM photos");
        denied("album_api", "SELECT * FROM thumb_jobs");
        denied("album_api", "DELETE FROM thumb_jobs");
        denied("album_api", "DELETE FROM albums");
    }

    @Test
    void elWorkerNoCreaNiBorraFotos() {
        as("album_worker", "SELECT count(*) FROM thumb_jobs");
        denied("album_worker", "DELETE FROM photos");
        denied("album_worker", "SELECT * FROM album_members");

La primera foto, en DevTools

Abre http://localhost:8080/, entra como ana, abre DevTools en la pestaña Network y sube foto.jpg. Tienen que aparecer, en orden:

  1. El permisoPOST /v1/albums/…/uploads a localhost:8080, con un 201 y la URL firmada en la respuesta.
  2. El preflightOPTIONS a localhost:9000, con Access-Control-Allow-Origin: http://localhost:8080 y Access-Control-Max-Age: 3600. Chrome lo muestra como una fila aparte, de tipo preflight.
  3. Los bytesPUT a localhost:9000, con el tamaño de la foto en Request Headers. Es la única request que lleva los bytes.
  4. La confirmaciónPOST /v1/photos/…/complete, con "status":"uploaded".
  5. La miniaturaUno o más GET /v1/photos/… hasta "status":"ready", y después un GET de la miniatura a localhost:9000.

Sube una segunda foto antes de que pase una hora: el OPTIONS no vuelve a aparecer, porque el navegador guardó la respuesta. Recarga la página y mira la miniatura en Network: en la columna Size tiene que decir (memory cache) o (disk cache). Es la URL reutilizada del paso 10.

Tocar la firma

Pide una URL sin subir nada y prueba tres cambios. Ninguno debería pasar:

. scripts/lib.sh; login ana
api POST "/v1/albums/$ALBUM/uploads" "{\"filename\":\"foto.jpg\",\"content_type\":\"image/jpeg\",\"size\":$(bytes foto.jpg)}"
URL=$(echo "$BODY" | campo url)

# 1. Otro vencimiento: un día más
EXP=$(echo "$URL" | sed -E 's/.*exp=([0-9]+).*/\1/')
OTRA=${URL/exp=$EXP/exp=$((EXP + 86400))}
curl -s -o /dev/null -D - -X PUT -H 'Content-Type: image/jpeg' --data-binary @foto.jpg "$OTRA" | grep -i 'HTTP/\|x-error'

# 2. La URL de subida usada para leer
curl -s -o /dev/null -D - "$URL" | grep -i 'HTTP/\|x-error'

# 3. Otro Content-Type
curl -s -o /dev/null -D - -X PUT -H 'Content-Type: text/html' --data-binary @foto.jpg "$URL" | grep -i 'HTTP/\|x-error'

Los dos primeros tienen que dar 403 con X-Error-Code: BAD_SIGNATURE: el vencimiento y el método están dentro de la firma. El tercero, 403 con CONTENT_TYPE_MISMATCH: la firma es válida, pero el header no es el que se firmó. Ahora haz el PUT bien, con Content-Type: image/jpeg, dos veces seguidas: las dos dan 200, y la segunda reemplaza a la primera. Una URL firmada no se gasta al usarla; vale hasta que vence.

api POST "/v1/albums/$ALBUM/uploads" "{\"filename\":\"foto.jpg\",\"content_type\":\"image/jpeg\",\"size\":$(bytes foto.jpg)}"

Tiene que dar 403 con EXPIRED. La firma sigue siendo válida (no se tocó nada), pero el almacén verifica el vencimiento después de la firma. CORS: curl pasa, otra página no

Con una URL de subida recién pedida, como en "Tocar la firma", curl sube sin problema: no manda Origin ni hace preflight. Ahora intenta lo mismo desde una página de otro origen. El JDK trae un servidor de archivos estático, jwebserver:

mkdir -p /tmp/otra && jwebserver -p 8081 -d /tmp/otra

En Git Bash, -d necesita una ruta absoluta de Windows: usa -d "$(cygpath -w /tmp/otra)". Abre http://127.0.0.1:8081/, abre la consola de DevTools y pega, con tu URL:

fetch('http://localhost:9000/o/…', { method: 'PUT', headers: { 'Content-Type': 'image/jpeg' }, body: 'x' })

La consola tiene que mostrar un error que dice blocked by CORS policy, y en Network, el OPTIONS con un 403 y ningún PUT. El navegador nunca mandó los bytes. Mira el log del almacén, docker compose logs files: no hay ninguna línea PUT nueva.

Cortar una subida grande y retomarla

Un archivo de 100 MiB que pasa la revisión de un MP4: los bytes 4 a 7 dicen ftyp, y lo demás es azar.

printf '\x00\x00\x00\x18ftypisom' > grande.mp4
head -c 104857600 /dev/urandom >> grande.mp4
PARAR_EN=4 scripts/grande.sh grande.mp4
RETOMAR=1  scripts/grande.sh grande.mp4

Son 104 857 612 bytes: 12 partes de 8 MiB y una de 4 194 316 bytes, 13 en total. La primera corrida sube de la 1 a la 4 y se detiene. La segunda tiene que decir Retomo …: ya estaban las partes 1 2 3 4, subir de la 5 a la 13 y confirmar con un 200 y "status":"ready": es un video, no lleva miniatura. Ahora hazlo en la página: elige grande.mp4, recarga la página a la mitad y vuelve a elegirlo. Tiene que decir Retomando: N de 13 partes ya estaban.

Para ver una subida a medias que nadie retoma, corre PARAR_EN=2 scripts/grande.sh grande.mp4 y no la retomes: queda una fila pending y dos partes en el almacén, en /data/mpu/. Es la basura del experimento de la limpieza.

La bomba de descompresión

jshell scripts/bomba.jsh
scripts/subir.sh bomba.png
docker compose logs worker | grep rechazada

bomba.jsh imprime cuántos bytes ocupa el PNG: anótalo junto a los 225 millones de píxeles. La subida pasa la confirmación, porque la cabecera dice PNG y el tamaño es el declarado. El worker la rechaza con Foto … rechazada: too_many_pixels: 15000x15000, y subir.sh termina mostrando la foto con "status":"rejected" y "reason":"too_many_pixels". En docker stats worker, la memoria no tiene que moverse.

Quita la primera defensa y mira la segunda: ALBUM_MAX_PIXELS=300000000 docker compose up -d worker y sube la bomba otra vez. Este PNG en particular es de 1 bit por píxel y el submuestreo lee uno de cada 18 píxeles por eje, así que lo que pase depende de cómo el decodificador de PNG maneje esas dos cosas. Anota el pico de memoria en docker stats y si la foto terminó ready o el worker murió. Sea cual sea el resultado, es la razón de tener las dos defensas: no conviene que la seguridad dependa del formato de cada archivo. Al terminar, docker compose up -d worker.

Falla: el archivo miente

TAMANO=5000 scripts/subir.sh foto.jpg
echo '<script>alert(1)</script>' > pagina.html
TIPO=image/png scripts/subir.sh pagina.html

La primera declara 5 000 bytes y manda la foto entera. El almacén local la frena en el PUT: si ves 413, lo rechazó al ver el Content-Length. Si la foto pasa de 2 MB, puede que curl muestre 000: Tomcat responde y cierra la conexión sin leer el resto, y curl no alcanza a leer la respuesta. Después, la confirmación da 409 con UPLOAD_MISSING, porque no hay objeto. La segunda manda un HTML con Content-Type: image/png: el PUT pasa, porque es el tipo que se firmó, y la confirmación da 422 con "reason":"content_mismatch". En el log de la api, Subida … rechazada: content_mismatch. Con R2, la primera también pasa el PUT y la frena la confirmación, con size_mismatch.

Rotar la clave de firma

Guarda una URL de miniatura en una variable, rota la clave en las tres fases de la figura A11.5 y mira qué le pasa a esa URL en cada una. La URL vale 15 minutos: haz las tres fases dentro de ese plazo.

. scripts/lib.sh; login ana
api GET "/v1/albums/$ALBUM/photos"; VIEJA=$(echo "$BODY" | campo thumb_url)
openssl rand -base64 32    # el secreto de k2

# Fase 1: en .env, FILES_SIGNING_KEYS=k1:…,k2:…   (k2 al final)
docker compose up -d --force-recreate files api worker
# Fase 2: en .env, FILES_SIGNING_KEYS=k2:…,k1:…   (k2 al frente)
docker compose up -d --force-recreate files api worker
curl -s -o /dev/null -w '%{http_code}\n' "$VIEJA"
# Fase 3: en .env, FILES_SIGNING_KEYS=k2:…        (sin k1)
docker compose up -d --force-recreate files api worker
curl -s -o /dev/null -D - "$VIEJA" | grep -i 'HTTP/\|x-error'

Después de la fase 2, la URL vieja sigue dando 200, y una URL nueva del listado lleva kid=k2. Después de la fase 3, la vieja da 403 con UNKNOWN_KEY. En producción, entre la fase 2 y la 3 esperarías a que venza la última URL firmada con k1. Ojo con la caché de PhotoUrls: vive en la memoria de la api, así que al recrear la api se vacía y las URLs nuevas salen con la clave nueva.

Falla: salir del directorio

curl -s -o /dev/null -w '%{http_code}\n' --path-as-is 'http://localhost:9000/o/albums/../../etc/passwd'
curl -s -o /dev/null -w '%{http_code}\n' 'http://localhost:9000/o/albums/%2e%2e/%2e%2e/etc/passwd'

--path-as-is hace que curl mande los .. tal cual, sin resolverlos. Los dos tienen que dar 400: los frena el StrictHttpFirewall de Spring Security antes del controlador, y antes de verificar la firma. Para ver la segunda defensa, prueba una clave que el StrictHttpFirewall deja pasar pero que no tiene la forma de las del álbum, con mayúsculas: curl -i 'http://localhost:9000/o/Albums/x/y/original?exp=1&kid=k1&sig=AAAA'. Da 400 con X-Error-Code: BAD_KEY: la forma de la clave se revisa antes que la firma, así que ni siquiera se calcula el HMAC.

La limpieza

La limpieza borra por edad, así que para verla trabajar hay que envejecer la basura a mano. Deja una subida pendiente (la del experimento anterior, o una nueva) y un huérfano, borrando la fila de una foto que ya está lista:

scripts/subir.sh foto.jpg                      # anota el ID
docker compose exec postgres psql -U app -d app -c "DELETE FROM photos WHERE id = '<ID>'"
docker compose exec postgres psql -U app -d app -c \
  "UPDATE photos SET created_at = now() - interval '25 hours' WHERE status = 'pending'"
docker compose exec files sh -c 'touch -d "2 days ago" /data/obj/albums/*/<ID>/*'
docker compose run --rm jobs

El log tiene que terminar con una línea Limpieza: N pendientes, 0 rechazadas, 2 huérfanos, con N el número de subidas pendientes que dejaste, y los dos huérfanos el original y la miniatura de la foto sin fila. Después, Terminado. Corre docker compose run --rm jobs otra vez: todo en cero. Las partes de la subida cortada siguen en /data/mpu/ si la subida no se abortó, y las descarta FilesHousekeeping a los 7 días. La limpieza sí las aborta al borrar su fila pending.

Cómo conectar

Este proyecto funciona solo. Si quieres juntarlo con uno anterior:

  • Con A00, el laboratorio común

    El compose, PgBouncer en modo transacción, Flyway directo a PostgreSQL y Testcontainers son los de A00. Aquí se suma un rol por proceso con permisos mínimos.

  • Con A01, detrás de Nginx

    Si pones la api detrás del Nginx de A01, revisa client_max_body_size: con la subida directa, la api solo recibe JSON chico, y puedes dejarlo en 1 MB. Con el camino a través de la api, tendrías que subirlo a 16 MiB y Nginx guardaría cada archivo en un temporal antes de pasarlo. El almacén local, en cambio, sí necesita un límite alto si lo pones detrás de Nginx.

  • Con A03, caché que aguanta un pico

    A03 cacheaba respuestas de la api; aquí lo que se cachea son URLs firmadas, en la memoria de la api y en el navegador. La URL reutilizada mientras le quede un tercio de vida es un TTL con renovación anticipada, la misma idea que servir lo vencido mientras se refresca.

  • Con A09, colas y pub/sub

    thumb_jobs es una cola en PostgreSQL con SKIP LOCKED, como el relay del outbox de A09, pero con un lease en una columna en lugar de un lock que dura la transacción. Si ya tienes el Redis Streams de A09, puedes mover las miniaturas ahí: el trabajo se insertaría en el outbox, en la misma transacción que confirma la foto.

  • Con A10, cuando Redis se cae

    El almacén también se cae. La api ya responde 503 con Retry-After cuando el almacén no contesta; el circuit breaker de A10 alrededor de LocalObjectStore o R2ObjectStore evitaría que cada request espere el timeout completo mientras está caído.
