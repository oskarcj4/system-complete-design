CSP y cabeceras de seguridad

El escape evita que el código del atacante entre. La CSP es la segunda línea: si entra, el navegador no lo ejecuta. Bien escrita es corta, se basa en nonces y no en dominios, y se despliega mirando los reportes antes de bloquear.

M77 terminó en una lista de capas. La primera, el escape, depende de que nadie olvide un solo e() en miles de líneas. Esta es la segunda: una cabecera con la que el servidor le dice al navegador qué código puede correr en la página. Si el escape falló, el payload entra al DOM, pero no se ejecuta.

78.1Qué es una CSP y qué no es

Analogía

Es la lista de invitados en la puerta de un evento. No impide que alguien se cuele por la cocina (el escape olvidado), pero adentro, el personal solo atiende a quien lleva la pulsera del día. Una pulsera que cambia cada noche es un nonce; una lista que dice "cualquiera que venga de la ciudad X" es una lista de dominios.

Una CSP (Content Security Policy) es una cabecera de respuesta con directivas. Cada directiva dice de dónde puede venir un tipo de recurso, y el navegador bloquea y reporta lo que no cumple Documentado.

  • Qué hace: bloquea scripts inline, manejadores on*, eval y scripts de orígenes no permitidos; limita a dónde se conecta, desde dónde se enmarca y a dónde envía formularios.
  • Qué no hace: no frena la inyección de HTML sin script (un formulario falso, DOM clobbering, M77), no frena CSRF y no protege de lo que haga tu propio JavaScript con datos que no escapó.

Los valores especiales van entre comillas simples: 'self' (el mismo origen), 'none', 'nonce-…', 'sha256-…', 'strict-dynamic', 'unsafe-inline' y 'unsafe-eval'. Los dos últimos desactivan justo lo que la CSP protege.

78.3Por qué una lista de dominios no sirve

La primera CSP que escribe todo el mundo es una lista: script-src 'self' https://cdn.jsdelivr.net https://www.google-analytics.com. Parece estricta y casi nunca lo es.

En 2016, investigadores de Google analizaron unas 26 000 políticas únicas de la web y encontraron que el 94.72 % se podía eludir, casi siempre por un dominio permitido que servía JSONP o una librería con gadgets Documentado. De ahí sale la recomendación actual: una CSP estricta, basada en nonces o hashes, sin listas de dominios para los scripts Documentado.

Un gadget de script es código legítimo de una librería que lee el DOM y ejecuta algo según lo que encuentra: por ejemplo, AngularJS 1.x evalúa las expresiones {{ }} del HTML. Si la librería está permitida, el atacante no inyecta un <script>: inyecta HTML que la librería convierte en código.

78.4La CSP estricta: nonce y strict-dynamic

Un nonce aquí es lo mismo que en M36: un número que se usa una sola vez. El servidor genera uno aleatorio por respuesta, lo pone en la cabecera y en cada <script> legítimo. El atacante no lo conoce cuando escribe su payload, porque se guardó antes, en la base.

<?php
// core/headers.php: cabeceras de seguridad para las páginas HTML
function cabecerasHtml(): string
{
    $nonce = base64_encode(random_bytes(16));            // 128 bits, uno por respuesta
    $csp = implode('; ', [
        "script-src 'nonce-$nonce' 'strict-dynamic' https: 'unsafe-inline'",   // (1)
        "object-src 'none'",
        "base-uri 'none'",
        "form-action 'self'",
        "frame-ancestors 'none'",
        "require-trusted-types-for 'script'",              // M77, primero en Report-Only
        "report-to csp",
    ]);
    header("Content-Security-Policy: $csp");
    header('Reporting-Endpoints: csp="https://api.practicas.edu.gt/endpoints/csp-report.php"');
    return $nonce;
}
  1. La línea completa es para compatibilidad: un navegador con CSP 3 ve el nonce y 'strict-dynamic', e ignora https: y 'unsafe-inline'. Un navegador viejo que no entiende strict-dynamic cae a https:, y uno que no entiende nonces, a 'unsafe-inline'. La página funciona en todos y es estricta donde se puede Documentado.
<?php $nonce = cabecerasHtml(); ?>
<!doctype html>
<script nonce="<?= $nonce ?>" src="/js/app.js"></script>
<script nonce="<?= $nonce ?>">iniciarFeed(<?= js($datosIniciales) ?>);</script>
<!-- Lo inyectado no tiene el nonce de esta respuesta: no corre -->

Qué pasa si falla

Un nonce fijo, o uno que se guarda en una caché compartida con la página, se reutiliza: el atacante lo lee una vez y lo pone en su payload. El nonce se genera por respuesta con un CSPRNG (random_bytes), y una página con nonce no se cachea en un CDN para todos los usuarios.

Una SPA estática: hashes

El frontend del sistema es una SPA de Vite: un index.html estático que sirve Apache, sin PHP que genere un nonce. Ahí se usan hashes: el SHA-256 del contenido de cada script inline permitido, que el navegador recalcula y compara.

# La SPA del frontend (Vite) es un index.html estático: no hay PHP que genere un nonce.
# Sin scripts inline, la política estricta usa hashes del único script de arranque, si lo hay.
Content-Security-Policy: script-src 'sha256-3q2+7w…' 'strict-dynamic'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
# Si no hay ningún script inline, 'self' con strict-dynamic no sirve: strict-dynamic ignora 'self'.
# En ese caso: script-src 'self'; y que en tu propio origen no haya archivos que suba un usuario ni JSONP.

78.5Desplegar sin romper: report-only y reportes

Content-Security-Policy-Report-Only evalúa la política y manda un reporte por cada violación, sin bloquear. Los reportes van al endpoint que nombra report-to (con la cabecera Reporting-Endpoints) o, en navegadores que todavía no la soportan, report-uri, que está obsoleta pero sigue funcionando Documentado. Report-only y frame-ancestors no funcionan en una etiqueta <meta>: van en la cabecera.

<?php
// endpoints/csp-report.php: recibe reportes; no confía en nada de lo que llega
$cuerpo = file_get_contents('php://input', length: 64 * 1024);   // tope de tamaño
$tipo = $_SERVER['CONTENT_TYPE'] ?? '';
if (!str_starts_with($tipo, 'application/reports+json') && !str_starts_with($tipo, 'application/csp-report')) {
    http_response_code(415); exit;
}
error_log('csp ' . substr(preg_replace('/[\r\n]/', ' ', $cuerpo), 0, 2000));   // M79: sin saltos de línea
http_response_code(204);

78.6Las demás cabeceras de seguridad

  • Strict-Transport-Security (HSTS, M01): el navegador solo usa HTTPS con el dominio durante max-age segundos. Para entrar en la lista de precarga de los navegadores hacen falta un año, includeSubDomains y preload Documentado. Ojo con includeSubDomains si algún subdominio interno todavía usa HTTP.
  • X-Content-Type-Options: nosniff: el navegador respeta el Content-Type y no adivina. Un script con tipo text/plain o un JSON no se ejecutan como script. Es la otra mitad del arreglo de 77.4.
  • Referrer-Policy: cuánto de la URL viaja en Referer a otros sitios. El valor por defecto de los navegadores actuales es strict-origin-when-cross-origin: a otro sitio solo va el origen Documentado. Una API puede usar no-referrer.
  • Permissions-Policy: qué APIs del navegador puede usar la página y sus iframes. Si no usas la cámara, camera=() impide que un script inyectado la pida.
  • frame-ancestors: quién puede enmarcar la página. Reemplaza a X-Frame-Options, que se puede mandar también para navegadores viejos. Es la defensa contra el clickjacking (M83).
  • X-XSS-Protection: está obsoleta. El filtro que activaba se quitó de los navegadores, y en algunos casos se podía usar para borrar scripts legítimos. Se omite, o se manda en 0 Documentado.
# .htaccess o el VirtualHost del frontend en Apache (XAMPP): cabeceras para todo lo estático
<IfModule mod_headers.c>
  Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
  Header always set X-Content-Type-Options "nosniff"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
  Header always set Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()"
  Header always set Cross-Origin-Opener-Policy "same-origin"
</IfModule>

78.7COOP, COEP y CORP: aislar el proceso

Spectre (2018) mostró que el código de una página puede leer memoria de su mismo proceso midiendo tiempos. Los navegadores respondieron separando sitios en procesos (M73), y con tres cabeceras con las que una página pide más aislamiento: COOP y COEP, más CORP para los recursos.

CabeceraQuién la mandaQué hace
Cross-Origin-Opener-Policy: same-originTu páginaOtra ventana de otro origen no conserva window.opener ni comparte grupo de navegación
Cross-Origin-Embedder-Policy: require-corpTu páginaSolo carga recursos de otro origen que lo permitan con CORP o CORS
Cross-Origin-Resource-Policy: same-siteTus recursos (la API, imágenes)Otro sitio no los puede incluir con <img> o <script>

Con COOP y COEP, la página obtiene crossOriginIsolated y puede usar SharedArrayBuffer y relojes de alta precisión Documentado. Para una aplicación como la tuya, que no los necesita, alcanza con COOP same-origin en el frontend y CORP en la API. COEP rompe cualquier recurso de otro origen que no mande CORP: se activa solo si hace falta.

78.8En tu proyecto: la API y el frontend

La API no sirve HTML. Su política es la más simple de todas: nada se carga, nada se enmarca. Esa línea, más nosniff, cierra el hallazgo 5 de la auditoría aunque algún día alguien abra un JSON en el navegador Documentado.

<?php
// core/response.php: la API no sirve HTML, así que su política es "nada"
header('Content-Type: application/json; charset=utf-8');
header('X-Content-Type-Options: nosniff');
header("Content-Security-Policy: default-src 'none'; frame-ancestors 'none'");
header('Cross-Origin-Resource-Policy: same-site');
header('Referrer-Policy: no-referrer');
header('Cache-Control: no-store');              // respuestas con datos personales

El frontend lleva las cabeceras de Apache de 78.6 y una CSP con hashes o 'self', más connect-src con la URL de la API. En el laboratorio, localhost:5173 (Vite) y localhost (Apache) son orígenes distintos: connect-src tiene que nombrar los dos mientras desarrollas, y solo el de producción después.

Trade-off

Vite en modo desarrollo inyecta estilos y scripts inline para el recargado en caliente. Una CSP estricta rompe el servidor de desarrollo. La política estricta se prueba contra el build (vite build y vite preview), no contra vite dev.
