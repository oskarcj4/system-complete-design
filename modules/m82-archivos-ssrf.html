Archivos, SSRF y redirecciones

Un archivo subido termina en tu disco, una URL que tu servidor visita sale desde dentro de tu red y una URL de redirección se lleva al usuario con tu dominio en la barra. En los tres casos, el servidor presta su posición a un dato que no escribió.

En M79 el dato del usuario terminaba dentro de un lenguaje. Aquí termina como algo que el servidor hace: un archivo que guarda, una URL que visita o una URL a la que manda al navegador. El sistema de prácticas no tiene ninguna de las tres funciones todavía, pero tiene dos URLs guardadas (cv_url y sitio_web), y la guía WEB08 convierte los CVs en archivos subidos.

82.1Subir un archivo

Analogía

Una oficina de correos que recibe paquetes. Pesa el paquete (tamaño), lo pasa por rayos X en lugar de creer la etiqueta (tipo real), le pone su propio número de guía (nombre propio), lo guarda en la bodega y no en el mostrador (fuera del webroot) y solo se lo entrega al destinatario con identificación (el script con el dueño).

Lo peor que puede pasar con una subida en PHP es una web shell: un .php que termina en una carpeta que Apache sirve, y que el atacante abre en el navegador para ejecutar comandos con los permisos del servidor. Todo lo demás (llenar el disco, un PDF con malware para la reclutadora, un SVG con un script) es menos grave, y también tiene su control.

82.2El tipo real del archivo

  • Lista de permitidos, no de prohibidos. Prohibir .php deja pasar .phtml, .phar, .PhP y cv.php. en Windows. Permitir solo application/pdf no deja pasar nada más.
  • Un archivo puede ser dos cosas. Un políglota es válido como dos formatos a la vez: un GIF cuyos primeros bytes son GIF89a y que más adelante contiene <?php. finfo dice "image/gif" y es verdad. Por eso el tipo real no reemplaza al control 4: si nunca se ejecuta, no importa qué más contenga.
  • Las imágenes se vuelven a codificar. Abrir la imagen con GD o Imagick y guardarla de nuevo descarta todo lo que no son píxeles, incluidos los metadatos EXIF con la ubicación de la foto.
  • SVG es un documento, no una imagen. Lleva <script> y se ejecuta si se abre en tu origen (M77). Si se aceptan, se sirven como descarga o desde otro dominio.

82.3Guardarlo y servirlo

<?php
// endpoints/cv.php POST: subir el CV de una postulación propia
const CV_MAX_BYTES = 2 * 1024 * 1024;
const CV_TIPOS = ['application/pdf' => 'pdf'];                     // lista, no "lo que no sea .php"

$sesion = autorizar('cv');
$postulacion = $postulaciones->propiaPendiente((int)($_POST['postulacion'] ?? 0), $sesion); // M80
$f = $_FILES['cv'] ?? null;
if (!$f || $f['error'] !== UPLOAD_ERR_OK || $f['size'] > CV_MAX_BYTES) {
    Response::json(-1, 'Archivo ausente o mayor a 2 MB', [], 400);
}
$tipo = (new finfo(FILEINFO_MIME_TYPE))->file($f['tmp_name']);    // del contenido, no de la request
if (!isset(CV_TIPOS[$tipo])) {
    Response::json(-1, 'Solo PDF', [], 415);
}
$nombre = bin2hex(random_bytes(16)) . '.' . CV_TIPOS[$tipo];       // el nombre del usuario no se usa
$destino = __DIR__ . '/../../storage/cvs/' . $nombre;               // fuera de public_html
if (!move_uploaded_file($f['tmp_name'], $destino)) {
    Response::json(-1, 'No se pudo guardar', [], 500);
}
$postulaciones->guardarCv($postulacion['id'], $nombre, $f['name']); // el nombre original, solo como dato

PHP tiene sus propios límites antes de tu código: upload_max_filesize (2 MB por defecto) y post_max_size (8 MB) en php.ini Documentado. Son el piso; el límite propio dice cuánto acepta esta función. Servirlo es el script de 80.8: el dueño en la consulta, el nombre desde la base, Content-Disposition: attachment para que el navegador lo descargue en lugar de abrirlo en tu origen, y nosniff de M78 para que no adivine el tipo.

Si por cualquier razón queda una carpeta pública de subidas, Apache puede negarse a interpretar PHP en ella. Es una red de seguridad, no el control principal:

# Si por error algo termina en una carpeta pública de subidas (Apache de XAMPP)
<Directory "C:/xampp/htdocs/SistemaControlPracticas/uploads">
    php_admin_flag engine off            # mod_php no interpreta nada aquí
    Options -Indexes -ExecCGI
    <FilesMatch "\.(php|phtml|phar|pht)$">
        Require all denied
    </FilesMatch>
</Directory>

Trade-off

Un almacén de objetos (S3 o compatible, M09) resuelve casi todo esto de una vez: no ejecuta nada, se sirve desde otro dominio y la descarga va con una URL firmada que dura minutos. Cuesta otra pieza que operar. Para los CVs de un sistema universitario, una carpeta fuera del webroot y el script de 80.8 alcanzan; si el sistema crece o pasa a varias máquinas, el almacén de objetos es el paso siguiente.

Los archivos comprimidos tienen su propia trampa: un ZIP cuyas entradas se llaman ../../public/shell.php escribe fuera de la carpeta al extraerse (zip slip), y uno de 40 KB que se expande a gigas llena el disco (bomba de descompresión). Si hay que extraer, cada nombre pasa por el realpath de 80.8 y se cuenta el tamaño mientras se extrae.

82.4SSRF: el servidor visita una URL por ti

SSRF (Server-Side Request Forgery) pasa cuando el servidor hace una request a una URL que eligió el usuario. Es el CSRF de M76 movido al servidor: en lugar de usar el navegador de la víctima, el atacante usa tu servidor, que está dentro de tu red y ve lo que internet no ve. Funciones que la provocan: vista previa de enlaces, importar desde una URL, webhooks configurables, generar un PDF desde HTML, descargar una imagen de perfil desde un enlace.

82.5El servicio de metadatos de la nube

Cada máquina virtual en AWS, Google Cloud o Azure puede preguntar por HTTP, sin autenticación, quién es, y obtener las credenciales temporales del rol que tiene asignado. Es el IMDS (Instance Metadata Service) en 169.254.169.254. En M37 viste el caso de Capital One en 2019: una request no prevista llegó a IMDSv1 y las credenciales del rol bastaron para leer el almacén de objetos Documentado.

Las defensas de la nube contra SSRF son pedirle al cliente algo que una URL sola no da:

  • AWS IMDSv2 exige primero un token pedido con PUT y una cabecera propia, y el token vuelve con un límite de saltos de red Documentado. Una SSRF típica solo controla la URL de un GET.
  • Google Cloud exige la cabecera Metadata-Flavor: Google Documentado, y Azure, Metadata: true Documentado.
# IMDSv2 (AWS): primero un token con PUT, después la lectura con el token
$ TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" \
    -H "X-aws-ec2-metadata-token-ttl-seconds: 300")
$ curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/
# Exigir v2 y un salto de red: un contenedor detrás de un puente ya no llega
$ aws ec2 modify-instance-metadata-options --instance-id i-0abc… \
    --http-tokens required --http-put-response-hop-limit 1

Y la de siempre: el rol de la máquina con lo mínimo (M37). Si una SSRF llega a las credenciales, que no alcancen para mucho.

82.6Validar una URL que vas a visitar

La mejor defensa es no tener la función, o que la URL no sea libre: una lista de dominios permitidos (los webhooks a un proveedor de pagos van a sus dominios, nada más). Cuando la URL tiene que ser libre, como la vista previa, la validación tiene varias reglas y todas importan:

Dos trampas se llevan casi todas las validaciones caseras. La primera son las redirecciones: la URL válida apunta a un sitio público que responde 302 Location: http://169.254.169.254/, y curl la sigue si se lo permites. La segunda es el DNS rebinding:

<?php
// core/url_externa.php: visitar una URL que mandó un usuario
function obtenerExterna(string $url): string
{
    $p = parse_url($url);
    if (!$p || !in_array($p['scheme'] ?? '', ['http', 'https'], true) || empty($p['host'])
        || isset($p['user']) || !in_array($p['port'] ?? null, [null, 80, 443], true)) {
        throw new DomainException('URL no permitida');
    }
    $ips = gethostbynamel($p['host']) ?: [];                         // IPv4; IPv6 se descarta abajo
    $ip = $ips[0] ?? '';
    if (!filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_IPV4 | FILTER_FLAG_GLOBAL_RANGE)) {
        throw new DomainException('Destino no permitido');           // privadas, loopback, link-local…
    }
    $puerto = $p['port'] ?? ($p['scheme'] === 'https' ? 443 : 80);
    $ch = curl_init($url);
    curl_setopt_array($ch, [
        CURLOPT_RESOLVE        => ["{$p['host']}:$puerto:$ip"],    // conecta a la IP validada
        CURLOPT_IPRESOLVE      => CURL_IPRESOLVE_V4,
        CURLOPT_PROTOCOLS_STR  => 'http,https',
        CURLOPT_FOLLOWLOCATION => false,                             // una redirección se valida de nuevo
        CURLOPT_CONNECTTIMEOUT => 2,
        CURLOPT_TIMEOUT        => 3,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_MAXFILESIZE    => 1024 * 1024,
    ]);
    $cuerpo = curl_exec($ch);
    curl_close($ch);
    return $cuerpo === false ? '' : $cuerpo;
}

FILTER_FLAG_GLOBAL_RANGE existe desde PHP 8.2 y rechaza las direcciones privadas, reservadas y locales en una sola bandera Documentado. La función devuelve solo IPv4 y fuerza IPv4 en curl, lo que evita las formas IPv6 de la figura 82.4 a cambio de no visitar sitios que solo tienen IPv6. Debajo de todo, la red: si el servidor solo puede salir por un proxy con lista de destinos (el filtrado de salida de M32), una validación que falla no llega lejos.

82.7Redirecciones abiertas

Una redirección abierta es un endpoint de tu dominio que manda al navegador a cualquier URL que venga en un parámetro. No compromete tu servidor; presta tu dominio. El usuario ve practicas.edu.gt en el enlace, confía, y termina en otro sitio.

Además del phishing, una redirección abierta en el dominio de una aplicación OAuth permite robar el código de autorización si el proveedor compara el redirect_uri por prefijo (M10), y con javascript: en un location.href del frontend es un XSS de DOM (M77).

<?php
// Después del login: next es el nombre de una pantalla, no una URL
const DESTINOS = ['inicio' => '/', 'postulaciones' => '/mis-postulaciones', 'perfil' => '/perfil'];
$destino = DESTINOS[$_GET['next'] ?? ''] ?? '/';
header('Location: ' . $destino, true, 303);

// Si de verdad hace falta una ruta libre: una sola / al inicio, sin // ni \ ni esquema
function rutaLocal(string $r): string
{
    return preg_match('#^/(?![/\\\\])[^\\\\\r\n]*$#', $r) ? $r : '/';
}

82.8Las URLs que el sistema guarda

Hoy, cv_url y sitio_web se guardan con trim y nada más, y el frontend las pinta como enlaces. Nadie las visita desde el servidor, así que no hay SSRF; el riesgo está en el navegador: javascript:fetch('…'+document.cookie) como sitio web de una institución es un XSS almacenado que se dispara cuando alguien hace clic (77.2), y una URL a un sitio de phishing con aspecto de CV es una redirección abierta con más pasos.

<?php
// endpoints/instituciones.php y postulaciones.php: validar al guardar
function urlWebValida(string $u): bool
{
    return strlen($u) <= 500
        && filter_var($u, FILTER_VALIDATE_URL) !== false
        && in_array(strtolower(parse_url($u, PHP_URL_SCHEME)), ['http', 'https'], true);
}
// Y al pintar, en el frontend: el esquema se vuelve a comprobar (M77)
//   const u = new URL(inst.sitio_web);  if (u.protocol === 'https:' || u.protocol === 'http:') a.href = u.href;

Las dos validaciones hacen falta: la del servidor evita guardar basura, y la del frontend protege también los datos que ya estaban guardados antes de la regla. Y si algún día el servidor visita esas URLs (para comprobar que el CV existe, por ejemplo), pasan por obtenerExterna() de 82.6.
